# Idea：把 Planner 训练成 MAS 的世界模型

一句话：当前 Agentic RL 用任务奖励优化策略；这篇工作用交互经验优化 Planner 对多智能体系统的内部信念。策略是世界模型变准之后自然出现的，不是被直接优化的对象。

工作标题：Epistemic Planning — prediction-guided epistemic planning for agentic RL。

## 世界模型建模的是 MAS，不是任务环境

经典世界模型回答的是：环境下一步长什么样。Dreamer 预测游戏画面，WebDreamer 预测网页会怎么变，然后挑一条更可能做完任务的动作。那是对环境动力学的模型。

这里要建模的对象是多智能体系统自己。Planner 真正不知道、而且会随任务迁移的，是这条因果链：

```text
Environment → Executor 如何落地 → Tool 实际如何响应 → 能力边界在哪里 → 因此该怎么 Plan
```

具体四块信念，合在一起才叫内部世界模型 \(M_t\)（它不是对话记忆）：

- **Capability**：Executor / Tool 能不能做 OCR、读 PDF、解析表格、跑 SQL。这是能力图，跨任务复用。
- **Tool**：这个工具有多可靠、覆盖哪些来源、什么情况下超时或返回空。
- **Environment**：当前环境的状态与约束，例如索引里有没有这个实体、页面是否可访问。
- **Recovery**：这类失败能不能修、要几步、代价多大。

Planner 学习的映射因此从 `Task → Plan → Success` 改成对上述系统的认知。任务成功只说明结局，不说明 Planner 是否理解了系统。

## 现有做法学不到这个模型

主流管线是：

```text
Task → Plan → Execute → Success? → Reward → Policy Update
```

它默认「任务成功 = Planner 变好」。Reward Hacking 是这个假设的表象：Planner 发现反复 Retry 最终也能成功，奖励很高，系统认知没有增加。过程奖励、验证器、限制重试次数，都还在监督结局。奖励回答「成没成」，不回答「为什么成、为什么败」。

七个由此落下的洞，收成一件事：Planner 被当成了策略网络。策略网络最大化外部回报，所以会找捷径。认知系统要最小化的是对 MAS 的认知误差：能力预测、环境预测、恢复预测、世界模型是否更接近真实系统。

失败在现有范式里是负样本。在这个工作里，失败是信念修正的主要来源。成功多半只是确认已有判断，信息很少；一次自信会成功、结果失败的交互，迫使 Planner 分辨错在 Executor、Tool、Environment 还是 Plan。预测误差推动世界模型，奖励不推动。

## 预测用来设计实验

若世界模型只用来打一个成功率 \(p\)，再去选 \(p\) 更高的计划，它仍是在挑更可能成功的动作。那是 predictive planning，和 WebDreamer 同一类。

这篇的机制是 prediction-guided epistemic planning：预测用来决定下一步试错的方向。预判某条计划会失败时，问题变成——怎样设计这一次失败，使它把互相竞争的假设分开，并因此改写后续计划。

例。Executor 的三项能力未知：能否读 PDF、能否 OCR、能否解析复杂表格。整条链一起做，失败之后不知道断在哪一环，这是无信息失败（Type I）。Planner 应拆成两次实验：只读第一页（成功 → 会读 PDF），再识别扫描文字（失败 → 没有 OCR）。之后的计划就确定为「PDF → 外部 OCR → Executor 做表格推理」。失败序列把成功路径构造出来（Type III），而不是被惩罚掉。

这和 \(\epsilon\)-greedy、熵最大化不同。探索不是随机试一个没试过的动作，而是在当前信念的不确定处，选择最能区分假设的实验。设 \(H_1\)：Executor 不会 OCR；\(H_2\)：它只是处理不了大 PDF。要选的行动是

```text
e* = argmax_e IG(e; H)
```

信息增益必须改变下一步 Plan。只是「我又知道了一些事」但搜索方向不变，不算认知进步。认知进步是这条链：

```text
预测 → 决定探哪里 → 拿到证据 → 更新 M → 下一步 Plan 改变 → 后来更能做成任务
```

因此 Planner 同时做两层规划。对象层：怎样完成任务。元层：现在做不成时，该探系统的哪一处，哪一种失败对到达成功最有信息。即 Plan to Act 与 Plan to Learn。

无信息的 Retry 在这套目标下自己失去价值：信念不变，信息增益趋近于零，即使最后任务成功。不必再手写「最多重试 5 次」。

## 双输出是 MAS 世界模型的一步转移

标量 \(p\) 只能监督「成败猜对没有」。MAS 的转移发生在执行过程内部：Executor 怎样填参数，Tool 怎样搜集并返回证据，失败落在链的哪一环。Planner 作为世界模型，每一步同时输出：

- **Plan**：子目标、工具、这一步在检验的假设。
- **Imagined execution**：Executor 将如何绑定参数；Tool 将如何调用、返回什么形态的证据；预期观测；失败位点，以及这个失败能排除哪些假设。

然后只把选中的那一条交给真实 Executor。回来后按层比较，而不是合成一个成败比特：

| 层 | 预判 | 真实量 | 更新哪一块信念 |
|---|---|---|---|
| 参数 | Executor 会怎么调用 | 实际发出的参数 | Executor 如何落地；不是任务本身错了 |
| 工具动力学 | 工具会搜集并返回什么 | 工具的原始返回 | Tool 的可靠性、覆盖、超时、空结果 |
| 结局 | 子目标是否被证据满足 | 执行是否真正完成该步 | 能力边界，或环境判断 |

只有结局层有监督时，超时和「搜到了但证据不对」是同一种失败，假设空间缩不小。三层残差把失败定位成修正性证据。

学习信号沿用思考稿的原则：失败不必是负奖励。

```text
R_t = U_task + λ · I(预判, 真实) − β · 实验代价
```

\(I\) 只计算那些改写了下一步 Plan 的差异。一次有信息的失败，可以比一次没有信息的成功更有价值。

闭环是：

```text
M_t → 双输出预判 → 用预判决定是完成任务还是做诊断实验
    → 只执行选中的行动 → 三层比较 → 更新 M_{t+1} → 重规划
```

\(M_t\) 更新之后，策略是 \(\pi(a \mid M_t)\)。策略从模型里长出来。

## 什么叫学成了

世界模型要带走的是系统知识，不是某一题的轨迹。

- 能力图：一次任务里确认「没有 OCR」，之后所有需要读扫描件的任务都绕开这个 Executor。
- 工具模型：一次超时把该工具的可靠性写低，以后的任务受益。
- 反事实：Google 做成了，不代表 Wikipedia 做不成。Planner 要有计划空间的结构，而不是记住一条成功轨迹。
- 恢复：定位并修好的代价、步数、成功率本身是模型的一部分。现有 reflection 只在最终成功时给奖励，恢复能力没有被学到。

优化目标是任务推进加上认知误差的下降：

```text
max  E[R_task] − λ · E_epistemic
```

认知误差包括：能力预测准不准、环境与工具可靠性准不准、恢复代价准不准、能力图 / 工具图 / 因果图是否更接近真实 MAS。

## 这篇若要站得住，贡献是这句话

「失败也有用」已经有 Predictive Processing、Active Inference、课程学习和自我对弈。Agentic RL 里也已有过程奖励、信息增益、失败后修复轨迹。还没有被做成学习机制的是：

把失败定义成对 MAS 信念的修正，并且让 Planner 主动设计那种失败。

形式化之后要回答的是：一个 LLM 多智能体 Planner，怎样计划实验，使失败变成对未来成功有用的信息，并同时推进任务进度和认知进度。

和邻近工作的界限：

- AgentFlow 把轨迹成败广播到每一步工具选择，学的是动作轨迹，不学 Executor 为什么失败。
- EPC-AW 在计划阶段做跨 agent 的一致性校准，选中的计划仍直接真执行，没有对执行过程的预判。
- WebDreamer、HiPER、RAP 想象的是环境或子目标之后的状态，用来提高任务成功率。
- HIVE 现有的 sibling 对照发生在真执行之后，记录换过工具或参数；它还不是行动前的 MAS 世界模型，也不能把 sibling 对照再写成这篇的贡献。
- StructAgent 用证据提交进度，适合作为执行环境。它的 Planner 不预判 actor 将如何执行。

## 实验只说明主张，不代替主张

主环可以落在 HIVE 的 Planner–Executor–Diagnoser 上：给 Planner 加上想象执行头，用三层残差更新 \(M_t\)，只训练 Planner，Executor 和 Diagnoser 冻结，避免「真实量」跟着策略一起漂。工具动力学需要可复现，所以主循环用代码执行和本地语料；在线搜索太慢、返回又被摘要过，失败原因混在一起，不适合当世界模型的训练动力学。它可以留作少量探针，用来检验工具可靠性是否写对了。

要报的不是单一 pass@1。同一预算下看：任务是否至少不差；三层预判是否变准；无信息 Retry 是否减少；一次失败学到的能力或工具判断，是否改变后续任务的计划。StructAgent 只做迁移：同一套信念放到类型化动作上（表格操作、只读文件与 shell 探针），看下一步计划是否改变。点击坐标对不齐因果链，不拿来当残差。OSWorld 总分不是这篇的优化目标。
