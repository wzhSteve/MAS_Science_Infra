# Agent-R

## 1. 出处
- Venue / arXiv / 日期：arXiv:2501.11425
- 代码：ByteDance-Seed/Agent-R（MCTS path collection）

## 2. Abstract 要点
- Agent 失败后难恢复；步级 critique 数据贵。
- Agent-R：MCTS 构造“从错误轨迹恢复到正确轨迹”的 revision samples。
- 模型引导找首错步，拼接失败前缀 + 成功后缀 + 反思 thought。
- 迭代 SFT；交互环境上 +5.59% 量级提升，强调及时纠错而非终局才改。

## 3. Intro 诊断的社区盲区
只按对错奖惩动作学不会 on-the-fly reflection / recovery。

## 4. 方法三层定位
| 层 | 内容 |
| --- | --- |
| Rollout | MCTS 树探索 |
| Advantage / 数据 | 构造修正轨迹（需成功侧） |
| Loss | SFT（非 GRPO） |
| 失败用法 | **造正样本**：失败前缀+成功后缀 |

## 5. 实验设定线索
- 环境：三类交互 agent 环境（非纯搜索 QA 为主，但机制可移植）
- 关键参：MCTS 成本高；成功后缀稀缺时退化

## 7. 与 RAE：同 / 异 / 优 / 劣
- **相似**：G3/G4——失败有用、要会恢复。
- **不同**：需要成功侧存在；目标是模仿修正轨迹，不是支持集投影；无成功分支时目标崩。
- **对方优势**：恢复叙事经典；审稿人熟悉。
- **对方劣势**：难题分层（成功后缀稀缺）应崩溃——RAE 主打分层。

## 8. Baseline 决策
- **Yes（B6 主选）**
- 理由：失败利用谱系代表；搜索设定可用轻量“同前缀成功续采拼接 + SFT”近似，避免完整 MCTS。
