## 0. 掌握标准（一句话）

面试官要听的是：**你能把一条带工具的轨迹，讲成可优化的 on-policy 问题**——谁采样、谁打分、优势怎么比、哪些 token 吃梯度、你的改动改了哪一环、为什么有效或失败。

不要求：背 veRL / Ray / FSDP 行号，或默写某个 fork 的类图。

## 2. 三档深度

### Must（面试白板应能讲）

1. **On-policy 一步在干什么**  
   rollout →（工具）→ reward → advantage → actor update。Driver 编排，GPU worker 做生成与反传。

2. **Agent 轨迹 ≠ 纯文本 completion**  
   模型 token 与工具回填 token 混在同一条 `responses` 里；进 loss 的通常只有模型自己生成的部分（`loss_mask`）。

3. **Outcome reward 的常见落点**  
   一条轨迹一个标量，往往写在最后一个有效 response token；组内再做 baseline（如 GRPO）。

4. **多轨迹怎么比**  
   同一 prompt 的 `n` 条轨迹共享分组键（如 `uid`）；advantage 是「相对同组」的，不是绝对分数神话。

5. **分支 / 搜索类方法在优化什么**  
   用额外轨迹提供对比信号或探索；要能说清：分叉点在哪、新轨迹从哪续写、梯度打在谁身上。

6. **你自己的故事**  
   改了 reward / 采样 / loss / 数据中的哪一块；预期机制；结果或失败原因。

### Bonus（有则加分）

- 亲手跑通过开源 Agent RL（veRL 一类）小规模实验，能解释日志里的异常分。  
- 知道 ARPO（轮级熵分叉）与 APPO（token 级再生成 + 信用回映）差在「何时分叉、信用如何回传」。  
- 能讨论 reward hacking、格式奖励、工具滥用、长度偏置。  
- 知道 KL 可以进 reward 也可以进 actor loss，以及系数为 0 时仍可能挂着 ref 模型。

### Skip（除非 JD 偏系统 / 训推）

- Megatron、异步 rollout 调度、KV cache / sharding 实现细节。  
- 把整份 trainer 逐函数精读当主业。  
- 背配置项默认值表。

## 3. 必须能口述的概念卡

下面每张卡：定义 → 为什么重要 → 一句话自检。结合本仓库时，括号内指向 ARPO/APPO 直觉，不必记行号。

### 3.1 轨迹与工具循环

- **定义**：模型生成直到 stop tag（如 `</search>`）→ 执行工具 → 把 `<result>...</result>` 拼回序列 → 再生成，直到答案或长度上限。  
- **重要**：训练信号来自「整段交互」，但梯度应对「决策 token」负责。  
- **自检**：工具结果 token 该不该进 policy loss？为什么？

### 3.2 `response_mask` vs `loss_mask`

- **定义**：`response_mask` ≈ 哪些位置是有效 response（含工具文本）；`loss_mask` ≈ 哪些位置允许进策略梯度（通常模型 token=1，工具回填=0）。  
- **重要**：混淆两者会把搜索引擎写的字当成模型行为来更新。  
- **自检**：attention 看得到的 token，是否一定吃梯度？

### 3.3 Rollout logprob vs old logprob

- **定义**：采样时引擎给出的 logprob（行为策略）vs 当前 actor 对同一 response 重算的 logprob（常作 PPO 的 `old_log_probs`）。  
- **重要**：on-policy 近似、监控采样–训练不一致、某些分支分数会用到二者差。  
- **自检**：为什么每个 step 还要再算一遍 logprob，而不是只用 vLLM 的？

### 3.4 GRPO 式 outcome advantage

- **定义**：轨迹标量分在同 prompt 组内减均值（常再除标准差），再乘回 mask。无 critic。  
- **重要**：Agent RL 里最常见的「组内相对好坏」。  
- **自检**：`n=1` 时 GRPO 还有没有有意义的优势？组内全同分呢？

### 3.5 分叉：ARPO vs APPO（对照用）

| | ARPO | APPO（官方动态分支） |
| --- | --- | --- |
| 分叉时机 | 同一次工具循环内，偏「工具轮后」 | Trainer 里第二次生成，偏「初始轨迹某 token」 |
| 触发信号 | 相对初始熵的熵增 + 概率门 | 熵与 future value 的 z-score 等 |
| 回到 trainer | 已凑满 `n` 条 | 先初始条，再拼分支条 |
| 梯度 | 各轨迹按自有 mask 正常更新（走 GRPO） | 分支行常整段 `loss_mask=0`，信用映回初始前缀 |
| advantage | 一组 GRPO | init / branch 分组再回映 |

- **自检**：若只增加探索轨迹却不让它们进 loss，信用如何回到被更新的 token？

### 3.6 Reward 设计雷区

- 格式分 vs 答案分：只奖励格式会刷标签。  
- 工具次数奖励：易诱导无意义调用。  
- Soft / strict 解析：抽不出答案时分数语义完全不同。  
- Outcome-only：稀疏、归功难；process / 分叉是在补信用分配，不是换问题定义。

### 3.7 KL 与「挂着不用」

- Ref policy 存在 ≠ 一定在惩罚。  
- 系数在 reward 侧还是 loss 侧，面试能各举一例即可。

## 4. 一张图：Must 级数据流

```text
样本 (prompt + ground_truth)
    → tokenize / chat 前缀
    → 采样 n 条轨迹（中间可工具、可分叉）
    → 规则或模型打分 → 标量写在轨迹末 token
    → 按 prompt 组算 advantage
    → 仅 loss_mask=1 的 token 上做 policy update
```

## 5. 论文与路线：建议怎么建「问题库」

不必追求读完所有 Agent RL 论文。建议按问题收，每类能讲清「代表作主张 / 明显缺陷 / 你若复现会先验证什么」。

| 问题 | 你要能说的话 |
| --- | --- |
| 为什么 Agent 上要 RL，而不仅是 SFT | 分布偏移、多步决策、工具后状态 |
| 信用分配 | outcome 稀疏；process / 分叉 / 注意力类方法各补哪一块 |
| 采样与探索 | temperature、多轨迹、树/束、熵触发分叉 |
| 奖励 | 规则、模型裁判、工具环境反馈；hacking |
| 稳定性 | KL、clip、组大小、长度、假阴性解析 |
| 评价 | 最终答案、过程合规、工具效率、分布外 |

本仓库的 ARPO/APPO 适合当作「分叉 + 工具轨迹」的具体案例写进问题库，而不是当成唯一主流。

## 6. 代码：读到哪、何时用 AI

| 场景 | 建议 |
| --- | --- |
| 建立直觉 | 读源码指南的「地图 + 概念站」，停于能口述 |
| 改算法 | 先写清改动点（reward / mask / advantage / 采样），再用 AI 落代码 |
| Debug | 自己定位阶段（生成？打分？分组？），AI 辅助查具体报错 |
| 面试 | 讲机制与取舍；需要时说「实现落在 veRL 的 rollout/reward/advantage」，不背文件名 |

**禁止依赖**：只会说「AI 写的能跑」，讲不清 mask 与分组。  
**健康依赖**：框架样板 AI 生成，实验假设与结论你负责。

若要加深实现，优先顺序：

1. 工具循环与 `loss_mask`  
2. reward 写入位置  
3. GRPO 分组  
4.（可选）ARPO 分叉或 APPO 第二次生成  

到此为止对研究岗通常足够。系统课再往下挖 worker / 并行。

## 7. 项目怎么做才像「研究经历」

简历上有用的最小闭环：

1. **设定**：任务、工具、是否多轮。  
2. **基线**：例如 GRPO + 规则 reward，说清配置。  
3. **你的变量**：只改一处主变量（奖励、分叉、数据、loss）。  
4. **证据**：主指标 + 至少一个诊断（工具次数、解析失败率、组内分数方差）。  
5. **负结果**：什么没用、你认为为什么。

面试叙事模板：

> 问题是 X → 我怀疑瓶颈在 Y → 改了 Z → 指标与过程量变化是… → 若重做会先验证…

## 8. 面试自测（不看笔记作答）

**概念**

1. 画出 Agent RL 一个 training step。  
2. 工具回填进不进 loss？用哪个 mask 保证？  
3. GRPO 的分组键是什么？`n` 与 `train_batch_size` 分别指什么？  
4. Outcome reward 写在哪个 token 上？对 process supervision 意味着什么？  
5. ARPO 与 APPO 的分叉点与信用回传差在哪？（能答一层即可）

**判断**

6. 提高格式分权重，短期准确率上升，你担心什么？  
7. 分叉很多但 advantage 方差极小，可能发生了什么？  
8. `use_kl_loss=True` 且系数为 0，还会不会加载 ref 模型？有什么工程含义？

**经历**

9. 用 90 秒讲你最近一次 Agent/RL 相关实验的「假设—改动—结果」。  
10. 若只能再做一个 ablation，你做哪个？为什么？

参考答案不必与仓库实现逐字一致，但应与第 3、4 节不矛盾。实现核对可回源码指南自测章。
