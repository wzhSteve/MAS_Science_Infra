# Plan

本阶段调整为 **个人模型资源库与实验绑定**：先在当前工作空间维护多个模型连接和训练模型来源，再由各实验选择使用。模型资源位于实验之上，实验设置负责绑定，不再承担重复录入端点、模型名和密钥的主要职责。

**个人跨实验复用不等于平台共享。**即使只有一个人、本地使用，也需要一次配置、多实验选择；不需要先建设账户、组织、权限、公开发布或共享市场。

依赖 [第二阶段](MAS前端产品化第二阶段-画布工作区与实验设置.md) 的唯一配置草稿与 [第三阶段](MAS前端产品化第三阶段-真实调试与结果交互.md) 的执行身份边界。整体页面方向参考 [实施总览](MAS前端产品化实施总览.md) 和 [MAS 实验平台产品形态](MAS实验平台产品形态.md)。

本文件根据新的交互决策修订。**此前总览和本文件旧版将资源注册与引用全部后置的范围，不再适用于本阶段的个人模型复用能力。**新增范围限于下文的最小后端支持；数据导入、跨用户共享、逐 Agent 模型与完整训练快照仍后置。个人资源与绑定的代码已接入，实施范围见 Implementation Notes；未将完整 UI 验收或真实模型验证标为完成。

## Position in the Project

此前实现的是“按实验查看模型和数据配置的汇总页”：可以查看、跳回实验编辑和预览 parquet，但没有独立模型资源，也没有真正的实验引用。它是可复用的 UI 基础，不是本阶段修订目标的完成状态。

目标关系为：

```text
个人工作空间
  ├─ 模型资源库
  │    ├─ 推理连接 A：日常调试
  │    ├─ 推理连接 B：高质量推理
  │    └─ 训练模型来源 C：本地权重 / checkpoint
  └─ 数据入口：暂保留已有路径、用途说明与预览
                 ↓ 显式选择、绑定
       实验 A / 实验 B / 实验 C
         ├─ 默认推理模型
         ├─ 训练模型来源
         └─ 各自的 Workflow、数据配置、训练方案与运行记录
```

不要继续以“暂未建设平台共享”为由，让用户在每个实验重复维护同一个连接。也不能只增加一个下拉框，选中后复制端点到实验文件，再把复制行为称为引用。

## Requirements

- 模型资源可以独立于实验创建，拥有稳定 ID、用户可读名称、明确类型和修订信息。
- 同一个人可以保存多个模型连接、多个训练模型来源，多个实验可以引用同一资源。
- 模型页负责创建、编辑、手动检查和查看引用关系；实验设置负责选择、保存绑定与跳转维护。
- 选择资源先改变实验草稿，显式保存后才生效；打开页面、选择、保存均不自动执行模型或训练。
- 推理连接与训练模型来源分开管理，训练算法、奖励、采样与优化参数仍属于具体实验。
- Agent 首期仍继承实验默认推理模型，不顺带开放逐节点模型覆盖。
- 真实 Key 只在服务端保存和解析，不进入资源列表、浏览器持久化、实验引用、运行快照或下载。
- 资源变更对多个引用实验的影响必须明确；已开始的调用和已保存记录不改用新值。
- 旧实验默认继续按原配置运行，迁移必须显式确认，不自动批量修改已有模型连接。
- 数据读入方式未确定，不增加上传协议、数据注册存储或格式转换；保留现有服务端路径与任务预览。
- 沿用现有全宽画布、顶部导航、颜色、字体、表单与侧栏风格，不恢复固定技术模块侧边栏。

## Scope

- In：个人模型资源列表、详情、新增 / 编辑、手动连接检查、引用实验展示和删除保护。
- In：最小服务端资源存储、凭据存储、稳定资源 ID、修订校验及实验绑定接口。
- In：实验默认推理模型选择器、训练模型来源选择器，与原草稿和执行入口接线。
- In：资源解析接入就绪检查、探测、独立 Rollout、Collect、本地模型启动及训练模型来源解析。
- In：旧 inline 模型配置兼容、显式迁移、运行时来源记录与错误说明。
- In：现有数据路径、训练 / 验证用途和 parquet 预览入口继续可用。
- Out：用户账户、组织、跨用户权限、公开分享、资源市场、计费和商业平台治理。
- Out：数据上传 / 导入协议、统一数据资源注册表、任意数据格式适配、自动下载权重。
- Out：逐 Agent 模型覆盖、多策略联合训练、改变算法 / 奖励 / loss、完整训练任务快照系统。
- Out：自动替换实验绑定、自动停止其他实验服务、复制历史运行或自动重新执行。

## Current State

以下是本轮实现前的过渡基线，不应当作新的资源库能力。新增接线说明见 Implementation Notes。

- `pages\Resources.tsx` 和 `features\resources` 按实验读取 bundle，显示推理配置、训练模型来源与数据路径。
- 模型详情的编辑入口返回当前实验设置，尚无个人资源级新增和编辑。
- `LLMPanel` 仍维护当前实验 `llm.yaml` 及 `.secrets.env`；服务环境变量只是默认来源，不是具备稳定 ID 的资源。
- `resolve_llm_config` 集中解析当前实验配置和凭据；`bindSavedModel` 将已保存的模型摘要同步到 Workflow。
- 训练来源主要来自 RL 的 `model_path` 或 `actor_rollout_ref.model.path`，不是模型资源引用。
- Agent 模型字段仅支持空值 / `inherit`；单次 Rollout 已保存有效模型摘要，不等于训练也具备同等快照能力。
- 资源页可显示已保存的 `data.train_files` / `data.val_files`，并手动调用 `/api/mas/sample-data` 预览任务。
- 现有资源导航、返回设置地址和编辑会话保留机制可以复用，不需要重做前面三个阶段。

## Resource Model

| 对象 | 管理位置 | 核心信息 | 不承担的职责 |
| --- | --- | --- | --- |
| 推理连接 | 个人模型资源库 | 名称、API / 本地服务来源、模型名、端点、凭据；本地启动所需配置按现有能力保留 | 更新第三方模型权重、保存某实验训练超参 |
| 训练模型来源 | 个人模型资源库 | 名称、模型权重 / checkpoint 路径、可选说明、修订 | 自动保证 GPU / 权重可用，定义训练算法或创建训练进程 |
| 实验绑定 | 实验设置 | 默认推理资源 ID、训练来源资源 ID，明确 legacy 或 resource 模式 | 存放资源密钥、复制一份可独立编辑的资源配置 |
| 训练方案 | 实验设置 | 算法、奖励、采样、优化、设备等现有参数 | 冒充可复用模型连接 |
| 策略版本 / checkpoint 产物 | 对应训练运行 | 实际训练来源与生成结果 | 因模型名称相同就宣称是同一策略 |
| 数据配置 | 暂保留现有实验设置与数据入口 | 已保存路径、训练 / 验证用途、任务预览 | 预先确定未来上传与共享方式 |

模型来源可以增加用户友好名称，例如“研究用 DeepSeek”“本地 Qwen 服务”。端点相同、模型名相同但凭据不同，仍可能是不同资源，不能自动合并。

`rl_endpoint` 继续表示训练过程注入的端点，不包装成可以独立调试的普通固定连接。训练产生的 checkpoint 可以由用户以后登记为训练模型来源，但不在本阶段实现自动产物注册。

## Proposed Architecture

```text
个人模型资源页
  → 服务端资源目录 + 服务端凭据存储
           ↑
实验设置保存资源引用
  → 运行开始时解析绑定与资源修订
  → 不可变的本次有效模型配置
  → 原 MAS 执行核心 / 原训练启动适配
  → 记录实际资源 ID、修订与脱敏模型信息
```

- 资源目录属于当前工作空间，不能放在某个实验的目录内；更换当前实验不会更换个人资源列表。
- 首期只需要小型持久化目录，不建设用户系统或通用资产服务。具体采用文件还是数据库由实现时按现有存储惯例确定，但必须具备下文的一致性保证。
- 服务端公开模型资源与内部凭据使用不同结构；更新凭据与公开配置必须作为一致的修订提交，不能出现新端点配旧 Key 的半成功状态。
- 推理资源与训练来源采用可区分的类型，选择器过滤类型，后端也再次校验；不能只在前端隐藏错误选项。
- 实验 inline 配置和 resource 绑定采用显式模式。绑定存在时资源是唯一权威来源，旧字段不得覆盖解析结果。
- 复用原配置解析入口与执行核心，不让每个 Rollout / Collect handler 各自查一套资源。

## Model Resource UI

模型页不再先要求选择所属实验，而是显示当前个人工作空间的资源列表：

```text
模型与数据
[模型] [数据]                     [新增推理连接] [登记训练模型来源]

名称                 用途             配置摘要            被引用
日常调试 DeepSeek    推理连接         API / 模型名称      实验 A、B
高质量推理           推理连接         API / 模型名称      未引用
本地 Qwen 权重       训练模型来源     路径已填写          实验 A

点击条目 → 资源详情 / 编辑 / 手动检查 / 引用实验
```

- 推理表单维护名称、模式、端点、模型名和 Key；已有本地服务及本地启动配置保留，不强迫用户转成第三方 API。
- 训练来源表单维护名称和现有训练入口可消费的模型路径，不在这里填写学习率、奖励或 GPU。
- 未配置、已配置、未检查、最近检查成功 / 失败必须区分；资源类型或路径已填写不代表可训练。
- 保存不自动探测。手动检查继续使用明确的检查类型，`/models` 成功不等于生成或工具调用成功。
- Key 留空保留已有值；替换、显式清除须有不同语义，清除需确认。资源编辑不继承当前浏览实验的 Key。
- 修改详情前显示受影响实验数量；失败保留草稿，不以局部成功冒充整个资源已保存。
- 不在个人资源页面展示“发布到平台”“分享给所有人”等尚未建设的操作。

## Experiment Binding UI

### 默认推理模型

```text
实验设置 → 模型绑定
默认推理模型：[日常调试 DeepSeek ▾]
端点摘要 / 模型名 / 凭据已配置
[查看 / 编辑资源] [新增连接]
所有 Agent 默认继承本实验选择
                         [保存模型绑定]
```

- 默认操作是“选一个已配置资源”，不是重复输入一遍地址与 Key。
- “新增连接”携带返回位置进入资源创建；成功后返回原实验模型选择器，将新资源作为待保存选择，不能自动改写绑定或发起调试。
- “编辑资源”修改的是个人资源本身，要提示其他引用实验也会受影响；仅想修改某实验时可新增独立资源再绑定，不悄悄复制。
- 旧实验尚未迁移时仍可选择“使用实验已保存配置”，不改变其有效值。实验设置不提供旧配置编辑或迁移表单；新增、编辑与检查模型统一到管理模型页。
- 模型绑定草稿与 Workflow 草稿分开；Workflow 保存不能回写旧端点或丢掉资源引用。
- 已绑定资源不可用时显示具体错误，不自动切换到列表第一项、服务默认或其他实验的连接。

### 训练模型来源

- 在“训练方案 / 执行环境”选择已登记的训练模型来源，展示其路径和说明。
- 原算法、数据、学习率、采样、GPU 和训练确认继续属于当前实验，选择模型来源不会重置这些字段。
- 开始训练时由服务端解析来源，并固定本次模型路径；推理连接不会被静默用作训练权重。
- 原有未迁移路径保留为 legacy 模式。新绑定生效后，不让旧 `model_path` 或简参表单反向覆盖资源。
- 本阶段只固定资源解析结果，不据此承诺整个 RL / Workflow 配置已实现不可变训练快照。

## Minimal Backend Contract

以下为本阶段拟新增或扩展的必要能力，不是现有接口，也不预先规定 URL：

| 能力 | 必须具备的契约 |
| --- | --- |
| 资源列表与详情 | 稳定 ID、类型、名称、资源修订、脱敏配置、凭据状态；支持有界分页和必要过滤 |
| 创建 / 编辑 | 输入校验、资源类型约束、原子保存；编辑携带基线修订，冲突明确返回，不最后写入者静默覆盖 |
| 凭据维护 | 服务端独立保存，不返回 Key；留空保留、替换、清除的含义明确，写入失败不报告成功 |
| 手动连接检查 | 解析所选资源而非当前实验；结果关联该资源修订，资源变化使旧结果失效 |
| 实验绑定读写 | 读取有效来源；保存资源 ID 前检查存在性与类型，使用实验配置版本避免覆盖其他编辑 |
| 引用查询与删除 | 服务端查询真实引用；有引用时拒绝删除并列出引用实验；检查与删除之间不能产生并发悬空绑定 |
| 旧配置迁移 | 服务端读取原实验配置 / 凭据，显式创建资源并绑定；失败阶段可恢复，不把 Key 发给浏览器搬迁 |
| 执行解析 | 一次解析得到资源 ID、修订和内部有效配置；后续调用使用该次值，不逐 Agent 重读最新资源 |

不要在 localStorage 保存模型资源，或在 UI 中遍历所有实验并批量复制连接来模拟资源库。资源编辑、引用维护与凭据解析需要真实后端支持，不能只靠前端开关完成。

## Resolution and Change Semantics

首期采用“实验绑定资源 ID，后续运行使用资源当前修订”的规则；运行开始后固定解析结果。暂不建设可选择任意历史资源版本的产品功能。

- 资源保存时提示：会影响引用它的实验之后发起的运行；已经开始的调用不切换端点、Key 或模型。
- 就绪、探测和执行使用同一绑定解析规则。页面确认信息关联资源修订，过期时刷新，而不是沿用旧检查结果。
- 持久化轨迹至少记录实际使用的资源 ID、修订、来源与脱敏模型摘要；不能日后按资源最新值重新解释历史。
- 新增元数据不改变 Agent / 模型调用 / 工具调用的原轨迹语义，旧记录没有资源字段时显示 legacy / 未记录。
- 绑定模式下的空资源 Key 不继承其他实验 Key；若允许使用服务默认凭据，必须作为显式资源凭据来源，并在资源详情说明。
- legacy 模式继续原凭据优先级，不因启用资源页改变旧实验行为。探测临时 Key 的原能力仍保留，但不暗中保存。
- 缺失资源、类型不符、凭据加载失败和修订冲突均明确报错，不回退到另一模型或 Mock。
- 资源删除不删除历史运行或模型文件；首期有实验引用时禁止删除，要求用户先显式换绑或解除引用。
- 本地模型进程仍沿用现有实验启动 / 停止及互斥规则。启动后的临时地址不自动回写整个个人资源、影响其他实验。

## Legacy Migration

以下为保留的服务端兼容能力，不作为实验设置中的日常操作入口。前端仅引导到管理模型页面新增资源再选择绑定，不要求用户理解迁移流程。

迁移默认不自动发生，旧配置在用户确认之前持续可用：

1. 打开旧实验时显示其实际来源，用户可以继续使用实验内配置。
2. 用户选择“保存为个人模型资源”，填写资源名称并确认作用范围。
3. 服务端使用原配置和明确选择的凭据来源创建资源，再保存该实验的绑定；不经浏览器回传原 Key。
4. 创建成功但绑定失败时保留原实验配置，明确显示已创建资源，允许重新选择绑定，不能重试就重复创建。
5. 选择已有资源替换旧配置时展示前后差异，显式保存，不按同地址 / 同模型自动匹配。

- 推理连接和训练模型来源分别迁移；不把一个 API 配置同时登记成可训练来源。
- 原服务默认凭据如何用于新资源要显式选择：继续引用服务默认来源，或由服务端保存当时的值；不得通过不透明回退改变语义。
- 如需解除资源绑定并恢复实验内配置，应显式选择恢复旧值还是复制当前有效配置，服务端处理凭据。首期也可以暂不开放复制式解除，不能做含糊的“恢复默认”按钮。
- 旧 CLI / 训练调用仍可使用原 inline 配置；新引用必须在进入已有执行接口前解析完毕，不要求底层执行器读取个人资源目录。

## Data Boundary

数据资源在长期产品关系上也属于实验上层，但 **本阶段不为对齐模型界面而提前决定数据导入实现**：

- 保留现有已保存路径、训练 / 验证用途、服务端 parquet 任务预览。
- 数据页可以暂按实验显示这些配置，并明确这是过渡能力；模型页则应成为真正的个人资源列表，两者不必强行相同。
- `val_files` 表示训练内验证输入，不等于已具备独立评估执行记录。
- 预览不自动保存训练路径、不创建数据集 ID、不上传、不复制文件、不触发模型或训练。
- 未确定上传、目录导入、远端地址还是其他方式之前，不提供看似可用的导入 / 分享按钮。
- 不把不存在的字段、默认路径、读取到的前 N 条当作资源版本、文件存在证明或完整数据规模。

## Frontend State and Performance

- 资源页维护资源级编辑草稿，实验设置只维护 binding 草稿；二者不是同一份表单的两个副本。
- 原 legacy 值继续保留在服务端，实验设置不挂载旧连接表单；不为页面精简自动覆盖或删除原配置。
- 模型资源列表直接调用资源摘要接口，按页加载；不再为了列出模型读取全部实验 bundle。
- 资源详情、引用实验列表、诊断信息按需读取；保存 / 手动检查才触发相应请求，不后台轮询所有连接。
- 编辑一个资源不会通过全局 Context 广播所有字段，导致画布或其他资源卡片逐次重渲染。
- 进入资源页保留实验编辑会话、画布位置和选中节点；返回时定位原设置分组或原节点，不自动保存。
- 从选择器新建资源成功后保留待保存选项；取消创建或保存失败回到原选择，不丢原模型绑定。
- 返回上下文仅携带实验、资源 ID 和位置标识，不能包含 Key、完整 Prompt 或轨迹内容。
- 跨实验切换和关闭未保存资源表单均有明确保护；浏览器刷新不保证恢复未保存 Key。

## Implementation Notes

- `model_resources.py` 使用 SQLite 保存资源公开配置、私有凭据和实验引用；默认 `resources/model_resources.sqlite3`，支持 `SCIENCE_MODEL_RESOURCES_DB`。数据库及辅助文件被 Git 忽略，不是加密托管或多用户权限系统。
- 资源配置与凭据以同一事务提交；资源和实验绑定使用整数修订进行并发检查。绑定、迁移创建加绑定、引用删除检查使用同一存储事务边界，失败不以旧值回退成成功。
- 资源接口为 `GET/POST /api/model-resources`、`GET/PUT/DELETE /api/model-resources/{id}` 和 `POST /api/model-resources/{id}/probe`；列表支持类型、名称和分页，单页不超过 100 项。
- 实验引用通过 `GET/PUT /api/experiments/{id}/model-bindings` 维护；`POST .../model-bindings/migrate` 显式将已保存的 legacy 来源登记并绑定。推理和训练引用分别保存，使用同一实验绑定修订避免无提示覆盖。
- 凭据模式为保存的资源 Key、显式服务默认或无凭据；资源解析不继承原实验 Key。旧实验的 `.secrets.env` 和 YAML 不自动迁移，解绑恢复原 inline 来源。
- `llm_config` 统一解析推理引用；公开摘要含资源身份和修订。Workflow 中的 llm 仍只使用原 kind / model / base_url 结构，避免将新字段强塞进旧 schema。
- Rollout、Collect、模型身份和进程元数据保留实际资源来源。训练启动固定解析出的 `--model`，不把资源路径复制回 legacy RL 配置；这不等于已具备完整训练方案快照。
- 本地推理资源可只登记已启动服务的端点和模型。通过平台启动本地模型时，必须另有权重路径和与配置端口匹配的 localhost / 127.0.0.1 HTTP `/v1` 地址；不自动回写共享端点。
- 模型页不依赖实验列表，支持先登记资源；数据页继续按实验查看路径与手动预览。资源编辑、删除和清除 Key 都有明确操作及引用 / 影响说明，不提供跨用户分享。
- 实验模型组改为选择推理资源，训练组和环境组共用训练来源选择。绑定保存独立于 RL 参数保存；旧配置 dirty 时阻止切换来源，未保存训练绑定时阻止从新训练面板启动。
- 按最新 UI 简化要求，实验设置移除旧 LLM 表单、迁移登记、重复连接探测和修订说明，只保留模型选择、状态、保存、刷新和一个“管理模型”跳转。连接维护与手动探测统一在资源页；本地模型启动 / 停止继续在执行环境分组使用已保存配置。
- 删除设置分组开头的解释段落和底部保存范围说明。必要的未保存、冲突、执行错误与确认仍保留，保存接口、模型解析、旧配置兼容和训练行为不变。
- 从资源页选择用于原实验，只生成待保存选择；参数被消费后移除临时 URL 选择标记，避免下次返回重复覆盖草稿。返回工作区刷新服务端基线而不覆盖 dirty 草稿。
- 资源列表与编辑表单分别维护局部状态；模型页分块加载，无后台全量探测。未保存摘要仍使用轻量登记，输入不会通过全局 Context 驱动画布级联渲染。
- 前端 TypeScript / Vite 编译和后端模块导入通过。未运行测试套件；服务端使用临时数据的本地合成检查核对事务、冲突、迁移回滚、凭据隔离和启动参数，不读取用户真实 Key 输出、不请求真实模型、不启动训练。完整 UI 与实际服务调用由用户手动验收。

## Acceptance and Delivery Boundary

- 不先创建实验也能登记多个推理连接和训练模型来源，刷新 / 重启后仍可读取。
- 两个实验选择同一个资源，保存后都由该资源解析执行；实验文件不复制一份可独立变更的 Key。
- 只切换某实验的绑定不修改另一个实验；修改资源本身会明确提示所有引用实验后续调用受影响。
- 在选择器中新建资源，成功返回原位置，不自动保存绑定或启动执行。
- 资源修订更新后旧探测失效；进行中的调用仍使用已解析值，历史记录不变。
- 删除被引用资源会被服务端拒绝；并发编辑 / 绑定 / 删除不能留下无提示的半成功配置。
- 未迁移旧实验与旧 CLI 按原配置正常运行；迁移失败保留原可用配置，不重复创建资源或丢失凭据。
- Key 不回显、不进入 URL / 日志 / 快照；绑定资源凭据不会意外继承另一个实验的 Key。
- 训练入口实际使用所选训练来源，不用 API 是否可访问判定可训练；原训练参数和算法行为不变。
- 数据入口仍能执行原预览，未增加隐式上传、路径保存、文件迁移或独立评估承诺。
- 前端保留编译检查和用户手动 UI 验收；本阶段已包含服务端与执行接线，不能仅凭页面编译就宣称绑定、迁移和凭据一致性成立。实现时需针对这些契约做本地验证，外部模型和真实训练仍由用户明确触发。

交付完成的标准是 **个人先维护模型资源，多个实验再真实选择与使用**，而不只是拥有一个名为“资源”的页面。本阶段不交付平台共享、通用数据导入或完整训练快照。

## Risks and Edge Cases

- 资源变更影响多个实验，要区别“编辑公共引用的个人资源”和“仅为本实验换绑”。
- 资源目录是当前个人工作空间的逻辑范围，不宣称已提供跨用户访问隔离或商业级密钥托管。
- 资源修订与模型策略版本是不同概念；修改名称 / Key 也可能产生资源修订，不能把它当成权重版本。
- 资源探测不支持 `/models` 不代表无法推理；空 Key 仅在明确允许的来源规则下用于无鉴权服务。
- 多个实验引用本地端点不意味着有多个模型进程；保留原进程互斥规则，不能自动扩展为并发推理调度。
- RL 其他字段仍可能存在旧的快照边界，不能借模型来源固定扩大承诺。
