# Plan

本阶段交付独立的“资源”页面和实验内资源配置返回路径，使模型、数据不再表现为编排阶段。视觉沿用现有页面和表单，不另建资源设计系统。

依赖 [第二阶段](MAS前端产品化第二阶段-画布工作区与实验设置.md) 的设置状态与 [第三阶段](MAS前端产品化第三阶段-真实调试与结果交互.md) 的调试返回链路。全局约束见 [实施总览](MAS前端产品化实施总览.md)。

## Position in the Project

**“资源入口产品化”和“真正共享资源能力”必须分开验收。**现有模型配置按实验保存，当前执行器不支持 Agent 独立模型。纯前端改版不能把它们变成工作空间级资源引用。

本阶段按两层组织：A 层迁移现有配置和数据操作，可在不改变执行功能的前提下交付；B 层为目标形态所需的后端契约门禁，需独立批准和实现后才开放相应操作。只完成 A 层不能宣称产品形态中的资源复用已经完成。

## Requirements

- 全局导航提供“资源”，区分模型和数据；当前实验的设置提供直达对应详情及返回入口。
- 模型说明名称、来源、实际模型、配置 / 检查状态和凭据来源，不展示 Key。
- 当前实验模型与共享资源必须有不同作用域标识，不把配置值复制称为资源引用。
- Agent 默认继承实验模型；没有执行器支持时不开放看似可用的逐节点模型选择器。
- 训练与评估数据用途分开；路径、格式和导入问题只出现在相关数据流程。
- 保存模型不自动探测，探测不自动生成；创建 / 查看资源不发起付费请求。
- 所有已运行记录保持运行时脱敏信息，不回写为资源最新值。

## Scope

- In / A：模型与数据资源入口页、当前实验连接详情、已配置数据引用信息、现有预览 / 导入入口、返回设置。
- In / A：能力与作用域标签、缺失配置与依赖的上下文提示。
- In / B：定义共享模型 / 数据资源、绑定、版本、删除引用检查所需的契约和 UI 门禁。
- Out / 当前前端迁移：实施资源后端 CRUD、移动密钥、数据目录迁移、逐 Agent 模型执行支持。
- Out：自动更新现有实验绑定、自动替换调试模型为训练策略、未经确认删除资源或文件。

## Current State

- `LLMPanel` 读写当前实验 `llm.yaml` 与 `.secrets.env`，服务 `.env` 是默认来源，不是具备 ID 的模型注册表。
- `useMasDraft.bindSavedModel` 将实验保存模型同步到 Workflow；画布不能反向覆盖该来源。
- `AgentNodeSpec.model` 虽有字段，但当前运行时仅接受空值 / `inherit`，不支持独立绑定。
- 现有数据能力围绕 parquet 路径、数据预览与采集 / 训练字段；不等于具有名称、版本和共享引用的数据注册表。
- LLM 页同时包含 API 配置与本地模型启停；迁移不能漏掉本地模式或 RL endpoint 的解释。

## Proposed Architecture

```text
ResourcesPage
  ├─ Models
  │    └─ ConnectionDetails（标记 experiment 或未来 workspace 作用域）
  └─ Datasets
       └─ DatasetDetails（来源、格式、用途、可用预览）

ExperimentSettings
  ├─ 默认推理模型 → 详情 → 返回原设置位置
  └─ 数据与采样 → 数据详情 → 返回原字段
```

- A 层建立资源视图适配器，消费现有实验配置。跨实验浏览时显示“所属实验”，编辑前切换到正确的配置作用域。
- 不为名称、ID、更新时间在浏览器创建隐形数据库；没有字段时显示已有模型名称 / 实验名称或未记录。
- 已有数据路径可以展示为“当前实验的数据配置”，不能把路径字符串包装为永久数据集 ID。
- 来自画布的返回上下文只携带实验、节点 / 设置分组和字段身份，不携带 Key 或整份运行快照。
- 新资源创建能力未就绪时，页面仍可完成 A 层的配置管理；共享管理入口应隐藏或禁用并说明原因。

## Backend Capability Gates

以下均是目标契约要求，不是已经存在的接口，也不预先硬编码新的 REST 路径：

| 门禁 | 后端需提供的事实与保证 | 未通过时 UI 行为 |
| --- | --- | --- |
| R1：共享资源 | 稳定 resource ID、作用域、名称、版本、服务端凭据存储、引用实验列表 | 只展示实验级连接，不出现“修改后影响所有实验”的伪承诺 |
| R2：实验引用 | 保存 binding 与版本解析规则，运行前解析一次，旧 inline 配置兼容 | 继续原 `llm.yaml` 规则，不在浏览器批量复制端点模拟引用 |
| R3：Agent 覆盖 | 单节点模型解析进入实际执行和轨迹；训练绑定另有明确语义 | 仅“继承实验默认”，不允许保存无效独立模型字段 |
| R4：数据资源 | 格式、schema、用途、存储位置、读取预览、上传 / 导入结果及引用边界 | 保留实际已有路径与预览能力，不承诺任意格式上传 |
| R5：变更 / 删除 | 引用检查、运行时快照保留、并发版本冲突处理 | 不开放共享删除，不改历史运行的模型身份 |

门禁应由服务端能力声明或明确的 API 版本协商驱动。不能根据是否存在某个前端字段猜测执行支持。

## Migration Contract

- 现有实验 inline 模型配置默认保留，不在用户第一次打开新页面时自动迁移。
- 未来迁移须由用户确认：创建新共享资源还是绑定已有资源；明确凭据处理，不把真实 Key 返回浏览器用于搬迁。
- 删除资源不删除过去的轨迹或训练产物；绑定缺失在未来运行前明确报错。
- 资源修改仅影响之后按规则解析的运行，已开始任务不跟随最新资源变化。
- 数据用途绑定保持独立，不能默认训练数据就是评估数据。
- 若 B 层另行获批，必须先补接口 / 执行回归，再打开选择器；它不是通过前端开关就能实现的能力。

## UI Layout

```text
资源
[模型] [数据]

模型名称             来源 / 作用域       配置状态       [详情]
当前实验默认模型     API / demo 实验     已配置
```

## Acceptance and Delivery Boundary

- 不同实验模型不会因前端资源视图混合而串用；保存仍写入正确实验。
- Key 不出现在资源列表、URL、草稿持久化或导出记录中。
- Agent 没有独立模型能力时，用户无法选择后保存一个无法执行的绑定。
- 数据格式 / 引擎问题只阻止相关操作，不影响单题 API 调试。
- 从节点 / 设置进入资源详情再返回，保留原位置与未保存业务输入。
- A 层验收通过只能标记“资源入口与现有配置迁移完成”；R1–R5 未完成必须继续保留为目标差距。

## Risks and Edge Cases

- 同地址同模型不表示同凭据、同权限或同资源，不按 URL 自动合并资源。
- `/models` 可访问只表示列表探测通过，不提升为可训练状态。
- 未知数据规模、版本或模型能力显示未知，不用猜测值装饰资源卡片。
