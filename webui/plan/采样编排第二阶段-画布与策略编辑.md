# Plan

本阶段把第一阶段已经可信的执行位置做成可编排 UI，而不是把旧 Rollout Sampling 面板照搬回来。用户在同一张主画布上切换 Workflow / Sampling 语义，理解潜在边界、触发条件、预算与实际可执行状态，保存后 Preflight 显示同一组有效值。

依赖[第一阶段：可执行站点与续跑前缀](采样编排第一阶段-可执行站点与续跑前缀.md)。训练仍由 `mas/train_tir_agent.py` 和 `rl/hooks/` 执行；前端不推导训练计划或重复实现 Gate。

## Position in the Project

`workflow.sampling` 是唯一可编辑数据源。Workflow 模式表达 MAS 的静态拓扑和可能路由；Sampling 模式在同一画布上覆盖“潜在执行窗口”，Inspector 编辑被选中的 Site。它不是第二张 Workflow，也不是把动态 rollout 预先线性化；真实路径与命中结果仍由后续 Rollout Tree 展示。

```text
Workflow 草稿
   └─ 同一主画布
       ├─ Workflow 模式：Agent / Tool / Router / 连线
       └─ Sampling 模式：潜在窗口覆盖层 → Site Inspector
                                      ↓ 同一份 sampling.sites
                          服务端能力投影 / 保存 / Preflight
```

## Requirements

- UI 的候选、可执行状态、站点计数与第一阶段的服务端有效站点规则一致；不以 `effectiveSites()` 在浏览器里伪造已启用 Site。
- Workflow / Sampling 切换属于画布主操作，不放进训练参数字段或全局导航；它与添加节点、单题调试组成底部中央图标工具栏，并与左下视口控制保持同一水平线。
- 画布选择与 Site Inspector 指向同一 opportunity/anchor 身份。一个按钮只修改 `workflow.sampling`，不复制到另一份前端状态。
- 分清“配置了站点”“训练可能到达边界”“该 run 真正命中/分支”三个状态；设计时的角标不能宣称已有训练结果。
- 只允许启用当前有事件和续跑前缀的站点及有信号的 Gate；不支持的已有 YAML 保留、可查看和修复，不在无关编辑时丢字段。
- `group_n` 是每题最终候选数，`initial_rollouts` 是先跑的独立轨迹数，`beam_size` 是每个站点/快照的上限；局部覆盖为空才继承全局。不能把这三者当成解码 beam。
- 用户切换 Sampling mode、推荐配置或保存 RL 设置时，Workflow Sampling 的最终算法与候选数优先级保持现状；Preflight 显示覆盖来源。
- 没有自动 GPU 请求；单题 Mock 与 Collect 的独立轨迹不得标作训练分支验收。

## Scope

- In：画布 Sampling 模式、站点选择、可执行状态、Gate/次数/局部预算编辑、候选预览、无损保存与启动摘要。
- In：兼容旧 barrier 和原有 Site 的高级字段、未知扩展字段。
- Out：新建完整第二套 Workflow 编辑器、由 UI 计算 entropy/RAE、伪造 Router/边/token 分支能力。
- Out：展示运行后的树节点和实时奖励；属于后续树阶段。

## Current State

- `SamplingSettings.tsx` 是长列表加字段表单；用户需要用底层 Site/Gate 字段理解采样，并不能在画布语境中区分可执行、兼容和不支持位置。
- `MasGraphEditor.tsx` 已有 branch 数量角标，`useMasDraft.ts` 会将完整 Workflow 保存到实验；`workflowGraph.ts` 的序列化以 `...base` 保留 Sampling/扩展字段。
- 当前 Inspector 可设置 `when/nth`、Gate、局部 beam 和 reward，但默认 Site 已写死 `fork.beam_size=2`，使“留空继承全局”只在用户清空后才成立。
- 第一阶段的 Preflight 已能判断已配置站点，但设计页尚无只读能力投影；若 TypeScript 复制这套规则会再次产生跨层漂移。

## Proposed Architecture

### 同一画布，两种模式

画布底部中央使用统一的图标工具栏：

- Workflow 模式保留添加节点、连线、入口和节点 Inspector。
- Sampling 模式禁止拖动拓扑、连线、删除和节点库操作；普通图形弱化，只叠加潜在边界状态。点击节点/边选择 capability opportunity，左侧训练侧栏同步打开对应 Site Inspector。
- 设计态状态固定为“可配置 / 已配置 / 兼容 / 暂不支持 / 配置失效”；“已命中 / Gate 通过 / 已创建 child”只属于 Rollout Tree。
- 添加、Workflow、Sampling、单题调试只显示 18px 图标，通过现有 Tooltip 和 `aria-label` 解释；按钮使用 38px 点击区域。左下缩放、适配和小地图保持原位，但复用同一 CanvasToolbar 视觉组件。

### 产品语义与能力投影

新增只读 `POST /api/mas/sampling/preview`。服务端复用 `MASSpec`、compiler 和 `site_policy.py` 返回预算、潜在边界、实际 runtime event、前缀能力、允许的 Gate、legacy 规则及诊断。前端不复制执行能力规则，只将事实翻译成人类心智模型。

1. 顶层策略条以“采样方式、最终候选、先独立运行、剩余分支预算”解释行为；ARPO/GRPO 等实现名放进高级说明。
2. 同一主画布以机会覆盖层表示潜在边界，不把动态 Router 或所有 Tool 强行排成线性真实路径。
3. Site Inspector 按“位置—条件—动作”组织：在哪里、何时检查、什么情况下扩展、如何保留上下文、最多新增多少条；anchor/event/resume 等放进高级合同信息。

已有但暂不支持的站点要显示身份和缺失原因，保留原始字段；未声明的 legacy 默认站点以“兼容规则”单列，不冒充已创建的逐 Tool Site。开启显式站点时才物化 Site；失效节点和未知扩展字段不应因编辑别的节点而丢失。

### 保存和有效预览

前端只维护草稿；保存后的站点摘要由服务端同一有效解析器返回或通过只读检查取得。草稿可做本地输入提示，但不得替代服务端对能力/参数的裁决。训练时仍使用保存 → Preflight → 确认 → 创建 run；运行快照保存最终 Sampling。

## Implementation Notes

- 画布动作统一收进底部中央工具栏；缩放、适配和小地图保留左下并复用同一工具栏组件。进入 Sampling 后节点库和调试动作保持原位但禁用，避免工具栏宽度和视觉重心跳动。
- `samplingPreview` 对草稿做短延迟只读请求，不保存 Workflow、不请求 GPU、不创建运行。节点组件只接收派生的显示状态，Sampling 草稿仍只存在于 `useMasDraft`。
- 主画布不尝试预测真实 rollout 顺序；Tool/Agent/Router/边只表示潜在机会。运行态结果继续留给 Rollout Tree。
- 新 Site 默认继承全局 beam，而不是写死局部值；已存在的局部覆盖保持不变。
- 修复旧浮层样式覆盖 primary 背景导致模式选中态与白色画布混淆的问题；pressed 状态统一使用 accent-subtle、accent 图标和内描边。
- 画布工具按钮提升至 38px/18px，节点主要文字不低于 11px；训练侧栏使用 `clamp(350px, 21vw, 410px)`，窄屏再降至 320/280px，不使用全局 zoom。
- 本阶段未增加测试用例或触发真实训练；使用 Python 编译、WebUI production build 和本地页面交互检查确认接线与布局。

## Lightweight Validation

默认验证只编译 Python、构建 WebUI，并在本地页面检查模式切换、能力投影、双向选择与响应式布局。真实执行只由用户在服务器 WebUI 显式触发。

## Acceptance and Delivery Boundary

- 画布与路径视图操作的是同一 Site；刷新后状态、Gate 参数、未知字段都未丢失。
- 默认 legacy `after_tool` 在 UI 与 Preflight 都算一个泛化站点；显式两个不同 Tool 才显示两个具名站点。
- 暂不支持的 Router/边/Verifier/token 不会显示为“可执行”，也不会在启动检查后被静默当成首次 Tool 分支。
- 用户能看懂最终候选数、初始轨迹、分支上限和算法来源；本阶段不把画布预览宣称为训练结果。

## Risks and Edge Cases

- 路径视图是静态配置预览，动态 Router 走向不能由画布连线提前保证。
- 删除节点后仍保存的旧 Site 需要可见且可修复，不能因重新序列化丢失。
- 本阶段不实现 `on_token`；当前设计将它列为后续窗口内能力，旧配置仅展示其不支持状态。
