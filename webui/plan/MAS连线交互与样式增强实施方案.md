# Plan

本阶段在上一阶段“单一画布工作区 + 紧凑工作栏 + 常驻工具箱 + 按需属性面板 + 运行控制台”的基础上，完善连线的产品语义、视觉样式、创建方式和属性编辑体验。

上一阶段已经提供基础连线与类型修改，但连线主要依靠一条默认曲线和文本标签表达含义；节点连接点不完整，关系选择浮层位于画布中央，属性面板也缺少明确的视觉层级。本阶段不是再增加一个通用表单，而是让用户直接理解“谁可以调用什么工具”“哪些 Agent 之间如何协作”，并能顺畅地创建、修改和调整这些关系。

产品上将连线明确分为两大类：工具调用关系与 Agent 协作关系。Agent 协作关系下包含传递信息、反馈和任务路由。底层继续使用现有 `tool_call`、`message`、`feedback`、`route`，不新增运行协议或编排引擎。

本方案区分“业务关系”与“线条外观”：影响业务的是双方实体、关系方向和关系类型；上、右、下、左连接点只决定线条从哪里进出。点击线条后的属性面板负责前者，画布上的直接拖拽负责后者，不把美观调整包装成业务配置。

本阶段实现以 UI 和必要的交互逻辑为范围，进度见 Action Items。未修改后端编排引擎，也不安排测试体系或测试用例；编译要求涵盖 TypeScript、Vite 生产构建和开发模式样式转换。

## Requirements

- 连线在产品层面分为“工具调用”和“Agent 协作”两类，而不是把四个底层枚举作为平级技术选项暴露给用户。
- 工具调用连线表示向 Agent 提供工具能力，由 Agent 在运行时按需调用，不表示每次经过该线都必须执行工具。
- Agent 协作包含“传递信息”“反馈”“任务路由”，每一种都有清晰的方向、解释和视觉标识。
- Agent 与 Tool 均提供上、右、下、左四个连接点，连接点的位置不绑定业务关系类型。
- 连线方向由业务语义决定，不能因为选了上方或左侧连接点就改变含义。
- 创建连线时根据两端实体自动判断关系大类，只在确实有多种合法协作方式时要求用户选择。
- 拖拽中提供可连接目标反馈，非法连接在当前位置说明原因，不只在画布顶部显示统一错误。
- 连线必须容易点击、选择和重新连接，不能要求用户精确命中一条细线。
- 点击线条或标签后打开连线属性面板，使用实体卡片、方向操作和关系选项表达业务含义，不出现连接点方位设置。
- 创建、修改类型、反转方向与重新连接必须使用同一套规则，避免不同操作入口行为不一致。
- 保持工具绑定、图上连线与 WorkflowSpec 同步；仅改变连接点位置不应改变业务关系。
- 常驻“添加到画布”工具箱保持默认展开，仅右上角叉号可以关闭；连线操作不能影响工具箱状态。
- 保留已有点阵背景和工作区结构，不在本阶段重新调整整个页面布局。
- 不展示没有实际事件支持的运行流光、执行次数或动态数据流。

## Scope

- In：两类关系的信息架构、四向连接点、连线视觉与标签、拖线反馈、关系选择浮层、连线属性面板、连接点调整、端点重连、方向反转。
- In：统一的关系限制、重复边处理、原有非法边展示、工具绑定联动和连线视图元数据的保留。
- In：与现有运行时一致的必要限制和说明，避免用户画出“看似可执行但实际被忽略”的分支。
- Out：后端编排引擎修改、广播消息、并行分支、条件表达式编辑、动态工具参数、节点级执行回放。
- Out：完整撤销重做、节点自动布局、人工折点编辑、复杂避障算法、整张画布的跨设备视图同步。
- Out：新增测试框架、自动化交互测试、端到端测试和真实模型执行；只保留编译要求。

## Current State

以下记录本阶段实施前的基线，后续增强的实现进度见 Action Items。

当前已经具备：

- `GraphCanvas` 使用 React Flow，已接入原生 `BackgroundVariant.Dots` 点阵。
- `AgentNode` 目前只有左侧输入点和右侧输出点。
- `ToolNode` 目前只有左侧输入点，不能从工具一侧起手建立关系。
- `graphEdge()` 为所有边生成相同的箭头和默认曲线，主要通过文字标签区分类型。
- `MasGraphEditor` 在落线后判断可用类型，多种类型时弹出位于画布中央的选择框。
- `EdgeInspector` 显示两端 ID、一个关系类型下拉框和删除按钮。
- `useGraphEditor` 已实现基础重复边限制、工具方向限制和单个 Agent 的输入路由数量限制。
- 节点工具复选框与 `tool_call` 边已经通过图提交逻辑关联。

当前不足：

- 工具能力绑定看起来像必须执行的工作流步骤。
- 业务关系类型与连线颜色、虚实、标签缺少统一对应。
- 连接点过少，用户需要移动节点来迁就出线方向。
- `connect()` 没有保留拖线时选择的 `sourceHandle` / `targetHandle`。
- 修改类型时重新构造边，后续新增的连接点和视图信息容易丢失。
- 关系选择弹窗脱离刚刚完成的拖拽位置，用户需要重新寻找操作区域。
- 属性面板的端点大块留白、表单与操作缺少层级，难以形成专业编辑器的观感。
- 反馈角色限制和运行时单后继行为还没有完整前置到界面。

### Runtime Facts

以下是当前运行时的实际能力，不是本阶段拟新增的功能：

| 事实 | 代码入口 | 对界面的影响 |
| --- | --- | --- |
| `tool_call` 将工具加入 Agent 的可用工具集合 | `workflow\compiler.py` 的 `tools_for` | 文案表达“提供工具、按需调用”，不能表达“固定执行此工具” |
| 反馈源需匹配 verifier / critic，反馈目标需匹配 hub / planner / orchestrator，当前编译器同时识别对应 role 或精确 ID | `workflow\compiler.py` 的反馈分支 | 反馈选项按现有规则限制，不能允许任意 Agent 对建立反馈 |
| 每个目标 Agent 最多接受一条输入 route | `workflow\compiler.py` 的 `inbound_route` | 不能新增第二条输入路由 |
| 每个源 Agent 的 route、message、feedback 分别存入单目标映射 | `route_out`、`message_out`、`feedback_to` | 多个同类型输出会覆盖，不应画成可执行的扇出 |
| 同一源的 route 优先于 message | `next_agent()` | 不能把两者画成同时执行的两个分支 |
| 普通 Agent 将输出交给下一个 Agent；verifier / critic 有专用反馈执行路径 | `workflow\runtime.py` 的 `run_compiled_graph` | 消息不是广播，反馈也不是无条件返回 |
| `hub_react` 与仅含 hub / verifier 的子图存在专门执行路径 | `MASSpec.is_executable()`、`CompiledWorkflow.hub_subset` | 图上有效关系不等于所有拓扑都按通用图执行，界面不能承诺任意调度 |
| 后端 `EdgeSpec` 已支持 `meta` | `workflow\spec.py` | 可利用现有扩展字段保留连接点，不必新增后端字段 |

本阶段不修复或扩展这些运行时机制。UI 需要据此限制新增操作，并明确解释仍受运行拓扑影响的行为。

## Relationship Model

### Two Relationship Families

```text
连线关系
  工具调用
    tool_call：提供工具能力，Agent 按需调用
  Agent 协作
    message：传递信息
    feedback：反馈
    route：任务路由
```

| 产品分类 | 显示名称 | 底层 kind | 端点语义 | 面板说明 |
| --- | --- | --- | --- | --- |
| 工具调用 | 工具调用 · 按需 | `tool_call` | Agent → Tool | 向该 Agent 提供工具，由 Agent 自行决定是否调用 |
| Agent 协作 | 传递信息 | `message` | Agent → Agent | 将上游输出交给下游 Agent，当前运行时不是广播 |
| Agent 协作 | 反馈 | `feedback` | 反馈 Agent → 接收 Agent | 由反馈角色根据执行结果决定是否返回处理 |
| Agent 协作 | 任务路由 | `route` | Agent → Agent | 指定后续任务处理的 Agent，当前不是条件分支 |

交互原则：

- 大类根据实体组合推导，不提供允许用户随意切换“大类”的下拉框。
- Agent 与 Tool 之间只能生成 `tool_call`。
- Agent 与 Agent 之间只显示协作关系。
- Tool 与 Tool 之间不能连接。
- 工具调用的调用者、工具名称是核心信息，不能展示为普通的“执行起点 / 下一步骤”。
- 工具边不提供强制执行、调用次数、优先级或条件等后端没有支持的配置。

## Four-Side Handles

Agent 和 Tool 统一使用一个 `NodeHandles` 组件，在四边中点各渲染一个连接点。

```text
               ○ top
        ┌────────────────┐
 left ○ │ Agent / Tool   │ ○ right
        └────────────────┘
               ○ bottom
```

### Handle Identity

- 固定使用 `top`、`right`、`bottom`、`left` 四个稳定 ID。
- 不使用数组下标或运行时随机数作为 Handle ID。
- 不在同一位置叠放两个外观相同的输入 / 输出点，避免用户无法判断正在操作哪一个。
- 一个连接点允许承载多条合法关系；四个点是几何锚点，不代表最多只能有四条边。
- 端口不绑定 message、feedback 或 tool_call，关系规则与端口位置解耦。
- 四向连接点只属于画布的出线位置。用户在画布上拖拽选择或调整，不需要进入属性面板配置方位。
- 同一实体上的连接点切换不会改变关系方向、执行顺序、工具能力或协作方式。

### Connection Mode

建议使用 React Flow 的 `ConnectionMode.Loose`，四个可起手的 Handle 统一采用该模式支持的配置，端点类型的限制交给统一业务规则。

- Agent 可以从任意一边起手，连接另一个实体的任意一边。
- 允许用户从 Tool 一侧起手连接 Agent，但提交前必须规范化为 `Agent → Tool`。
- 工具反向起手时同步交换节点与 Handle：不能只交换 `source` / `target`，却把连接点留在原来的节点上。
- Agent 之间以拖拽起点作为发送方、终点作为接收方；不因为选择反馈类型而自动反转方向。
- 四向连接点不代表 Tool 可以主动调度 Agent；这是操作自由度，不是新的运行能力。

### Handle Appearance

- 默认可见但低对比，视觉圆点约 8px，透明命中区域约 20–24px。
- Hover 或选中节点时增加连接点对比度，不改变节点尺寸。
- 拖拽时突出可连接实体和连接点，无效目标使用较弱的禁用样式。
- 连接点命中区域不能与节点拖拽区争抢操作；不要用不可点击的伪元素替代真实 Handle。
- 连接点仍保留可访问名称，例如“Planner，上方连接点”。
- 不使用绿色动画表示实际运行；拖拽高亮只表达“可以连接”。

## Edge Visual System

连线样式由关系配置统一决定，不在节点组件、属性面板和连线组件中分别拼装。

| 关系 | 基础线条 | 默认色调 | 方向表达 | 常驻标签 |
| --- | --- | --- | --- | --- |
| 工具调用 | 较轻的长虚线，建议 `6 5` | 中性蓝灰 | 无执行箭头，端点和面板表达 Agent / Tool 归属 | 工具图标 + 按需调用 |
| 传递信息 | 细实线，约 1.5px | 柔和蓝灰 | 单向小箭头 | 消息图标 + 传递信息 |
| 任务路由 | 实线，约 2px | 主色系蓝 | 单向小箭头 | 路由图标 + 任务路由 |
| 反馈 | 短虚线，建议 `3 3` | 低饱和琥珀色 | 从反馈方指向接收方的小箭头 | 反馈图标 + 反馈 |

这是统一的语义配色，不开放逐条边的任意颜色、线宽选择，避免相同关系出现不同视觉含义。

### Path and Direction

- 基础路径统一使用平滑曲线，与四向连接点自然衔接。
- 首期优先复用 `getBezierPath` 与 `BaseEdge`，不实现完整路径规划器。
- 路径形状与关系类型分开：上方连线可以向上绕行，反馈不必总是从右向左。
- 有箭头的关系，箭头始终指向业务 target，而不是“用户最后选择的那个视觉点”的旧引用。
- 同节点对之间合法的多条边，以及相反方向的边，需要稳定的曲线偏移和标签错位，不能完全重合。
- 按节点对预先计算同组边的稳定排序与偏移，避免每一条边在渲染时重新扫描全部图。
- 首期只做同端点线束的区分，不承诺自动绕开所有其他节点。

### Interaction States

| 状态 | 表现 |
| --- | --- |
| 普通 | 低噪声线条与小标签，保留关系语义 |
| Hover | 适度提高线条与标签对比度 |
| 选中 | 外层主色细光晕或描边，保留原虚实和关系色；两端实体轻量高亮 |
| 拖拽重连 | 显示预览线与候选连接点，原关系在提交前保留 |
| 非法 / 遗留冲突 | 红色错误标记与简短原因，仍可选择、修改、删除 |

- 透明交互路径宽度建议 16–20px，与可见线宽分离。
- 不使用 `animated: true` 表示一条普通关系“正在工作”。
- Hover 提示、选择光晕和真实运行状态要有明确区别。

### Edge Labels

- 使用 `EdgeLabelRenderer` 渲染紧凑的 HTML 标签，替代单薄的 SVG 默认文本。
- 标签由图标、中文短标题和必要状态组成，字体约 11px，白色或轻微关系色底，细边框、小圆角。
- 点击线条或标签都选中同一条边并打开属性面板。
- 标签只负责识别和选中，不把删除、反转、类型下拉框全部塞进每条边上。
- 标签设置合适的 `pointer-events`，并使用 React Flow 的 `nodrag` / `nopan` 行为隔离，点击不带动画布。
- 双向边的标签分开定位；缩小时保持简洁，不通过放大所有标签遮挡节点。

## Connection Creation

### Agent and Tool

```text
从任意连接点开始拖拽
  -> 命中 Agent / Tool 组合
  -> 判断现有工具是否支持、关系是否重复
  -> 规范化为 Agent → Tool，必要时交换 Handle
  -> 直接创建工具调用关系
  -> 标签显示“按需调用”
  -> 同步 Agent 的工具列表
```

- 不弹出关系类型选择器，也不要求再点一次“确定”。
- 如果从工具一侧起手，预览提示“为目标 Agent 提供此工具”，消除方向上的误解。
- 绑定成功后保持常驻工具箱打开。
- 若同一个 Agent 已经绑定该工具，不创建平行重复边；提示“已提供此工具”，并可定位已有关系。

### Agent and Agent

```text
从发送方连接点拖到接收方连接点
  -> 计算当前端点下的合法协作类型
  -> 无合法类型：就地提示原因，不新增边
  -> 只有一个合法类型：直接创建
  -> 多个合法类型：在落点附近打开关系选择浮层
  -> 点击一个选项即创建，无二次确认
```

关系选择浮层：

- 替换当前画布中央的三按钮弹窗。
- 锚定落点或目标连接点附近，避开常驻工具箱、属性面板和控制台；空间不足时翻转到另一侧。
- 顶部展示“发送方 → 接收方”，下方是有图标、标题、一句话说明的关系选项。
- 不可用类型保留原因，例如“反馈仅支持 verifier / critic 作为反馈方”，不能只变灰而没有解释。
- 正在选择的连接属于临时预览，不进入 WorkflowSpec，不影响未保存状态。
- 点击选项后创建；点击空白或按 Escape 取消临时连接，工具箱保持展开。
- 弹出时焦点进入选择器；关闭后回到对应画布对象或触发位置。

### During Dragging

- 通过 `isValidConnection` 判断“这个实体组合是否至少存在一种合法关系”，不提前强制选定 message。
- 只有部分类型受限时，目标仍可吸附，落线后在关系选项中解释限制。
- 全部类型非法时不吸附，靠近目标时显示一次简短原因，不连续堆积 toast。
- 拖到空白处只取消，不创建占位节点或悬空边。

## Edge Inspector — 点击线条后的属性面板

这里的 Edge Inspector 指用户点击一条已有连线或其标签后，在画布右侧打开的“连线属性面板”。它不是节点属性面板，也不是拖线结束时选择关系类型的临时浮层。

面板沿用现有右侧约 336px 容器，重点不是堆叠更多设置项，而是清楚表达和编辑三个业务要素：

- 双方实体：谁与谁建立关系。
- 关系方向：谁向谁传递信息、反馈或路由任务；工具关系则明确谁使用哪个工具。
- 关系类型：这条关系具体承担什么作用。

不在面板中展示连接点方位、Handle ID、曲率或线宽等外观参数。线条上下左右如何摆放由画布直接操作，不能与业务关系混为一谈。

### Agent Collaboration Layout — Agent 协作线属性

```text
┌─────────────────────────────────┐
│ Agent 协作                    × │
│ 传递信息                        │
├─────────────────────────────────┤
│ 关系双方                        │
│ [Agent 图标] Planner      更换  │
│ 发送方                          │
│             ↓       反转方向    │
│ [Agent 图标] Executor     更换  │
│ 接收方                          │
├─────────────────────────────────┤
│ 协作方式                        │
│ ● 传递信息   上游输出交给下游   │
│ ○ 任务路由   指定后续处理者     │
│ ○ 反馈       返回结果供修正     │
├─────────────────────────────────┤
│ 当前关系说明 / 必要限制提示     │
│ 随 Workflow 一起保存            │
│ 删除连线                        │
└─────────────────────────────────┘
```

样式要求：

- 顶部用分类小标题、关系标题与图标建立层级，不重复显示大段解释。
- 关系双方使用轻量实体卡片：名称为主，角色和发送方 / 接收方身份为次，技术 ID 放在不抢眼的位置；不展示左右连接点等几何信息。
- 两张实体卡片之间用方向箭头和“反转方向”操作表达关系，不要求用户根据线条在画布上的朝向猜测业务方向。
- 协作方式使用纵向 radio 卡片，选中项包含主色边框与浅底，禁用项显示实际原因。
- 卡片图标与画布标签复用同一套关系配置。
- 各分区保持约 16px 间距，正文 12px，辅助说明 11px；不把所有内容塞进同一个灰色块。
- 不增加四方向按钮或端口选择器。留白用于实体辨识、关系说明与必要限制，而不是填充低价值配置。
- “删除连线”留在固定底部，弱化危险色面积，避免比编辑操作更突出。
- 内容内部滚动，头部与底部稳定，窄屏保持现有覆盖面板形式。

### Tool Binding Layout — 工具调用线属性

- 顶部显示“工具调用”，副标题“由 Agent 按需使用”。
- 两张实体卡片分别标为“使用工具的 Agent”和“提供的 Tool”，可以更换为合法的对应实体。
- 中部提供明确说明：“这条关系仅提供工具能力，不保证每次运行都调用。”
- 不展示 Agent 协作的三种关系选项，不提供反转方向按钮。
- 不展示连接点设置。更换 Agent 或 Tool 可通过实体卡片或画布重连完成，二者使用同一条关系修改逻辑。
- 底部操作命名为“移除工具绑定”，并说明不会删除工具节点或其他 Agent 的绑定。

### Editing Behavior

- 点击实体卡片的“更换”打开可搜索的候选列表，按实体类型和当前关系限制提供选项；选中合法实体后一次更新关系，不额外添加局部保存按钮。
- 更换实体时保持当前关系类型，不能在更换过程中偷偷将反馈改成消息或将协作改成工具调用。
- 修改协作方式立即更新当前草稿和画布样式，不增加第二个局部“保存”按钮。
- 非法修改保留原值，在对应选项或分区显示原因，不先应用再回滚。
- 同一条边更换实体、修改方向或类型时保留前端 edge ID，避免选中状态丢失和面板闪动。
- 方向反转仅面向 Agent 协作，保持原关系类型并重新判断合法性；不合法时说明原因，不偷偷改成其他类型。
- 反转时交换两端节点与各自 Handle，不能让线回到默认左右点。
- 关闭属性面板不撤销已应用的合法修改，未保存状态仍由工作栏表达。

## Endpoint Reconnection

需要区分两种操作，不能把“换一个出线位置”和“换一个关系对象”都当成业务修改：

| 操作 | 归属 | 处理方式 |
| --- | --- | --- |
| 挪到同一实体的另一个连接点 | 外观调整 | 只更新线条锚点，不改变实体、方向、类型与工具绑定 |
| 改接到另一个实体 | 业务关系修改 | 判断新实体与当前类型是否兼容，通过后更新关系 |

- 选中连线后使用 React Flow 的端点重连能力，不另造一套拖拽系统。
- 同一实体内调整出线位置不必打开属性面板，不重新选择关系类型，也不因遗留业务冲突阻止纯外观调整。
- 工具关系只允许改接合法的 Agent / Tool 组合，最终始终规范化为 `Agent → Tool`。
- Agent 协作重连保留当前关系类型，禁止借重连静默转换成工具调用关系。
- 若新端点不支持当前关系，显示原因并保留原边。
- 重连到空白处视为取消，不自动删除旧边；删除必须是明确操作。
- 创建、更换实体的重连、方向反转和类型修改统一调用业务规则层，修改已有边时排除自身；同实体内更换连接点只处理视图信息。
- 一次成功的实体重连原子更新双方实体、相应 Handle、业务绑定及选中状态，不先删除旧边再尝试添加新边。
- 工具重连移除旧 Agent 的对应工具绑定，再添加新绑定；与此次操作无关的 Agent 和 Tool 不受影响。

## Connection Rules

规则分为“后端明确限制”和“防止前端表达超出当前运行能力的编辑限制”，不能混为一谈。

### Basic Rules

| 场景 | 新建 / 修改行为 | 用户可见说明 |
| --- | --- | --- |
| Agent 与 Tool | 允许，归一化为 `tool_call` | 工具由 Agent 按需调用 |
| Tool 与 Agent 反向拖拽 | 允许，交换两端及连接点后存储 | 为此 Agent 提供工具 |
| Tool 与 Tool | 拒绝 | 工具之间不能直接连接 |
| 节点连接自身 | 拒绝新建 | 请连接两个不同的实体 |
| 相同 source、target、kind 已存在 | 拒绝重复；不以 Handle 区分重复关系 | 该关系已经存在 |
| 节点不存在或已被删除 | 拒绝提交 | 连接对象已不存在 |
| 工具不在现有支持清单中 | 不承诺可执行，提示不支持 | 当前运行时不支持该工具 |
| 端口已连接其他边 | 不因此拒绝 | 端口只控制出线位置 |

自连接与重复边属于编辑器明确约束，不伪称为后端已经完整实现的校验。

### Agent Collaboration Rules

- 反馈源、目标遵循当前编译器的 role / ID 匹配规则，不只看节点显示名称。
- 单个 Agent 最多一条输入 route，沿用后端明确限制。
- 新增或修改时，同一源 Agent 最多保留一条同类型输出 route、message 或 feedback，避免单目标映射被覆盖。
- 后一项是 UI 为适配当前运行能力增加的编辑约束，不是现有编译器已经报错的规则。
- 对同一源同时配置 route 与 message，首期阻止新增这种有遮蔽关系的组合，并说明“当前运行时优先执行任务路由，不支持两条分支同时执行”。
- 不通过新增条件、权重或优先级输入框伪装成已经支持条件路由。
- 不施加笼统的“整个图必须无环”限制：合法反馈可能形成回路，终止条件属于现有运行时。
- verifier / critic 的反馈路径以及 hub 子图的特殊执行方式提供上下文提示；不能用泛化文案承诺所有 message 都会被实际调度。

### Existing Graphs

- 已有图加载时保留原始关系，包括当前 UI 不允许新建的关系，不静默删边或降级成 message。
- 对同类型多输出、route 遮蔽 message、反馈角色不符等情况，标记冲突并在属性面板说明。
- 修改一条旧边时判断“修改后的候选图”，不能只检查新端点，也不能把该边自身误判为重复。
- 用户可以删除或调整冲突边，界面不能因为旧图有其他问题就完全禁止选中与查看。
- 修改 Agent 角色后重新计算相关反馈边的可用性；发现不合法时标记，不自动更换关系。
- 本阶段前端规则是编辑指导，不取代服务器最终执行判断。

## Binding and Serialization

### Tool Binding Consistency

- 图上工具边、Agent 属性里的工具选择和序列化后的 `agents[].tools` 表达同一绑定。
- 增加、删除、重连工具边及取消工具勾选，都走统一的关系更新过程。
- 删除工具绑定不删除 Tool 实体，不修改其他 Agent 的工具集合。
- 已存在的工具边在勾选其他工具后保留自身 ID 与 Handle，不把该 Agent 的全部工具边删掉重建。
- `hub.verify` 自动派生的反馈边与手动边需要去重；删除或改动对应反馈关系时保留现有配置联动，不让边无故重新出现。
- 不修改无关的节点配置、训练配置或连线元数据。

当前运行时在 hub 没有显式工具时会回退使用全局 `spec.tools`。因此，“移除 hub 工具绑定”不能承诺彻底禁用该工具。属性面板应说明该兼容行为；若产品后续需要显式的“禁止 hub 使用所有工具”，应作为单独的执行语义变更处理，不能在本次 UI 改版中通过隐藏全局工具或删除共享 Tool 来变相实现。

### Handle Metadata

业务关系继续由 `from`、`to`、`kind` 表达。Handle 仅作为渲染元数据，利用后端已经支持的 `EdgeSpec.meta` 保留线条外观；这是实现细节，不是新增的用户业务配置：

```ts
type HandleId = 'top' | 'right' | 'bottom' | 'left';
type EdgeKind = 'tool_call' | 'message' | 'feedback' | 'route';

interface EdgeUiMetadata {
  sourceHandle: HandleId;
  targetHandle: HandleId;
}
```

建议写入：

```json
{
  "from": "planner",
  "to": "executor",
  "kind": "message",
  "meta": {
    "ui": {
      "sourceHandle": "bottom",
      "targetHandle": "top"
    }
  }
}
```

- 不把 `sourceHandle` / `targetHandle` 直接作为 EdgeSpec 顶层新字段，后端模型禁止未知顶层字段。
- 前端 API 类型补齐现有 `meta` 扩展，序列化时保留无关的 meta 内容。
- React Flow 的 `sourceHandle` / `targetHandle` 与 `meta.ui` 在转换边界映射，不在多个组件内分别维护副本。
- 保存连接点只是记住线条从哪一侧进出；不能因为连接点改变就重新推导拓扑、调整工具集合或改变执行行为。
- 旧边没有端口元数据时，根据两端相对位置选择朝向对方的连接点；不存在坐标依据时使用稳定的右出左入默认值。
- 已有合法 Handle 不因修改关系、切换面板或刷新 bundle 而重置。
- 移动节点不会自动改变用户明确选定的 Handle。
- 端口元数据不包含节点位置、折点或视口，本阶段仍不实现整张画布的位置持久化。

## Proposed Architecture

建议小幅整理现有组件，保持职责清晰，不建立通用图编辑器框架。

```text
NodeHandles
  -> 四向连接点与连接状态

edgeDefinitions
  -> 关系分类、名称、描述、图标、视觉 token

edgeRules
  -> 方向规范化、合法选项、冲突原因

useGraphEditor
  -> 新建 / 修改 / 重连 / 反转 / 删除的统一提交
  -> 工具绑定和 Workflow 草稿同步

WorkflowEdge
  -> BaseEdge 曲线、交互路径、箭头、标签

RelationTypePicker
  -> 新建浮层与属性面板共用的关系选项

EdgeInspector
  -> 点击线条后的业务属性：双方实体、方向、关系类型、删除
```

实现原则：

- 图规则为小型纯函数，输入当前图、候选关系及可选的原 edge ID，返回合法结果或可解释原因。
- `isValidConnection`、创建浮层和属性面板消费同一份判断结果，不复制角色清单和错误文案。
- `WorkflowEdge` 只负责渲染，不在每次绘制时调用业务提交或重建 WorkflowSpec。
- 以稳定映射管理 edge definitions，不在每个组件里重复 switch。
- 合法修改一次提交，保留现有草稿保存机制，不增加自动远端保存。
- 业务关系更新与线条几何更新分开处理：只有实体、方向或类型变化才进入关系规则与绑定同步流程。
- 避免无意义的 try/catch、多层 fallback 或每次渲染深拷贝全图。
- 需要统计边冲突或平行边偏移时，按图变更计算一次，拖动中尽量复用。

## Risks and Edge Cases

- 四向连接点若缺少稳定 ID 或序列化映射，保存后可能回到默认端口。
- Tool 反向起手如果只交换节点、不交换 Handle，会得到连接点错位的边。
- 仅改变类型时重建 edge ID，会导致标签与属性面板闪动或丢失选择。
- React Flow 的重新连接交互与业务关系方向不是同一层，工具重连必须先规范化再判断重复。
- 原有同类型多输出边可能曾被运行时覆盖；新增限制不能以“全部编译通过”为由隐藏这个问题，也不能擅自删除旧边。
- 反馈角色允许按 role 或精确 ID 匹配，前端规则不能只用名称包含 `verifier` 之类的模糊判断。
- 普通图执行与 hub 子图执行存在差异，不应仅凭画布上有一条 route 就承诺它改变了下一步执行。
- hub 的全局工具回退使“移除显式绑定”不等于“禁止使用工具”，必须保留明确说明。
- 标签交互层可能遮挡拖线目标，应缩小标签盒子并明确 pointer-events 边界。
- 工具箱、属性面板和关系浮层同时打开时，要根据可用空间定位，不自动关闭工具箱换取空间。
- 更改节点角色、应用模板或删除端点后，临时连接候选应取消，不能提交基于旧图的候选。
- 自定义样式仍需保持连接点、箭头与主路径使用同一关系配置，避免只换标签不换线条。
