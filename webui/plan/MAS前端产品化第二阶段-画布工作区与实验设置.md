# Plan

本阶段把现有参数页面收进画布上下文，交付新的工作区顶部栏和分组实验设置。改变入口与组织方式，不改变配置字段的含义、默认值或执行算法。

依赖 [第一阶段](MAS前端产品化第一阶段-实验首页与导航骨架.md)。全局约束见 [实施总览](MAS前端产品化实施总览.md)。

第一版落地范围与兼容行为见 Implementation Notes。本轮保持现有全宽画布和视觉风格，以设置入口与草稿收口为主，不增加新的执行能力。

## Position in the Project

这是最容易发生“UI 改版后配置被旧草稿覆盖”的阶段。先统一编辑状态所有权，再让完整表单和简要配置成为同一数据的不同视图。

本阶段结束后用户能在画布内完成已有模型、训练和诊断配置，不必沿六个模块逐页操作。

## Requirements

- 顶部提供返回首页、实验名称、保存状态、调试、实验设置、训练入口与运行记录入口。
- “调试”只展开面板；“开始训练”在第六阶段接入完整确认前，复用已有明确的训练流程，不直接启动。
- 左侧工具箱默认展开，只有用户明确关闭才关闭；设置与节点选择不改变该状态。
- 设置按模型绑定、数据与采样、训练方案、评估与诊断、执行环境分组。
- 主栏“保存设计”继续只保存 Workflow；分组配置独立保存，不能无提示改成保存全部。
- 每一组显示自己的未保存、保存中、成功与失败状态；顶栏不得在仍有设置未保存时只显示笼统“全部已保存”。
- API 推理不因 GPU 或 AGL 条件不足而无法配置或调试。

## Scope

- In：工作区主栏、设置面板、字段分组、共用草稿、上下文跳转与返回。
- In：迁移现有 LLM、RL、Harness 表单能力，包括本地模型启动 / 停止、推荐、预填、插件不可用状态。
- Out：删除高级参数、修改训练默认值、自动保存、合并多份配置的后端事务。
- Out：新增逐 Agent 模型能力、通用数据平台、训练前快照协议。

## Current State

以下为实施前基线。

- `WorkflowBar` 的“运行”只是打开 `RunConsole`，并不是立即执行；新名称需要准确表达这一点。
- `WorkflowSettings` 目前主要提供拓扑信息与 `RlQuickSettings`，不是完整实验设置。
- `useMasDraft` 和 `useRlDraft` 各维护 RL 草稿，完整 RL 页面明确说明二者独立保存。
- `LLMPanel` 的密钥保存、清空输入、临时探测与配置版本已具有约束，不能在拆表单时丢失。
- `HarnessPanel` 混合插件配置和最近 Collect 诊断；配置与结果将逐步分开，但诊断对象不能被改名成任意 Rollout。
- `RuntimeProvider` 当前集中订阅训练、Monitor、AGL 和实验事件；把所有设置组件挂载在画布里可能继续扩大无关刷新。

## Proposed Architecture

```text
ExperimentSession
  ├─ WorkflowDraft（继续复用 useMasDraft 的保存契约）
  ├─ SettingsDrafts
  │    ├─ LLM / RL / Harness / 元数据：分组版本与 dirty
  │    └─ 明确映射的采集输入与训练数据字段
  ├─ WorkspaceToolbar
  ├─ GraphEditor
  └─ InspectorHost：节点 / 连线 / 实验设置
```

- 按组迁移，不一次重写所有 hooks。迁移一组后，旧页面与新面板都使用该组唯一状态源。
- RL 先保留 `normalizeRlPayload`、推荐和 TrainSignal 预填函数；预填仅改变草稿，必须显式保存。
- 用配置路径而不是显示标签区分字段：调试问题、Collect 数量、训练数据与采样参数不能共用一个容易串写的表单字段。
- 若发现迁移前两份 RL 草稿均有未保存内容，不自动选择较新的一份覆盖另一份；展示差异，由用户确定保留内容。
- 保存请求捕获提交版本；请求期间继续编辑，只清除已保存版本的 dirty 标记。
- 页面后台刷新只更新服务端基线，不覆写未保存值；模型有效配置版本变化继续复用 `bindSavedModel` 规则。
- 凭据输入留在受控、短生命周期组件内，不写入通用状态持久化。离开未保存凭据时提示，不能隐式保存或无说明清空。

## UI Layout

```text
← 实验   实验名称   设计未保存 / 训练设置未保存
[保存设计]  [调试]  [实验设置]  [运行记录]  [开始训练]

工具箱            MAS 画布                 实验设置
Agent / Tool                              模型绑定
模板                                      数据与采样
                                          训练方案
                                          评估与诊断
                                          执行环境
```

- 面板宽度、控件密度沿用现有 `mas-panel` 与共享表单；长表单在面板内滚动，不挤掉画布。
- 大屏使用侧栏，窄屏使用同样样式的覆盖面板；均保留关闭按钮与键盘焦点返回。
- 首先显示摘要与常用字段，高级参数折叠但仍可访问。不得借“简化”删除现有专业能力。
- 数据与采样的独立采集入口在第三阶段迁入；真正共享数据资源在第四阶段处理。
- 第六阶段前训练入口可打开当前训练操作区；必须标明该阶段尚未提供统一启动快照。

## Interaction and Functional Preservation

| 现有动作 | 新位置 | 不变的行为 |
| --- | --- | --- |
| 保存 Workflow | 主栏保存设计 | 保存失败不继续依赖此次保存的执行 |
| 保存模型 / 探测 | 设置中的模型绑定 | 保存不探测，探测不保存，不自动生成 |
| 本地模型启停 | 执行环境 / 模型详情 | 保留模型进程与训练互斥提示和停止能力 |
| RL 全量参数 / 简参 | 同一训练方案的两个层次 | 不再形成相互覆盖的第二份 RL 草稿 |
| GPU 推荐 / 信号预填 | 训练高级设置 | 只预填、不保存、不启动训练 |
| 插件勾选 / 保存 | 评估与诊断 | stub 保持不可启用，使用原字段 |
| 最近 Collect 诊断 | 明确标注对象的诊断操作 | 仍作用于最近 Collect，不偷换目标 |

同一问题只在主上下文显示一条摘要，详细原因在展开区域复用；不能仅隐藏错误而不给修复入口。

## Implementation Notes

- 工作区继续使用原画布与工具箱。主栏区分“保存设计”“调试”“实验设置”“运行记录”“开始训练”；后两个执行相关入口只打开对应配置 / 记录，不直接调用模型或启动训练。
- 设置位于画布右侧，分为模型绑定、数据与采样、训练方案、评估与诊断、执行环境。关闭、切组、查看兼容页面时不卸载已经打开的配置表单。
- `WorkspacePanels` 将旧 `llm`、`rl`、`harness` 路径映射到同一个 MAS 工作区内的模型、训练、诊断分组，不再并行挂载另一套可独立保存的表单。
- `useMasDraft` 只保留 Workflow、采集与执行快照职责，移除独立 RL 草稿。`TrainingSettings` 是唯一 RL 编辑入口；常用参数、完整参数、Data 字段与环境设备选择共用 `useRlDraft`。
- 数据、训练、训练环境三个分组保存的都是同一份 `rl.yaml`，不是三份独立配置。GPU 选择先更新该训练草稿，再显式保存；不再通过旧顶部栏把旧 bundle 的其他 RL 字段一起回写。
- 模型连接表单与本地模型服务区复用同一个 `LLMPanel` 实例；Key 只留在原表单组件状态，保存、临时探测、清空已提交输入和服务端凭据解析语义不变。
- Harness 仍是配置规则并诊断当前实验最近一次 Collect，结果在诊断分组内独立展示。不将该诊断改称任意调试 run 的自动评估。
- “数据与采样”提供原数据集采集入口，打开原控制台中的示例 / parquet 配置；本阶段不搬迁采集核心，也不删除单次 Rollout 的 Mock / Live 选择。
- “运行记录”打开原单次 Rollout 历史选择器；完整多类型运行中心仍属于第五阶段，训练监控继续从“更多功能”进入。
- “开始训练”打开训练方案和已有保存 / GPU 确认步骤。未保存画布有明确提示，仍使用已保存 Workflow；不宣称已经具备多配置原子快照。
- 移除画布中的全局 `idle / reward` 状态条与旧全局参数操作栏，训练活动横幅、停止、Monitor 和 AGL Metrics 入口保留。
- 设置输入仅更新各自表单组件；工具栏未保存摘要通过已有轻量登记订阅，仅在 dirty / busy 状态变化时刷新。训练状态和日志订阅放在局部组件，日志正文展开后才挂载。
- 新增设置样式直接从 `main.tsx` 导入，复用现有 tokens、表单和面板样式。设置保持覆盖式侧栏，不通过每次输入重新布局画布。
- 新版本不合并旧版本内存里的两份 RL 草稿；升级 / 刷新前应先处理旧未保存内容。新版本会话内不会再创建两份 RL 状态。
- 本轮只进行 TypeScript / Vite 编译；未运行测试套件、模型请求或训练。视觉与完整交互验收由用户手动完成。

## Acceptance and Delivery Boundary

- 同一 RL 值在简参和完整设置中一致；任一处保存不会被另一处旧状态回写。
- Workflow 保存不覆盖模型页刚保存的模型；设置刷新不抹掉画布新编辑。
- 保存中编辑、保存失败、切换实验、连续打开设置均保持正确 dirty 状态。
- Key 保存后不回显；临时探测不变成保存；不产生额外模型请求。
- 本地启动 / 停止、训练停止、GPU 推荐、信号预填和诊断插件能力均有可达入口。
- 原节点、连线、工具绑定、入口设置、几何操作与历史定位仍保持原有序列化和执行含义。

不声称本阶段已实现产品形态中的共享资源或训练快照。阶段交付以真实可使用的设置侧栏为准。

## Risks and Edge Cases

- 一个主按钮同时保存多个文件会引入部分成功语义，本阶段不暗中增加“保存全部”。
- 关闭属性面板只改变 UI，不清空选择所对应的业务配置。
- 身份为 `hub` 的默认节点可以显示“计划 / 主 Agent”等说明，但不自动修改其 ID、角色或拓扑。
