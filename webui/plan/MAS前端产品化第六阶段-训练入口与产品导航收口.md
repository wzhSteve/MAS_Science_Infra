# Plan

本阶段交付工作区突出的“开始训练”入口、训练前摘要 / 阻断说明和进入运行详情的闭环，并收起已经完成迁移的旧技术模块导航。

依赖 [第二阶段](MAS前端产品化第二阶段-画布工作区与实验设置.md) 的唯一配置草稿、[第四阶段](MAS前端产品化第四阶段-模型与数据资源入口.md) 的资源能力边界和 [第五阶段](MAS前端产品化第五阶段-运行记录与详情中心.md) 的运行详情。全局约束见 [实施总览](MAS前端产品化实施总览.md)。

## Position in the Project

这是一个有新界面的交付阶段，不是单纯清理代码。用户能够从工作区理解“为什么能 / 不能训练、将使用什么配置、启动后去哪里看”。

**训练配置快照与资源锁定不是前端确认框能保证的。**新流程可以复用已有训练启动能力，但“确认内容与实际执行完全一致”的承诺必须由启动契约和训练 worker 读取方式共同保证。

## Requirements

- 工作区只有“开始训练”作为突出的执行主操作，调试继续作为次操作。
- 点击开始训练先呈现摘要 / 条件，不因打开弹窗就启动训练或停止本地模型。
- 摘要区分默认推理模型与训练模型 / 策略来源，不把 API 可访问当成可以更新其权重。
- 有未保存设计 / 设置时，明确选择本次使用哪个版本，不偷偷读取旧配置。
- 保存失败不启动；取消确认不启动；提交中重复点击不重复请求。
- 保留停止训练、本地模型互斥确认、GPU 占用提示和现有训练参数能力。
- 训练开始后进入其实际返回的运行详情，不跳到“最新训练”代替。
- 训练条件不足不影响画布编辑和已经可用的 API 调试。

## Scope

- In：训练启动摘要、条件说明、定向修复、显式确认、启动状态、运行详情跳转、导航收口。
- In：用唯一动作入口复用现有训练 API 和停止能力，不新增第二份训练启动逻辑。
- In：核对训练运行绑定 / 快照的后端能力，未满足时保留明确限制。
- Out / 当前前端迁移：改训练算法、优化器、采样语义、资源调度或引入自动后台训练。
- Out：没有后端保证却宣称并发安全、幂等启动、运行中完全隔离或第三方 API 可训练。

## Current State

- `useRlDraft.start` 先保存 RL，再调用启动动作；不是统一保存 Workflow、LLM、RL、Harness 的事务。
- `RuntimeProvider.startTrain` 经过 GPU 确认后调用现有 train API，并固定传入现有停止本地 LLM / 确认参数。
- 当前 UI 主要通过重新读取进程列表获得训练 ID，不能据此保证多请求环境下跳到本次启动。
- 训练页、横幅和 Monitor 中已有运行与停止入口；入口重组必须保留可达性。
- 训练启动和运行中配置读取是否固定到不可变副本，必须核对后端链路，不从进程启动参数推断已经满足。

## Proposed Architecture

```text
WorkspaceToolbar：开始训练 / 查看当前训练
  → TrainLaunchReview
      → 配置摘要 + 真正阻断项 + 定向修复
      → 明确保存范围 + 资源影响确认
      → 单一 TrainCommand
          → 原 train API（或另经批准的快照启动契约）
          → 返回 run ID
          → 本次训练详情
```

- 启动动作从页面布局解耦，旧入口和新入口调用同一命令，不各自实现保存 / 确认顺序。
- 配置检查结果与数据版本关联；确认期间相关配置变化应标记摘要过期，重新确认后才可提交。
- 前端可检查字段与明确条件，但不能假设本地检查等于 worker 环境可用；后端启动错误保留真实原因。
- 本地模型会被停止时，摘要必须说明哪个服务受影响。不能只把原来的 `stop_llm: true` 隐藏起来。
- 训练中主按钮优先变为“查看当前训练”；并发规则仍由后端执行，不通过 CSS 禁用假装全局互斥。

## Configuration and Snapshot Gate

| 层级 | 前端能实现 | 需要后端保证 |
| --- | --- | --- |
| 表单版本 | 捕获本次提交对象、dirty 状态、确认摘要 | 已保存版本是否仍为当前版本 |
| 多配置保存 | 显示逐组结果，失败停止后续启动 | 多文件原子提交 / revision 校验 |
| 启动身份 | 使用 train 响应中的准确 run ID | 持久化运行归属、并发冲突与幂等语义 |
| 运行快照 | 显示服务端返回的 snapshot 标识与覆盖范围 | worker 使用不可变 Workflow / RL / 资源解析结果 |
| 继续编辑 | 保留新草稿，不直接自动写入运行快照 | 运行期间不重读被新保存覆盖的配置文件 |

前端迁移必须遵守以下二选一发布条件：

- 后端快照门禁已满足：展示准确摘要，允许编辑 / 保存下一版而不影响本次运行。
- 后端快照门禁未满足：保留已有训练能力与明确的“配置隔离尚未保证”说明，不宣称达到目标形态；如需增加运行中禁止保存等保护行为，应另行确认，不能在 UI 迁移中擅自禁用原功能。

第一种才属于产品目标的完整训练闭环。第二种可以交付训练入口产品化，但该目标项必须标记未完成。

## UI Layout

```text
开始训练
实验：名称          设计：服务端版本 / 快照未提供
推理模型：用于调试的连接
训练策略：现有训练配置的模型来源与参与 Agent
数据与采样 / 奖励与优化 / 评估规则 / 执行环境

阻断问题 → [前往对应设置]
资源影响：将停止的本地模型 / 使用的 GPU
[取消]                      [确认启动]
```

- 有未保存配置时先显示保存范围与版本选择，不将“确认启动”同时冒充“静默保存全部”。
- 没有训练算力时显示具体阻断和“返回调试”，不隐藏画布或报实验整体不可用。
- 部分信息没有证据时显示未提供，不用模型名推断策略版本、共享权重或训练能力。
- 启动失败留在摘要上下文，保留已填设置与错误阶段；不会自动回退成 Mock。

## Navigation Convergence

| 原入口 | 正式产品位置 | 移除旧导航的条件 |
| --- | --- | --- |
| Experiment | 实验首页 + 实验基础设置 | 创建、选择、名称 / seed 编辑均有替代 |
| LLM | 模型资源详情 + 实验模型设置 | 保存、探测、本地启停与凭据来源完整迁移 |
| MAS | 实验工作区 | 编辑、保存、工具箱、连线、调试均保留 |
| RL | 训练设置 + 启动摘要 + 停止操作 | 所有高级字段、推荐、预填、训练 / 停止可用 |
| Harness | 评估与诊断设置 + 可信来源的结果 | 原最近 Collect 诊断仍可达，stub 不冒充已实现 |
| Monitor | 运行详情 + 实验级资料入口 | 有归属的运行数据与无归属实验数据均有明确位置 |

- 只有已完整迁移的模块退出主要导航；兼容入口保留到约定的回退窗口结束。
- 不把兼容入口的数据与新 UI 同时做两份持久化。
- 仅做前端路径 / 入口回退，不重写实验 YAML、不清理历史、不转换密钥或资源。
- 未通过的资源、快照、归属门禁不能靠“导航收口完成”改为已实现。

## Acceptance and Delivery Boundary

- 使用受控 API 响应验证取消、保存失败、摘要过期、重复点击、启动失败和正确 run ID 跳转，不自动启动真实训练。
- API 调试可用但训练环境不可用时，训练解释阻断，调试仍可运行。
- 已运行训练显示“查看当前训练”，停止操作仍可达。
- 若没有不可变快照证据，页面与文档均不得写“保存新设计绝不会影响运行中的训练”。
- 首页 → 工作区 → 设置 → 调试 → 记录 → 返回编辑，以及训练确认 → 详情路径均可见。
- 所有原功能都有正式位置或明确兼容位置，不能以简化导航为由删除。

## Risks and Edge Cases

- 部分设置已保存但训练未启动时，说明真实状态，不回滚用户成功保存的内容。
- 训练请求断开但没有返回 ID 时显示结果未知，先查进程 / 记录，不自动再次启动。
- 原生确认弹窗与新摘要不能形成两套相互矛盾的 GPU / 停服务提示。

## Delivery Boundary

六阶段完成的是前端页面架构与交互迁移。只有总览列出的共享资源、节点模型、运行归属与训练快照门禁也通过，才能进一步宣称完整实现产品形态；未通过项保留为独立后端 / 执行能力迭代。
