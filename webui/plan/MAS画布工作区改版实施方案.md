# Plan

本阶段目标是将 MAS 从“包含工作流图的配置页面”调整为以 Workflow 为核心的可视化编辑器，建立“单一画布工作区 + 紧凑工作栏 + 按需属性面板 + 可展开运行控制台”的界面结构。

当前页面已经具备 Agent / Tool 添加、节点编辑、连线、Workflow 保存和数据采集能力，但这些能力分散在多层操作栏、固定高度画布和独立表单中。这个阶段不重新设计工作流引擎，也不扩大后端能力，重点是重新组织现有功能，让用户始终围绕画布完成搭建、配置和运行。

首期实现以 UI 布局、信息层级和必要的前端状态接线为主；实施进度见 Action Items。完整编辑历史、视图持久化和节点级运行联动列入后续扩展，不作为首期前置条件。

## Requirements

- MAS 工作区采用固定可用高度布局，画布占据工作栏与控制台之外的剩余空间，不再使用固定 510px 高度。
- 不让 MAS 页面整体上下滚动。属性面板、节点库和控制台内容分别在自身容器内滚动。
- 移除 `MULTI-AGENT SYSTEM`、`MAS · Workflow` 和常驻技术说明，保留工作流身份、保存状态及必要操作。
- 收敛全局操作与页面内操作，MAS 内仅保留一个明确的运行入口及其确认执行流程。
- 紧凑工作栏包含工作流上下文、添加节点、保存、运行和工作流设置，不在默认状态展开完整节点列表或采集表单。
- 节点库默认展开，作为独立常驻工具箱，支持按类型浏览、搜索、连续点击添加和拖入画布，只通过右上角关闭按钮收起。
- 属性面板默认关闭，随节点或连线选择打开，不再长期显示“请选择一个节点”的空面板。
- 入口是 Agent 的属性，不再作为可拖拽的“采集入口”组件。
- 将现有示例采集、parquet 采集、预览和结果统一放入运行控制台。
- 输入数据与执行方式分开配置，不再用多个 Collect 按钮表达不同组合。
- 保存 Workflow、保存训练配置和运行任务必须保持明确边界。
- 保留现有接口与执行语义，不展示没有后端支持的停止、实时 token 或节点执行进度。
- 优先复用当前 React Flow、基础 UI 组件、样式 token 和数据请求逻辑，不引入另一套编辑器或设计系统。

## Scope

- In：MAS 全屏式工作区布局、紧凑工作栏、可搜索节点库、按需属性面板、连线属性交互、工作流设置入口、可折叠和调整高度的运行控制台、采集入口整合、文案调整、响应式布局。
- In：为上述 UI 接通必要的选中状态、连线修改、删除同步、数据预览内容、运行状态和错误展示，避免新界面存在无效操作。
- Out：WorkflowSpec 协议变更、编排引擎重写、数据处理节点、LLM 与 RL 页面重做、新增训练能力、新增后端接口。
- Out：完整撤销重做、跨刷新视图持久化、自动布局算法、复杂运行历史、节点级执行回放。这些能力在后续阶段独立实施。
- Out：测试体系建设、测试用例编写和专门的测试验证阶段；本文聚焦 UI 实施，不设置对应章节或任务。

## Current State

以下记录改版前的实现基线，便于理解组件迁移；当前实施进度见 Action Items。

- `webui\src\pages\MAS.tsx` 使用 `PageHeader`、`Section` 和 `ParquetCollect` 纵向组织页面。
- `WorkflowActions` 在画布上方同时展示保存、采集条数、算法、mock 采集和 live 采集。
- `GraphToolbar` 常驻展示模板、连线类型、可执行状态与入口信息。
- `GraphPalette` 常驻展示角色、工具和“采集入口”拖拽操作。
- `MasGraphEditor` 使用画布与属性栏并排布局，即使未选择节点也显示属性栏。
- `GraphCanvas` 已基于 React Flow 提供拖拽、连接、缩放、适应视图与小地图。
- `NodeInspector` 编辑节点参数，同时在入口节点中展示全局 RL 简参。
- `ParquetCollect` 是画布下方的独立 Section，包含数据文件、来源筛选、题目数和结果表格。
- 全局 `GlobalActionBar` 也存在 Collect 操作，使用已保存配置；MAS 内采集则先保存当前草稿。
- 当前 parquet 预览只将任务 ID 拼接成提示，没有展示问题内容。
- `useGraphEditor` 已维护节点与连线状态，但没有完整编辑历史；画布位置不写入 WorkflowSpec。

当前不足：

- 编辑对象被多层标题、配置和工具栏压到页面中间。
- 画布没有利用完整工作区，默认属性栏又占用横向空间。
- 运行入口重复，用户无法直观看出保存和执行对象的差异。
- 全局配置与节点配置混在一起。
- 技术字段名直接出现在主界面，理解成本偏高。
- 外层页面、属性栏和结果区缺乏清晰的滚动边界。

## Proposed Architecture

保留 `MASPanel` 作为页面编排入口，继续由 `useMasDraft` 管理草稿、保存和采集；图编辑状态保持在 `useGraphEditor`，界面显隐状态与业务草稿分开。

建议组件关系：

```text
WorkspacePanels（MAS 专属布局模式）
  MASPanel
    WorkflowBar
      WorkflowIdentity / SaveStatus
      AddNodeTrigger / SaveAction / RunAction / SettingsAction
    MasGraphEditor
      GraphCanvas
      GraphPalette（默认展开，可手动关闭）
      NodeInspector / EdgeInspector / WorkflowSettings（互斥）
    RunConsole
      RunConfig
      RunResults
      RunLog
```

分层职责：

| 层级 | 职责 |
| --- | --- |
| `MASPanel` | 组合工作栏、编辑器和控制台，连接保存与运行，不承载复杂表单细节 |
| `WorkflowBar` | 工作流身份、状态和主要操作；运行按钮打开控制台配置，不立即发起真实模型调用 |
| `MasGraphEditor` | 编排画布、节点库与属性面板，管理当前编辑对象 |
| `GraphCanvas` | 节点与连线呈现、选择、拖拽、连接和视图操作 |
| `GraphPalette` | 节点类型检索、节点添加与模板入口 |
| 属性面板 | 展示选中对象或工作流设置，避免同时展开多个右侧面板 |
| `RunConsole` | 运行配置、数据预览、状态、结果与日志 |
| `useMasDraft` | Workflow 草稿、保存、采集请求、预览数据及操作反馈 |
| `useGraphEditor` | 图状态与 WorkflowSpec 之间的同步、节点及连线编辑 |

不要求拆出每个展示型小组件。优先形成清晰的工作栏、编辑器、控制台三个边界，避免为改版引入过度抽象。

## Workspace Layout

目标布局：

```text
应用导航 │ 实验 / demo · Workflow · 已保存   ＋添加  保存  运行  设置
         ├──────────────────────────────────────────────────────
         │
         │ [节点库：默认展开]             [属性面板：按需展开]
         │
         │                    Workflow 画布
         │
         │ [缩放] [适应画布] [小地图开关]
         ├──────────────────────────────────────────────────────
         │ ▸ 运行控制台                   最近运行：未运行
```

布局规则：

- MAS 使用工作区专属布局类，移除普通内容页的外层大 padding 和 page-stack 间距，不影响其他页面。
- 从 `workspace-main`、`workspace-content`、活动面板到 `MASPanel` 建立完整的可伸缩高度链，相关 flex/grid 子项设置 `min-height: 0`。
- 隐藏面板继续遵循现有 `hidden` 机制，MAS 专属 display 规则不能让非活动页面重新出现。
- 工作栏建议高 48–56px；控制台收起时高 36px；画布填满中间区域。
- 保留应用导航与必要的全局状态信息，但在 MAS 模式下不再显示完整实验参数摘要、GPU 控件和全局 Collect / Diagnose / Train 操作组。
- 将必要的实验身份放到 MAS 工作栏中，其他页面保持现有 `WorkspaceHeader` 行为。
- 不用“铺满整个浏览器”的绝对定位覆盖应用导航，应在现有工作区内部铺满。

## Compact Workflow Bar

工作栏从左到右建议组织为：

```text
实验 / demo · Workflow   已保存       ＋ 添加   保存   运行   设置
```

- 工作流名称使用现有真实身份，不新增尚不存在的命名或重命名能力。
- “＋ 添加”打开节点库，包含 Agent、Tool 与模板分类；重复点击不会关闭已经打开的工具箱。
- “保存”只保存 Workflow；保存中禁用重复提交，保存失败保留未保存状态并显示原因。
- “运行”打开控制台并选中“运行配置”，不在工具栏内展开条数、文件路径和算法。
- “设置”打开右侧工作流设置面板，显示 topology 等技术详情，并提供独立的训练简参区域。
- 首期不摆放尚未实现的撤销、重做或整理布局按钮；后续能力完成后再接入。
- 页面未保存状态使用简短文字或小圆点，不使用大面积 warning 横幅。
- Workflow 保存状态与训练配置保存状态分别显示，不能用一个“已保存”概括两者。

## Node Library

节点库采用画布内左侧浮层，建议宽 240–280px，有搜索框、分类切换和可滚动内容区。

- 进入 MAS 时默认展开；手动关闭后，可点击“＋ 添加”或空画布引导重新打开。
- Agent 角色和 Tool 类型来自现有 palette，不硬编码另一套清单。
- 点击条目，在当前可见画布区域添加节点并选中，打开对应属性面板。
- 支持把条目拖入画布，沿用 React Flow 的屏幕坐标到画布坐标转换。
- 点击或拖拽添加后保持工具箱展开及当前搜索、分类状态，支持连续添加；新节点选中并在可见区域展示，连续点击添加时错开位置。
- 若现有模型不允许重复添加同一个工具或单例节点，禁用对应条目并明确显示“已添加”，不能点击后无反馈。
- 工具箱只通过右上角关闭按钮关闭。点击外部、按 Escape、选择节点 / 连线、打开工作流设置或运行控制台均不改变其展开状态。
- 工具箱开关独立于右侧属性面板，可以与节点属性或工作流设置同时存在；搜索框内快捷键不应触发画布删除等操作。
- 模板位于独立分类，不在工作栏逐个平铺。
- 模板操作明确使用“替换当前工作流”文案；非空画布应用模板前需要确认，取消时不改变草稿。
- “运行入口”从节点库移除，由 Agent 属性操作设置。

空画布仅显示简洁引导：“添加 Agent”与“从模板开始”。已有节点时不保留介绍性说明。

## Contextual Inspector

属性面板建议桌面端宽 336px，作为画布右侧覆盖面板，保留内部滚动、标题和关闭按钮。

- 未选择对象时默认关闭，不显示占位空面板。
- 同一时间只显示节点属性、连线属性、工作流设置中的一种。
- 点击画布空白处取消对象选择并关闭对应属性面板；工作流设置通过关闭按钮或 Escape 退出。
- 面板出现时不要自动 fitView 或重置用户缩放；必要时只将选中对象平移到未遮挡区域。
- 窄屏时使用覆盖抽屉，不将属性表单堆在画布下方。

### Agent Properties

- 优先显示名称 / 标识、角色、Prompt、Skills 和 Tools。
- 技术 ID 可只读展示，不在本阶段引入重命名带来的关联迁移。
- “参与训练”保留在节点属性中。
- “设为运行入口”作为明确操作，当前入口显示状态而非重复执行按钮。
- hub 专属 verify 设置保留，放入高级节点配置并解释用途。
- 全局 RL 简参从入口节点属性中移出，放进工作流设置的独立区域。
- Workflow 与 RL 保持各自保存操作，明确“训练配置需单独保存”。

### Tool Properties

- 显示工具名称、类型及现有可用说明。
- 不把 Tool 展示为可设置运行入口的对象。
- 不增加后端没有定义的工具参数表单。
- 通过 Agent 的工具选择与画布连线修改时，保持两种表达同步，不产生“表单已移除、图上仍连接”的状态。

### Edge Properties

- 连线属性面板是点击画布上的线条或线条标签后，在右侧打开的面板，不是节点属性面板，也不是创建连线时的类型选择浮层。
- 面板只围绕影响业务的三个要素组织：关联的双方实体、关系方向、关系类型；提供更换实体、修改类型、合法的方向反转与删除操作。
- 上、右、下、左连接点仅用于安排线条的出入位置和改善画布观感，不代表业务输入输出，也不决定执行顺序。
- 属性面板不设置“发送方 / 接收方连接点”的方位选择项，也不展示 Handle ID。线条从哪一侧进出，在画布上通过拖拽调整。
- 将同一条线挪到同一个实体的另一个连接点，只改变外观，不改变双方实体、方向、类型或工具绑定；改接到另一个实体才属于业务关系修改。
- Agent 到 Tool 的合法连接明确为工具调用，不让用户手动选择无意义的关系。
- Agent 之间存在多种合法关系时，拖线结束后显示就地选择器，确认后再提交连线，取消不生成边。
- 可选关系结合 palette 和已有图规则过滤，不仅依赖通用下拉框。
- 非法连接在交互处明确提示原因，不先保存无效结构再等待运行报错。
- 删除节点或连线后立即同步草稿及关联工具信息，不依赖后续拖动节点才能保存删除结果。

## Run Console

移除独立的 `ParquetCollect` Section，将采集与预览相关能力合并为工作区底部控制台。

控制台分为：

```text
运行配置 | 结果 | 日志
```

- 默认折叠，只显示名称与最近一次运行摘要。
- 展开后默认占工作区约三分之一高度，可通过顶部拖动柄调整高度。
- 高度上下限按可用工作区动态限制，始终保留可操作的画布区域。
- 拖动柄支持键盘调整；收起与展开按钮有明确可访问名称。
- 展开、收起、切换标签和改变高度均不能丢失配置、结果或草稿。
- 开始运行时保留当前标签，不强制切换到日志页。
- 完成后在“结果”标签增加状态提示，不打断正在编辑节点的用户。
- 运行失败时控制台头部显示失败状态与可展开详情，不把错误仅放在自动消失的提示中。

### Run Configuration

将输入来源与执行方式拆为独立配置：

| 配置项 | 选项或内容 |
| --- | --- |
| 输入数据 | 示例任务 / parquet 数据集 |
| 执行方式 | 模拟执行 / 真实模型 |
| 示例任务配置 | 题目数 |
| parquet 配置 | 服务端文件路径、数据来源筛选、读取题目数、预览按钮 |
| 高级配置 | 采集训练信号所用算法，沿用现有配置来源与传参语义 |

- 主操作使用“开始模拟运行”或“开始真实运行”，根据所选方式更新文案。
- 真实模型模式常驻提示“将调用已配置的模型及工具，可能产生费用”，不能仅依赖图标或 tooltip。
- 仅展示现有后端支持的组合，不为 UI 自由组合新增后端行为。
- parquet 文件路径标明“服务端可访问的路径”，不伪装为本地文件上传。
- `source` 改为“数据来源筛选”，明确是在文件内容中筛选来源。
- `data_n` 改为“读取题目数”，说明是筛选后的前 N 条，不描述为随机抽样。
- 题目数与 RL 每题采样数分开解释，不复用容易混淆的 `n` 文案。
- 算法配置放入默认折叠的高级区域，说明其影响训练信号生成，而非 Agent 拓扑。
- 预览只读取任务，不保存工作流、不发起模型调用。
- 预览展示任务 ID、来源与问题内容，长内容可展开；不再只展示 ID 提示。
- 路径、筛选或题目数改变后，将旧预览标记为过期或清除，避免误认为即将执行的输入。
- 保留运行前自动保存 Workflow 的行为，保存失败立即终止，不运行旧版本。
- 数量非法或文件路径为空时在对应字段提示，禁用执行而不是静默改写输入。

### Results

- 结果区承接现有 `id`、`answer`、`reward`、`tool` 数据，中文列名为“任务”“回答”“奖励”“工具调用”。
- 表格前显示完成条数、平均奖励与后端返回的产物位置。
- 没有结果时显示“运行完成后，结果将在这里展示”，不使用模拟数据填充。
- 长答案在单元格中截断，允许展开查看，避免撑破控制台布局。
- 新运行开始后仍可保留上一次结果，但必须标明“上次运行结果”，不能把它显示成本次结果。
- 新运行失败时保留失败信息，旧结果不能制造成功印象。
- 不把“调用过工具且奖励大于零”统一命名为任务成功，避免将特定演示逻辑当成通用判定。

### Logs and Progress

- 复用已有任务级 `collect_progress` 事件与请求结果，接入现有运行时订阅，不另建重复轮询或连接。
- 展示可获得的运行开始、任务进度、完成与失败信息。
- 现有事件没有 token、节点执行顺序或中止能力时，不显示对应控件和动画。
- 日志明确区分界面操作记录与后端事件，不将前端时间戳伪装成模型执行日志。
- 如果请求阶段只能获得开始与完成状态，就显示处理中，不编造百分比。
- 日志加载或连接失败明确提示“进度暂不可用”，最终结果仍以真实请求结果为准。

## Interaction Flow

首期主流程：

```text
进入 MAS
  -> 直接看到画布
  -> ＋ 添加 Agent / Tool
  -> 选中节点，按需编辑属性
  -> 拖拽建立连线，选择合法关系
  -> 保存 Workflow
  -> 点击运行，展开运行配置
  -> 选择输入与执行方式
  -> 可选预览 parquet 任务
  -> 确认开始运行
  -> 自动保存当前 Workflow
  -> 保存成功后发起采集
  -> 控制台展示进度、结果或失败原因
```

状态原则：

- 编辑状态、保存状态、运行状态和控制台展开状态相互独立。
- 运行期间不允许重复发起采集，执行按钮显示真实 pending 状态。
- 保存提交后发生的新编辑继续保留为未保存，不能被较早请求返回清除。
- 运行使用启动时保存的 Workflow；若运行中继续编辑，明确提示结果对应启动时版本，不对应后续修改。
- 切换实验时清空上一个实验的选择、预览、运行摘要与局部界面状态，避免跨实验混用。
- 无法运行时说明原因；能够定位到节点或连线的错误就提供定位操作，无法定位的错误保留整体提示。

## Styling Strategy

目标是浅色、低噪声的专业编辑器，不用大面积装饰抢夺画布注意力。

- 画布使用 xyflow 原生 `Background` 的 `Dots` 点阵，20px 间距、1.5px 点大小，配合极浅灰底；点阵随画布缩放和平移，不另叠加 CSS 网格。
- 工作栏、属性面板和控制台使用已有 surface 与 border token。
- 画布浮层采用细边框、轻阴影及统一圆角，避免每一块都有强烈卡片感。
- 节点只保留名称、角色、入口与必要状态；完整配置进入属性面板。
- Agent 与 Tool 通过图标、端口和边框样式区分，不依赖大量不同背景色。
- 选中使用主色描边，错误使用红色提示；颜色之外提供文字或图标，避免仅靠颜色传达状态。
- 缩放与适应画布常驻左下角，小地图通过开关按需显示。
- 中文用于操作和字段解释，Agent / Tool / Workflow 等领域词按需保留。
- 技术 ID、路径与 YAML 等信息使用等宽字体，但不作为主视觉标题。
- 悬浮按钮必须有 tooltip 和可访问名称；必要的主要操作保留文字，不做全图标工具栏。
- 空状态、加载状态和错误状态保持在对应区域，不让状态提示把整个画布推离视口。

## Responsive Layout

- 宽屏：工作栏单行，节点库与属性面板覆盖在画布两侧，控制台在底部展开。
- 中等宽度：压缩身份区域和低频操作，将技术详情收进设置；工具箱与属性面板保持独立，不为腾出空间自动关闭工具箱。
- 窄屏：保留添加、保存和运行，其他操作进入更多菜单；属性以覆盖抽屉展示，宽度不超过视口。
- 控制台在窄屏中保留标签切换，内容自身滚动，不使页面产生横向溢出。
- 不承诺手机端具备桌面级复杂编排效率，但应能够查看画布、编辑必要字段并运行。

## State and API Boundaries

现有请求接口保持不变：

- `putWorkflow`：保存工作流。
- `collect`：按配置执行采集。
- `sampleData`：预览 parquet 任务。
- RL 保存接口：独立保存训练配置。

建议明确三类前端状态：

| 状态 | 内容 | 是否影响 Workflow 未保存标记 |
| --- | --- | --- |
| Workflow 草稿 | 节点、连线、入口和节点参数 | 是 |
| 运行配置 | 数据来源、模式、题目数、文件路径、算法 | 否 |
| 界面状态 | 节点库开关、属性目标、控制台标签和高度、小地图开关 | 否 |

- `sampleData` 的 tasks 需要保留为结构化数据，供预览区域消费。
- `collect` 的摘要、产物位置和 rows 保留在运行结果状态中，不只拼接成提示字符串。
- 展示层不直接重写 HTTP 请求或拼装另一套 WorkflowSpec。
- 全局 RL 设置继续消费现有 `renderRlSettings` 能力，只改变承载位置与保存提示。
- 不为了界面布局扩展后端模型，也不把节点坐标等视图信息混入执行协议。

## Risks and Edge Cases

- 仅修改 `MAS.tsx` 无法实现稳定全高画布，必须配合外围布局；样式要限定 MAS，避免其他页面失去滚动。
- MAS 面板目前随应用面板一起挂载，非活动状态尺寸可能为零；回到 MAS 时不能因此覆盖正常视口或错误执行 fitView。
- 右侧浮层可能遮住选中节点，需要处理可见区域，但不能每次选择都重置整个画布。
- Workflow 保存与全局已保存快照存在时序差异；运行可用性不能长期被过期的全局状态锁死，最终仍以后端对提交版本的校验为准。
- 节点工具复选框与 `tool_call` 连线表示同一关系，迁移交互时必须保持一致，不能只改变视觉。
- 模板会替换现有图，而首期没有完整撤销栈，因此必须提供明确的替换确认。
- 运行配置与 RL 简参中的算法可能具有相近命名，必须说明保存归属与用途，不能暗中相互覆盖。
- 运行期间编辑与采集结果不是同一时刻的数据，需要明确结果归属，避免用户误判本次修改已经执行。
- 控制台拖动与画布拖动要隔离事件；浮层内输入快捷键不能触发节点删除。
- 进度事件与请求返回可能先后到达，应按同一次运行归并；缺少可靠关联信息时只展示可确认的进度，不把其他操作事件当作本次结果。
