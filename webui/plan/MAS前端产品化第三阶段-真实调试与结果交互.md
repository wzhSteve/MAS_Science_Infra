# Plan

本阶段交付面向用户的底部调试面板：“输入问题 → 发送调试 → 查看答案和执行过程”。复用单次 Rollout 的全部执行、快照和读取契约，同时改善错误呈现与大记录展开体验。

依赖 [第二阶段](MAS前端产品化第二阶段-画布工作区与实验设置.md)。全局约束见 [实施总览](MAS前端产品化实施总览.md)。

本阶段第一版已按下方 Implementation Notes 实施；用户要求仅保证编译，故性能测量与浏览器交互验收保留待办，不以结构优化代替实测结论。

按最新交互要求，过程展示进一步收敛为 **Agent 级任务交接与输出摘要**。取消细粒度事件、工具、对话的多页签和页面内详细 JSON 渲染；详细记录只允许下载文件后查看。后端记录粒度不变。

## Position in the Project

本阶段不是新增执行器，也不是把 Rollout 改成普通聊天。用户看到更简单的交互，服务端仍保存同一份可追溯轨迹。

默认隐藏 Mock / Live 选择属于明确的产品行为变化，必须通过新入口隔离；不能让旧入口的模拟操作静默变成付费调用。

## Requirements

- 顶栏“调试”只展开面板，面板“发送调试”才提交真实执行。
- 正式入口明确标注“真实调用，可能产生费用”，首次进入不自动执行。
- Mock 保留在明确的开发 / 演示入口，不与真实结果混合；现有 mock API 不删除。
- 发送继续先保存 Workflow，再执行同一份捕获快照；失败不提交，途中编辑不加入本次运行。
- 页面切换、断线、失败与重试不自动重复付费请求。
- 结果与错误始终绑定实验和 run ID；旧失败不能被误认为新运行的当前状态。
- 默认不展示 parquet、GPU、AGL 和训练字段；需要时从设置进入。
- 日志展开卡顿是待复现问题，不预先宣称某个组件就是唯一根因。

## Scope

- In：调试输入、模型简要状态、发送入口、答案与 Agent 输入输出摘要、错误分层、本次 / 历史结果标识。
- In：将独立数据集采集移至“数据与采样”，保留全部原参数、预览与结果访问。
- In：基于测量优化日志、JSON、轨迹渲染和无关轮询。
- Out：模型 token streaming、后台队列、取消运行、断线自动续跑、自动重试、任意节点续跑。
- Out：减少服务端记录内容来换取前端流畅度。

## Current State

以下为实施前基线；第二阶段已移除画布全局状态条，并提供采集入口跳转，本阶段直接沿用。

- `useMasRolloutRun` 默认 mock，POST 同步等待，已区分保存、运行、失败、中断与结果未知。
- `RunConsole` 同时包含单次 Rollout 和数据集采集，两种用途还共用部分视觉状态。
- `ModelReadiness` 会在阻断项与依赖详情重复显示同一缺失依赖；“刷新检查”不等于重启后端依赖缓存。
- `RolloutResults` 根据历史选择决定展示对象；`RolloutHistory` 已有“返回本页运行”，但当前与历史状态仍需更醒目标识。
- `TrajectoryDetails` 已有分页预览与按事件读取完整内容，不应倒退成一次读取全部轨迹。
- `JsonDetails` 在折叠时也计算 JSON 文本；`LogPanel` 渲染整段传入日志。这是性能调查线索，不是卡顿根因的既定结论。
- 全局 `StatusBar` 的实验事件 / reward 不属于当前单题运行，不应继续常驻干扰调试。

## Proposed Architecture

```text
DebugPanel
  ├─ DebugComposer + ReadinessSummary
  ├─ CurrentAttemptStatus（不受历史选择影响）
  └─ ResultViewer（current 或显式历史 run ID）
       ├─ 答案 / 错误
       └─ Agent 输入输出卡片 + 下载完整 JSON

ExperimentSettings → 数据与采样 → CollectPanel（原能力）
Developer / Demo → Mock 入口（明确标记）
```

- 复用 `useMasRolloutRun` 与 `executeWithSavedWorkflow`，不要在新按钮里绕开保存锁直接请求。
- 正式入口固定发送 `execution: live`；演示入口固定标记模拟。旧未提交 mock 草稿不能迁移为自动 Live 提交。
- 本次操作生命周期与正在查看的结果分开：可以查看旧记录，但始终看到新任务是否运行及其返回。
- 单次运行、数据集采集和历史记录共用底层组件，但使用不同身份和数据适配器，不能用一个“最新结果”变量代替。
- 读取详情失败只影响详情，不把成功运行状态变成运行失败；结果未知不能自动变成 failed 或 succeeded。

## UI Layout

```text
调试                         当前模型：实验默认       [配置]
[输入希望这个 Workflow 完成的任务……]
真实调用，可能产生费用                    [发送调试]

本次：执行中 / 已完成 / 失败 / 结果未知      Run ID
当前查看：本次结果 / 历史结果 · 时间        [返回本次]
最终答案或一句错误摘要
Agent 过程：输入摘要 → 输出摘要
[下载完整 JSON] [下载本页操作日志]
```

- 面板仍默认收起并可调高度；不会新增覆盖整张画布的聊天应用。
- 主答案和问题使用业务语言，运行身份、完整性与能力详情按需展开。
- 错误摘要示例：“模型请求失败”；提供已知阶段、节点定位与错误详情下载，不在页面内铺开供应商错误原文。
- 不用字符串猜测覆盖后端错误分类。已知错误可增加解释，未知错误保留原文入口。
- 后端断开统一提示服务不可达；不能每个区块各显示一条相同 `Internal Server Error`。

## Performance Work

先记录复现步骤、数据规模、浏览器和机器条件，再决定优化手段：

1. 分别测量打开面板、查看 Agent 卡片、加载后续过程和下载记录的耗时与请求；不再将页面内详细 JSON 展开作为调试界面需求。
2. 用浏览器 Performance / React Profiler 区分网络等待、JSON 解析 / 序列化、React 重渲染与布局开销。
3. 保留已存在的分页；闭合区域不挂载大型内容，不提前 stringify 全部详情。
4. 大文本展示分段或窗口化，明确“展示片段”与“下载完整记录”；不能静默丢弃复制内容。
5. 图表、日志和轨迹重组件按可见性订阅；共享轮询不得反复重渲染无变化的画布。
6. 优化后以同一数据和机器对比，不因为拆了组件或加了 memo 就宣称解决卡顿。

建议的验收数据与预算见总览。性能问题应在本阶段解决可复现部分，第五阶段复用这些展示组件，不另建日志系统。

## Implementation Notes

- 顶部“调试”打开正式真实入口，提交按钮为“发送调试”，固定 `execution: live` 并显示费用说明。页面加载、打开面板和切换视图都不触发执行。
- 模拟入口位于“实验设置 → 执行环境 → 开发与演示”，固定 `execution: mock`。真实调试与模拟各自保留输入和本次结果，不通过一个下拉框改变已有输入的费用语义。
- “实验设置 → 数据与采样 → 打开数据集采集”进入独立采集模式；默认调试不再显示用途切换条或 parquet 表单。原采集参数、模拟 / 真实选择、预览与结果均保留。
- `useMasRolloutRun` 下沉到控制台组件。输入问题、请求状态和读取轨迹不会直接更新 MAS 页面或画布；Workflow 保存锁和快照捕获仍使用原 `useMasDraft.executeWithSavedWorkflow`。
- 控制台始终独立显示本次操作状态、时间和可用的 run ID。历史结果有独立身份条与“返回本次结果”；“查看本次结果”会明确退出历史选择，不再仅切到结果页签。
- 模型摘要只显示当前模型、是否具备本地尝试条件及配置入口。依赖、凭据来源、端点探测和能力说明展开后读取展示，不重复渲染同一依赖的两份列表；单题不显示 parquet 提示。
- 错误先按已提供的 stage / code 展示简短说明，完整服务错误通过文本文件下载。不从供应商长文本猜测更具体的错误类型，也不静默修改后端业务状态。
- 日志 / 结果的重内容按可见性挂载，轨迹视图单独拆包；历史对象与输入状态分开比较，修改下一题输入不会重新序列化上一条 Workflow 快照。
- 调试控制台仅保留“任务输入”和“答案与过程”。操作日志页签与逐事件查看器已移除，不再默认展示 Skills、记忆读写、概率、快照范围等技术细节。
- `TrajectoryDetails` 改为 Agent 输入输出概览：按实际执行片段关联 Agent；输入摘取首次模型请求中的任务与上游交接，输出优先展示 Agent 结束输出，否则明确标为最近可见输出。系统提示词、记忆和工具参数不放入概览。
- 每张卡片的输入 / 输出展示最多 800 字符摘要，保留截断说明、简单工具调用次数与定位。重复执行的同一 Agent 分开列出；归属不明确的记录不猜测为某个 Agent。
- 概览沿用预览分页，后续内容由用户点击加载。下载完整 JSON 继续走服务端导出接口，包含整次运行而不只是当前已加载页；本页操作日志下载仅含浏览器已记录的保存和请求生命周期，明确区分来源。
- 共用 JSON / 大文本组件仍可服务其他设置和监控页面，但调试过程不使用它们渲染原始记录。
- 只读详情失败不覆盖执行成功状态；返回数据增加 run ID 一致性检查，避免显示不匹配的轨迹。无鉴权服务、不支持 `/models` 和无工具 Agent 的后端规则不变。
- 没有引入 token streaming、后台队列、取消、断线重放、自动重试或自动评分。所有执行仍由用户明确发起。
- 本轮只进行 TypeScript / Vite 编译，不运行测试套件、真实模型调用或训练。未采集 Performance / React Profiler 基线，不能据此宣称“日志卡顿已经根治”或“已达到性能预算”。

## Acceptance and Delivery Boundary

- 展开调试、切换标签、查看历史、读取详情、下载记录均不提交模型生成请求。
- 点击一次发送最多发出一次前端执行提交；保存失败、连续点击、返回页面不产生额外提交。
- 无 Key 的兼容服务仍按后端规则处理，不能在前端额外硬性禁止；无工具 Agent 保持空工具语义。
- 新任务执行时查看旧失败，页面明确显示两者身份；新任务完成后可直接返回本次结果。
- 不支持 `/models` 不阻止基础调试；没有训练 GPU 不阻止远程 API 调试。
- 至少以一个三 Agent、含工具调用的既有记录验收轨迹关联；执行器逻辑不因 UI 改名变化。
- Mock 用于自动化交互验证，真实模型验证由用户明确触发，不能把 mock 通过当成真实模型兼容证明。

## Risks and Edge Cases

- 移除 Mock 下拉框会改变用户对费用的预期，必须显式发布新入口语义。
- 同步请求期间关闭面板不代表取消服务端执行，保留说明。
- 视图懒加载不能导致历史定位丢失、复制文本不完整或展开焦点跳走。
