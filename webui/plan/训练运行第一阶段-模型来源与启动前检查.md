## Position in the Project

训练模型来源属于 Control 层的运行输入，不属于 Workflow 节点，也不能由浏览器猜测服务器文件。配置仍由 YAML 和模型资源引用表达；启动检查通过只读 API 返回。

当前服务器已经存在：

```text
/root/autodl-tmp/MAS_Science_Infra/LLM/Qwen3-4B/config.json
```

`experiments/arpo_e2e/rl.yaml` 也已指向该目录。当前 UI 显示“绑定读取失败”不是模型丢失，而是资源前端请求的 `/api/model-resources` 和 `/api/experiments/{id}/model-bindings` 尚未在当前集成分支注册。

资源后端实现存在于 `feature/ui` 的 `f7c387b`，但该提交与 `integration/new-webui` 已经分叉。不能整提交直接合并；应按当前分支的数据模型选择性迁移并补回测试。

## Requirements

- 训练模型来源支持资源绑定与旧 `rl.model_path` 两种模式。
- 有资源绑定时使用资源快照；没有绑定时继续使用实验内旧路径。
- 模型资源为空、资源库未初始化或实验尚未迁移，均不得让旧实验无故失去训练能力。
- 本地模型发现只扫描服务端允许的根目录，不接受浏览器提交任意扫描路径。
- 发现模型不等于自动登记、自动绑定或自动启动。
- 启动前检查只读，不保存配置、不停止模型服务、不占用 GPU、不创建训练进程。
- 检查结果区分阻断问题、警告和有效配置摘要。
- 真正启动时必须重新执行同一套服务端检查，不能只信任浏览器缓存。
- API 返回模型路径和命令摘要时不得包含凭据、环境变量秘密或认证 URL。

## Scope

- In：选择性迁移模型资源存储、绑定 API、有效模型解析与 legacy 回退。
- In：允许目录内的本地模型发现、训练模型登记与绑定。
- In：训练 Preflight 服务、类型和新 UI 摘要。
- In：修复当前模型资源 404 导致训练按钮永久禁用的问题。
- Out：创建训练进程、训练停止、运行状态机、日志流和算法真实执行。
- Out：自动下载模型、跨用户资源共享、任意服务器目录浏览和模型文件管理。

## Current State

- `services.start_train()` 直接读取 `rl.model_path` 或 `actor_rollout_ref.model.path`。
- `default_rl()` 默认路径是仓库内 `LLM/Qwen3-4B`，与当前服务器实际路径一致。
- 新前端已包含 `ModelBinding`、`ModelCatalog` 和资源 API 客户端。
- 当前分支缺少 `model_resources.py`、`model_resource_api.py` 及其 `app.py` 路由注册。
- `TrainingSettings` 把绑定读取失败映射为 `binding-unavailable`，导致启动按钮被禁用。
- 当前启动前只检查 GPU ID 范围、算法名和 profile；模型、数据、依赖与进程冲突会在子进程启动后才暴露。

## Proposed Architecture

```text
实验训练设置
  ├─ 已绑定 training resource
  │      → 固定 resource id + revision + model_path
  └─ 未绑定
         → 兼容读取 rl.model_path / actor_rollout_ref.model.path
                         ↓
                 resolve_training_source()
                         ↓
                    train_preflight()
       ┌───────────────┼────────────────┐
       模型/数据       GPU/依赖         Workflow/Sampling
                         ↓
           blocking_issues + warnings + effective_config
```

### 模型来源解析

新增单一入口 `resolve_training_source(experiment_id)`：

```text
绑定存在且有效     → source=resource
没有绑定           → source=legacy
绑定 ID 不存在     → 明确阻断，不回退 legacy
绑定类型不是训练模型 → 明确阻断
```

返回不可变内部对象和脱敏公开摘要。启动与 Preflight 必须调用同一入口，避免页面显示一个路径、实际训练使用另一个路径。

### 本地模型发现

新增只读接口，例如：

```text
GET /api/model-resources/discover-local
```

服务端扫描：

- 仓库根目录下的 `LLM/`。
- `SCIENCE_MODEL_ROOTS` 环境变量声明的额外根目录。

候选目录至少包含 `config.json`。服务端使用 `resolve()` 后检查仍位于允许根目录内，限制遍历深度和返回数量，不跟随逃逸根目录的符号链接。

返回字段：

```text
path
name
architectures
model_type
torch_dtype
registered_resource_id（若已登记）
```

用户点击“登记并绑定”后才创建训练模型资源并保存实验绑定。

### Preflight Contract

新增：

```text
GET /api/rl/preflight?experiment_id=<id>
```

返回：

```json
{
  "ready": false,
  "revision": "opaque-config-revision",
  "effective": {
    "algorithm": "arpo",
    "profile": "fast",
    "model": {"source": "legacy", "model_path": "..."},
    "gpu_ids": [0],
    "group_n": 4,
    "branch_site_count": 1
  },
  "checks": [],
  "blocking_issues": [],
  "warnings": [],
  "launch_preview": []
}
```

检查项包括：

- 模型目录和 `config.json`。
- train/val parquet 文件及基本可读性。
- GPU 数量、选中 ID、profile 与张量并行约束。
- Workflow schema、入口和可训练 Agent。
- Sampling 最终算法、`group_n`、Branch Sites 与 RL 配置映射。
- Python、Agent-Lightning、VERL、Ray、torch、parquet 引擎等启动依赖。
- 当前训练和本地 vLLM 占用情况。

`launch_preview` 仅展示脱敏参数，不包含 API Key 或完整环境。

## UI Layout

训练设置中的“训练模型来源”应展示三种清晰状态：

```text
已绑定资源：本地 Qwen3-4B
旧实验路径：/root/.../LLM/Qwen3-4B
未配置：阻止训练
```

模型资源 API 临时失败时，如果旧实验路径有效，应提示资源能力不可用，但不能禁用 legacy 训练。只有绑定存在但损坏时才阻断，避免静默使用旧路径。

“开始训练”进入 Preflight 页面，而不是立即启动。页面展示模型、数据、GPU、算法和分支策略摘要，并提供指向对应设置项的修复入口。

## Implementation Notes

- 模型资源使用 `artifacts/control/model_resources.sqlite3`，可通过
  `SCIENCE_MODEL_RESOURCES_DB` 覆盖；运行数据不进入 Git。
- `model_resources.py` 以 SQLite 事务保存资源、私有凭据、修订和实验绑定。
  本地模型“登记并绑定”在同一事务中完成，绑定冲突不会留下孤立资源。
- 本地发现默认只扫描仓库 `LLM/`，额外目录由 `SCIENCE_MODEL_ROOTS`
  明确配置；浏览器不能提交任意扫描根目录。
- `resolve_training_source()` 只在存在有效 training binding 时使用资源路径；
  未绑定实验继续使用 `rl.model_path`。损坏绑定不会静默回退。
- `/api/rl/preflight` 统一解析模型、数据、GPU、Workflow、Sampling、依赖和
  活动进程，并生成脱敏启动预览。`start_train()` 会重新执行相同检查。
- 推理资源解析同时补回 `/api/mas/readiness` 与请求级 API Key 传递，避免
  Collect 为某实验修改整个 Control 进程的环境变量。
- 前端只在训练模型设置可见时读取一次本地候选；Preflight 仅在用户点击
  “开始训练”时请求，不增加画布后台轮询或输入期间的全局重渲染。
- 自动验证只运行 Python 编译、无 GPU 契约测试和 WebUI production build。
  服务器中的模型发现、绑定和启动确认由用户手动验收，不自动启动训练。

## Lightweight Validation

本阶段自动验证保持快速，不启动模型或训练：

```bash
python -m compileall science_infra/control
cd webui && npm run build
```

可补充纯本地、无 GPU 的解析测试，覆盖资源优先级、legacy 回退、允许目录和 Preflight 错误分类。真实页面状态、模型登记与绑定由用户在 WebUI 中手动验收。

## Acceptance and Delivery Boundary

- 服务器上的 `LLM/Qwen3-4B` 能被发现并显示。
- `arpo_e2e` 在未绑定资源时仍能识别现有 `rl.model_path`。
- 资源与绑定接口不再返回 404。
- 无效模型路径、缺失数据或 GPU 配置错误显示为具体阻断项。
- 打开和刷新 Preflight 不产生训练进程、不停止 vLLM、不改写 YAML。
- 本阶段完成不代表训练已启动；创建进程与停止语义属于第二阶段。

## Risks and Edge Cases

- 直接合并 `f7c387b` 会带入与当前分支冲突的旧实现，应按模块和契约迁移。
- “资源 API 不可用”与“已绑定资源损坏”语义不同，不能统一回退。
- 只检查目录存在不足以证明模型可训练；至少检查模型配置文件，真实加载留到人工 GPU 验收。
- 扫描任意路径会扩大文件系统暴露面，必须使用服务端允许根目录。
