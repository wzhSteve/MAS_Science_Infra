# Plan

本阶段定位为“Rollout 查看、定位与可用性说明”，依赖 [第二阶段：统一 MAS 执行与单次 Rollout 采集](MAS运行与调试第二阶段-单题Rollout闭环.md)。展示已经在真实执行边界记录的 Agent 片段、模型调用、工具交互和错误，说明哪些信息完整、哪些缺失、哪些快照只能查看而不能恢复。

目标是“查看已记录的执行过程并定位问题”，不是展示虚假的实时流动动画。先完成运行后的轨迹查看，再考虑可靠的实时事件；不以 token streaming、异步队列或中止能力作为本阶段前置条件。

本阶段的实现进度见 Action Items，接口和读取策略见 Implementation Notes。所有展示基于已有记录，不代表已进行真实模型或训练验证。

本阶段属于面向 RL 的统一 Rollout 层的观察界面，不建设与采样数据割裂的调试日志系统。远程 API、自部署模型和训练策略共用轨迹契约；模型来源不同只影响可获得的能力信息，不改变轨迹的核心身份与层级。文件名保留以兼容现有链接。

## Requirements

- 每一份轨迹绑定后端 run ID、输入问题、Workflow 快照和实际模型摘要。
- 默认展示 Rollout 身份、采集状态和答案摘要，按需展开过程；答案优先是阅读布局，不意味着底层只保存答案。
- 区分对话消息、实际工具调用、工具返回、Agent 交接、最终答案和错误。
- 工具“已配置可用”不是“实际调用过”，不得用静态绑定边生成调用记录。
- 事件属于哪个 Agent 必须有可靠来源，缺失时显示未标注，不默认全部归为 hub。
- 工具调用与返回优先依靠真实调用 ID 对应，不能用事件位置或工具名称强行配对。
- 无精确时间或 usage 信息时显示缺失，不用事件数量估算 token、费用或耗时。
- 画布定位不得改变草稿、自动保存或关闭常驻工具箱。
- 保留现有采集日志的实验级语义，不把它混入某次单独的 rollout。
- 奖励和训练信号仍属于采集 / 高级信息，不成为单题答案查看的前置条件。
- 显式区分运行成功、记录完整、可续跑和满足某个训练算法的数据要求，不合成一个“可训练”状态。
- 第二阶段负责新运行数据的准确记录，本阶段只做读取与展示，不从合并消息或文本内容事后补造身份。

## Scope

- In：按执行片段和调用查看轨迹、工具输入输出、上下文来源、错误定位、有限的运行记录列表和再次运行入口。
- In：消费第二阶段的 agent_execution_id、模型调用和工具关联数据，兼容旧轨迹中明确的未标注状态。
- In：读取已保存轨迹、运行后定位和原始结果下载。
- In：记录完整性、模型能力缺失、快照覆盖范围与后续采样使用限制的说明。
- Out：token 级流式输出、实时节点状态、复杂运行对比、分支恢复、训练数据管理、自动奖励评测。
- Out：完整任务队列、取消运行、自动重试、任意历史 Workflow 覆盖当前草稿。

## Current State

以下是三个阶段实施前的基线。第二阶段完成后，新轨迹的身份、调用记录与快照范围应已由统一执行器生成；不能把下面的数据缺陷留到本阶段再靠 UI 推断修复。

- `Trajectory` 已包含 `messages`、`events`、`final_answer`、`final_reward`、Archive 引用与 meta。
- Archive 已记录工具调用、返回、快照等事件。
- 当前 `append_events_from_messages()` 在取得消息后转换事件，部分时间戳是归档时间，不是每次工具真正开始 / 结束时间。
- `ExecutionEvent.agent_id` 默认是 hub，部分记录点尚未显式传递真实执行 Agent。
- 工具调用事件含调用 ID，但工具返回事件目前未完整保留对应 ID。
- 部分事件内容已截断；不能把截断片段显示成完整工具输出。
- 多 Agent 的 messages 会合并，不能仅凭合并后的数组推断每一条消息属于哪个 Agent。
- 现有 SSE 总线主要是实验级事件，没有可靠的单次运行关联。
- 第二阶段提供统一轨迹、运行摘要和基本轨迹读取，本阶段在其上增加友好浏览与列表，不新造一份轨迹。

## Proposed Architecture

```text
第二阶段已保存的运行
  → 按 experiment_id + run_id 读取详情
  → 服务端返回结构化轨迹与来源说明
  → 前端按 Agent 执行片段 / 模型调用 / 工具 / 事件展示
  → 标注记录完整性、模型能力与快照范围
  → 用户点击有可靠实体归属的记录
  → 定位本次运行涉及的画布实体
```

- 继续复用已有 Trajectory / Archive，不新建重复的 tracing 平台。
- 原始轨迹和前端展示模型分开，前端不散落解析底层 payload 的代码。
- 在一个适配模块中统一事件标题、状态、关联 Agent、调用 ID 与截断标记。
- 详情按需获取，不把所有历史轨迹塞进每次实验 bundle。
- 运行摘要、轨迹列表和详情共享 run ID，不用数组索引代替身份。
- 执行片段、模型调用和工具调用使用各自稳定 ID；同一个 Agent 多次执行不能混为一组无法区分的消息。
- 基础记录缺失需要返回第二阶段修复采集源；本阶段只显示缺失事实，不增加展示层猜测规则。

## API Design

在第二阶段命名空间中增量扩展：

| 接口 | 作用 |
| --- | --- |
| `GET /api/mas/rollout-runs?experiment_id=...&cursor=...&limit=...` | 增加分页读取该实验的运行摘要 |
| `GET /api/mas/rollout-runs/{run_id}?experiment_id=...` | 保留第二阶段摘要读取契约 |
| `GET /api/mas/rollout-runs/{run_id}/trajectory?experiment_id=...` | 复用第二阶段轨迹读取，按需增加详细内容分段访问 |
| `GET /api/mas/rollout-runs/{run_id}/export?experiment_id=...` | 下载脱敏后的统一运行记录 |
| `GET /api/mas/rollout-runs/{run_id}/context?experiment_id=...` | 读取本次问题、配置快照与摘要，失败且无轨迹的运行也可查看 |
| `GET /api/mas/rollout-runs/{run_id}/trajectory/events/{event_id}?experiment_id=...` | 按需读取一个完整事件 |
| `GET /api/mas/rollout-runs/{run_id}/trajectory/messages?experiment_id=...&offset=...&limit=20` | 按需读取原始消息分页 |

- ID 与实验归属必须在服务端判断，不接受任意绝对路径作为读取参数。
- 摘要列表使用确定的排序和分页边界，不无限扫描后全部返回。
- 大型工具输出按需展开 / 分页或读取详情，不在首次打开控制台时加载所有内容。
- 运行记录不存在与记录损坏应明确区分。
- 本阶段不提供自动删除历史或无限期保留的承诺；先不加入删除功能，后续单独定义保留策略。
- 下载记录包含输入、执行快照、模型摘要、轨迹与状态，但不包含 API Key、Authorization 或服务端完整环境。
- 上述 Rollout 路径替代早期文档未实现的 debug-runs 提案；不是改变现有 `/api/mas/collect`。

## Trace Fidelity

记录来源与展示必须一一对应。以下是对第二阶段契约的消费要求，而不是本阶段才开始采集的新功能：

- 按实际 `agent_id` 和 `agent_execution_id` 展示工具、消息与错误，区分同一 Agent 的不同执行片段。
- 按第二阶段已保存的模型 call_id、tool_call_id 和结果关联展示，旧记录无法确定时显示未关联。
- 按真实事件序列展示，不使用 UI 排序结果代替因果关系。
- 合并 messages 视图消费已有来源映射，不为了显示重新改变发给模型的原始协议。
- 区分 `occurred_at` 与 `recorded_at`：已有归档时间只标为记录时间，不据此计算真实工具耗时。
- 只在实际调用入口和返回处都能采集到时间时展示调用耗时。
- 若输出已有截断，明确显示“摘要 / 已截断”；原始 messages 有完整内容且有可靠关联时，才提供完整详情。
- 不要求模型生成隐藏思维过程，不把普通 assistant 输出称为内部推理链。
- 老轨迹不做猜测性补全；按已有证据显示未标注 Agent、未知时间或无法配对。

## Rollout Usability

“有一条 rollout”与“能够做任意 RL 训练”不是同一个状态。结果详情提供轻量的“记录与能力”区域：

| 维度 | 展示内容 | 不作出的承诺 |
| --- | --- | --- |
| 执行结果 | 成功、失败、中断及终止原因 | 成功不代表答案正确 |
| 记录完整性 | Agent / 模型 / 工具关联是否完整，哪些内容被裁剪或缺失 | 日志可读不代表原始轨迹完整 |
| 模型信息 | 实际模型来源、版本已知或未知、共享模型的 Agent 范围 | API 模型名不等于可固定的策略版本 |
| 概率与 token | 实际提供的 token IDs、logprob、usage 及其类型 | 缺少 logprobs 时不能做严格熵判断；选中 token 概率不等于完整分布 |
| 评估状态 | 未评估 / 已有 reward 及来源 | 未评估不是 0 分 |
| 快照范围 | 消息、执行游标、记忆、外部工具状态分别是否包含 | 消息快照不等于可恢复整个 MAS |
| 学习适配 | 哪些数据尚需训练适配器生成或核对 | 不用一个通用“可训练”徽标保证所有算法可用 |

- 对新轨迹的 `trace_status=complete`，解释它只满足首期执行记录契约。
- 旧轨迹存在截断或默认 hub 归属时明确标记不完整，不能把未出现的 warning 解释成完整。
- API / 自部署轨迹使用同一详情结构；缺失能力是数据差异，不是另一个轨迹类型。
- 列出快照可用范围和不可续跑原因，但本阶段不新增分支执行按钮。
- 后续 ARPO 等采样器根据它需要的数据自行判断，UI 不根据 `algo` 名字推断能力。

## UI Layout

继续使用底部控制台，结果区域内部按需展开，不新开一个覆盖整张画布的调试应用。

```text
运行配置 | 结果 | 日志

Rollout · 真实推理 · 已完成 · 模型摘要       最近运行 ▾
记录：完整 / 部分缺失        模型来源：远程 API
输入问题摘要

最终答案
┌──────────────────────────────────────────────┐
│ 回答正文                                     │
└──────────────────────────────────────────────┘

过程：执行片段 | 对话 | 工具调用 | 事件
  Agent 第一次执行
    模型调用 → 实际上下文 / 输出
    工具调用 → 参数 / 返回
  Agent 交接与后续片段
  最终答案 / 错误 / 终止原因

记录与能力：上下文完整性 / token 与概率 / 快照范围
```

### Answer First

- 最终答案始终位于结果主区域，运行失败时用错误卡片替代“空答案成功”。
- 显示模拟 / 真实标记、模型、总运行耗时及实际工具调用数。
- 新运行开始后保留上次结果，但清楚标记不是本次结果。
- 没有参考答案和评估器时不显示奖励分数。
- 如果查看现有 Collect 产物，复用其中的 Trajectory；奖励 / 训练信号放入默认折叠的高级详情并标明来源，不将它们误认为当前单次运行自动计算的结果。

### Agent Execution and Context

- 先显示执行片段，再展开该片段的模型、Skill 与工具调用，避免多个 Agent 的消息混在同一个时间轴里。
- 可查看该次实际使用的 Prompt、上游交接内容、工具集合和 Skill 执行结果。
- 模型请求详情显示实际发出的上下文；若发生裁剪，区分原始来源与最终请求，不用最新画布配置代替。
- 内存记录显示 scope、owner 和明确读写内容 / 引用，不将 MemoryStore 摘要当成模型实际已经看过的消息。
- 多 Agent 共享模型时展示相同模型绑定，但保留独立的 Agent 片段身份。

### Conversation

- 按顺序展示用户输入、可公开的 assistant 内容和工具消息。
- system prompt 默认折叠，展示第二阶段记录的本次实际有效值，而不是只展示声明配置或当前节点刚编辑后的值。
- 长文本可展开，复制操作只复制用户所选择的内容。
- 文本默认安全渲染；若复用 Markdown 渲染器，沿用项目安全边界，不能直接注入任意 HTML。
- 消息是否属于某个 Agent 取决于明确记录，不依靠内容语义自动猜测。

### Tool Calls

每条工具记录包含：

- 工具名称、调用者 Agent（有记录时）、真实调用 ID。
- 输入参数和返回内容，分别可展开。
- 成功 / 失败 / 返回未记录等状态。
- 有可靠时间证据时的耗时。
- 内容截断标记与可用的完整记录入口。
- 归属的模型调用与 Agent 执行片段，不把工具返回计入模型生成 token 或待训练动作。

禁止将“绑定了 3 个工具”显示为“调用了 3 个工具”。工具列表为空时展示“本次没有记录到工具调用”，不能单靠缺失事件断言模型绝未请求过工具。

### Events and Errors

- 事件列表呈现实际记录，保留消息、工具、反馈、内存、快照和错误等类别。
- 常见视图只突出执行有关事件，内存 / 快照细节可折叠。
- 工具局部错误与整体运行失败分开显示。
- 错误卡片包含阶段、原因、相关实体和下一步建议；不能把鉴权失败提示成“检查 GPU”。
- 未知错误保留脱敏详情，不自动改成 mock，也不自动重试。

## Canvas Linking

- 对有可靠 agent_id 的记录提供“定位 Agent”。
- 定位某个 Agent 仍保留选中的执行片段，不能把该节点在整条轨迹里的多次运行混成一次。
- 对有可靠调用者和工具身份的记录，可定位该 Agent 与 Tool 的绑定边；无精确边标识时不猜测协作边。
- 同一对 Agent 可能有多个关系，不能只根据 from / to 推断实际执行了其中哪条。
- 画布高亮表示“选中的历史记录涉及此对象”，不是“该节点此刻正在执行”。
- 运行后草稿发生变化时，明确提示“当前画布与运行快照不同”。
- 当前画布已不存在相应实体时，不自动创建节点；显示记录中的名称与快照说明。
- 定位不修改草稿、不改变保存状态、不关闭工具箱、不覆盖节点配置。
- 暂不提供一键将历史 Workflow 覆盖当前草稿；若以后增加，必须独立确认。

## Run Records and Retry

- 最近运行列表按当前实验隔离，展示时间、输入摘要、模型、模拟 / 真实和结果状态。
- 首期使用控制台内下拉列表，不新建完整历史管理页面。
- 从历史记录选择结果不会修改当前模型配置或 Workflow。
- “使用此问题”只填充问题，不立即调用模型。
- 再次运行默认使用当前保存流程与当前模型配置，界面明确它是新运行，不是严格复现实验。
- 不自动带回历史密钥，历史产物也不能包含可复用密钥。
- 若未来支持“完全按历史快照重跑”，应单独定义模型和凭据来源；本阶段不暗示已有此能力。

## Progress Boundary

本阶段优先完成运行后的轨迹展示。第二阶段的调用边界记录不依赖这里是否接入实时 UI。

- 第二阶段同步请求期间仍可以显示本页“执行中”，但没有实时证据时不展示节点状态。
- 现有实验级 `collect_progress` 继续标为实验事件，不与某次 rollout 自动关联。
- 若需要额外发布调试生命周期事件，必须包含 `experiment_id`、`run_id` 和明确事件序列；请求结果与持久化记录仍是最终依据。
- 完成后一次性回放的记录不能显示成真实时间流式过程。
- 不把已有 Archive.append 自动等同于实时推送；后台线程投递事件与断线补发是另外的接线工作。
- token 流、中止、可靠后台执行和重连恢复继续列为后续扩展，避免本阶段扩大成任务平台重构。

## Implementation Notes

- 运行列表按 `(started_at, run_id)` 倒序游标分页，默认每页 15 条。每个实验在 rollout-runs 目录使用轻量 SQLite 索引；首次迁移只扫描已有运行摘要，以后写入摘要时同步索引，不反复扫描完整历史轨迹。
- 损坏或缺失的历史记录在列表中保留明确错误项，不静默跳过，也不提供自动删除。
- 原有完整轨迹接口保持兼容。UI 使用 `view=preview&offset=0&limit=100` 获取首批事件与截断预览，单个事件展开后读取完整详情；对话按 20 条一页读取。
- Preview 对字符串、数组和嵌套内容限量，并标记 `preview_truncated`、`metadata_truncated` 等；完整保存文件不因此改变。后端按文件版本缓存少量轨迹，避免同一记录每次展开都重复解析文件。
- 当前存储仍是每次运行的单一轨迹 JSON；第一次读取一个运行仍需解析该文件。此次限制的是初始网络传输、页面渲染与重复读取，不声称已经实现流式存储。
- 工具配对只使用执行片段、模型调用和工具调用的联合身份；缺少 ID、重复 ID、孤立返回和未加载返回均明确说明。
- 归属依据来自明确的 Agent 进入上下文或 v2 的运行关联字段；旧记录的默认 hub 不自动认定为真实调用者。
- “使用此问题”只填入当前任务输入，不恢复历史模型、Workflow 或密钥。历史浏览不替换正在运行的本页请求状态。
- 画布定位仅选择存在的 Agent 或唯一的 tool_call 绑定，不创建节点或提交草稿；文字明确这是历史记录定位，不是实时执行。
- 导出是用户明确下载本次记录；未完成或没有轨迹的运行仍可导出摘要和上下文，不发起模型调用。

## Delivery Boundary

本阶段交付“能看懂一次 rollout、定位有证据的问题、判断记录和快照的已知使用范围”。它是统一执行层的观察入口，不承诺完整观测平台、任意 RL 算法兼容或全系统状态恢复。

实施时保证前端类型与构建、后端记录模型与模块导入正常，不增加专门的测试章节或大规模测试任务。真实 API 和付费工具仍由用户明确操作；没有真实证据时不宣称特定节点、工具或协作关系已经执行。

## Risks and Edge Cases

- 当前事件默认 hub 或缺失调用 ID 的旧数据，不能通过 UI 猜测修复。
- 顺序归档生成的时间戳不能直接画成耗时分析图。
- 多 Agent 聚合消息缺少可靠归属时，应提供对话视图而不是虚构节点级追踪。
- API 请求失败前可能已产生模型费用，重试是新的外部操作。
- 大型工具输出和长消息要限制首次加载量，不能一次渲染全部历史记录。
- 运行记录可能包含用户问题、Prompt 和工具返回，导出前明确其内容范围，不混入服务端凭据。
