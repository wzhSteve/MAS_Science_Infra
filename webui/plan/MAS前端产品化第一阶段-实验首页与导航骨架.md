# Plan

本阶段交付新的“实验首页 → 实验工作区”路径，保留现有编辑器和执行入口。用户首先看到自己管理的实验，而不是六个技术模块。

本文件包含实施方案与第一阶段落地说明，已实施范围见 Action Items 和 Implementation Notes。总约束见 [实施总览](MAS前端产品化实施总览.md)，产品依据为 [MAS 实验平台产品形态](MAS实验平台产品形态.md)。

## Position in the Project

这是六阶段的第一阶段。必须把导航与编辑会话的生命周期一起处理，不能仅将六个面板换成会导致草稿丢失的路由。

本阶段不要求模型、数据、GPU 或训练服务就绪。首页和画布编辑应可独立访问。

## Requirements

- 首页突出“新建实验”；实验名称是主要信息，实验 ID 保留为辅助信息。
- 打开实验与查看已有运行是两个明确动作，不混用卡片点击区域。
- 没有可靠运行信息时显示未获取或尚无对应记录，不显示模拟状态。
- 浏览器后退、前进、直接打开实验地址与刷新后的定位有明确行为。
- 同一实验临时离开画布后返回，保留 Workflow 草稿、画布位置、选中项、工具箱状态和调试输入。
- 切换实验必须隔离状态；离开有未保存内容的实验先提示，不让旧请求覆盖新实验。
- 沿用已有按钮、卡片、字体、色彩与间距，不在本阶段改造设计语言。

## Scope

- In：实验首页、实验创建入口、工作区导航外壳、地址模型、实验编辑会话容器、错误边界。
- In：旧六面板的过渡访问入口，保证迁移期间功能仍可找到。
- Out：重新实现画布、共享资源注册表、训练执行、完整运行中心、实验复制后端。
- Out：给首页伪造最近修改时间、训练状态或持久化缩略图。

## Current State

以下为第一阶段实施前的基线，落地变化见 Implementation Notes。

- `app\App.tsx` 用 React state 保存 `tab` 和 `expId`，默认打开 `demo` 的 MAS。
- `app\navigation.ts` 定义 Experiment、LLM、MAS、RL、Harness、Monitor 六个平级入口。
- `WorkspacePanels.tsx` 使用 `hidden` 保留面板挂载，同一实验内切换页面不会自动销毁 MAS。
- `Workspace key={expId}` 与 `MASWorkspace` 的实验 key 会在切换实验时重建状态；当前不是多实验草稿仓库。
- `ExperimentPanel.tsx` 已有实验列表、名称 / seed 保存、按 ID 创建和切换；不等于已有首页卡片查询、复制或模板创建事务。
- `useGraphEditor` 在实例内保留节点位置，不能假设卸载后可从 Workflow 完整恢复视口与选择。

## Proposed Architecture

```text
AppShell
  ├─ ExperimentHome
  └─ ExperimentSession（按 experimentId 标识）
       ├─ 工作区页面
       ├─ 设置 / 资源返回位置
       └─ 运行查看入口

导航状态 ≠ 服务端配置 ≠ 本地编辑草稿 ≠ 本次运行
```

- 建议第一版采用 hash 地址，避免为 Vite 与后端静态服务同时增加 history fallback；这是拟新增地址契约，不是当前地址。
- 地址示例：`#/experiments`、`#/experiments/demo/workspace`；运行与资源地址由总览统一定义。
- 导航解析集中在 `app`，页面不拼接任意 URL；未知地址显示可恢复的未找到页面。
- 先把现有 MAS 编辑会话提升到稳定容器，复用其 hook，不创建两套编辑器。设置和运行视图只订阅需要的数据。
- 纯视图状态单独管理，不为记住缩放、折叠和选中项重写 `workflow.yaml`。
- 浏览器刷新先恢复地址，再读取服务端已保存内容；未保存业务草稿暂只保证当前会话内保留，并提供离开 / 刷新提示，不宣称持久化恢复。
- API Key 输入不得进入 URL、localStorage、首页缓存或通用草稿快照；离开未提交凭据表单的处理留到第二阶段统一。

## API and Data Boundary

| 需要的信息 | 可复用来源与处理 |
| --- | --- |
| 实验列表 | 复用现有 list API；当前首先获得 ID，不假定已有完整卡片字段 |
| 名称、结构摘要 | 读取必要的实验摘要；暂缺摘要接口时仅对当前页限量读取 bundle、缓存结果，不扫描全部实验 |
| 创建 | 复用现有 create API；名称和 ID 分开呈现，校验沿用后端 |
| 模板 | 只展示实际可读取并可保存的模板；多步骤创建必须显示失败阶段，失败不能跳转并宣称完整创建 |
| 最近训练 / 评估与修改时间 | 需要可靠服务端字段；缺失时不拿浏览器访问时间、最新调试时间代替 |
| 复制 | 属于能力门禁；在隔离配置、凭据、历史语义明确前不开放可点击的复制按钮 |

不在浏览器中复制整个实验 bundle 作为“复制实验”：它可能含引用、运行摘要和不应继承的来源信息。

## UI Layout

```text
实验                         资源入口                  [新建实验]
搜索实验

[实验名称 / 说明]       [实验名称 / 说明]
Agent 数量             结构摘要未获取
设计信息 / 运行信息分开
[打开工作区]           [打开工作区]
```

- 没有实验时显示“创建第一个实验”，不是要求填写模型连接。
- 搜索仅覆盖已加载数据时明确范围，不把前端分页过滤冒充全量搜索。
- 新首页不挂载所有实验的 React Flow 缩略图；先用 Agent 数量或轻量静态结构。
- 首页不保留固定全局侧栏；打开实验后画布占据工作区主体，左侧只保留画布自身的节点工具箱。
- 迁移期间从工作区顶部“更多功能”访问原配置与监控页面；不得出现两个同样突出的导航系统。完整设置面板重组仍留给第二阶段。

## State and Navigation

| 场景 | 约定 |
| --- | --- |
| 同实验查看记录再返回 | 恢复同一编辑会话，不从历史快照初始化当前草稿 |
| 同实验去模型配置再返回 | 保留 MAS 草稿；有效模型更新仍走现有配置版本同步 |
| 切到另一实验 | 未保存时选择保存后离开、放弃后离开或取消；保存失败留在原处 |
| 请求中切换实验 | 取消只读请求；写入 / 执行不因卸载被自动重试，返回值按实验身份归属 |
| 首页列表局部加载失败 | 保留其他卡片与新建入口，失败卡片可重试 |
| 后端离线 | 显示服务连接故障，不将所有实验标为设计无效或模型异常 |

若第一版只保留当前实验编辑会话，必须通过离开确认限定边界；不能承诺任意数量实验的未保存草稿永久保留。

## Implementation Notes

- 默认地址为 `#/experiments`；工作区为 `#/experiments/<id>/workspace`，兼容页面为 `#/experiments/<id>/panels/<panel>`。`#mas`、`#llm` 等简短技术入口映射到 demo 对应面板，未知地址提供恢复导航。
- 首页只有紧凑品牌栏、实验列表与创建入口，不放置固定侧边栏。工作区使用全宽画布，原功能保留在顶部“更多功能”菜单中；切换原功能页后可一键返回画布。
- 首页和导航新增 CSS 由 `main.tsx` 直接导入，确保开发服务器将其作为独立样式模块加载。本次已定位并修正开发模式未返回新增聚合样式的问题，不能只用生产编译成功代替样式实际生效。
- 首页按实验 ID 搜索，每页六项，摘要最多三个并发请求，仅缓存最多 24 项轻量结构摘要，不缓存完整 bundle 或密钥，不渲染 React Flow 缩略图。再次回到首页刷新列表与当前页摘要。
- 创建只使用已有默认 Workflow 创建能力，独立填写名称和 ID，seed 保持 42；不提供虚假的空白 / 模板事务或复制功能。提交前重新检查 ID 是否存在，失败提示核实结果，不自动重试。
- 现有 bundle 读取会初始化不存在的实验，因此工作区深链接先通过列表确认 ID，再读取 bundle。没有新增或修改后端接口；并发删除 / 创建的原有服务端语义不在本阶段重写。
- 页面只保留一个实验编辑会话。同实验去首页或其他面板后返回，保留已访问面板的实例；切换实验才在明确处理未保存内容后卸载旧会话。
- 工作区内容代码分块加载，未访问的兼容面板不初始化。离开工作区暂停实验轮询和事件订阅，返回后重新读取状态；这不取消服务端任务，也不承诺补齐离开期间未接收的实验级事件。
- 未保存登记只发布 dirty / busy 等摘要，保存函数和真实表单数据留在原组件。仅离开确认弹窗订阅登记变化，输入不会通过全局 Context 广播给画布。
- Workflow、模型、元数据、RL 完整配置 / 简参、Harness、GPU 保存及执行中的操作均接入保护。两份 RL 草稿同时 dirty 时不自动依次覆盖保存，要求先在对应面板明确处理。
- 调试和采集输入属于临时内容，没有独立保存接口；确认框明确说明“保存配置后切换”不会持久化这些输入。浏览器刷新 / 关闭使用原生离开提示，不承诺未保存内容跨刷新恢复。
- 跨实验处理支持保存后切换、放弃后切换、取消；保存失败不切换。浏览器历史导航取消时恢复原地址，避免地址与所显示实验不一致。
- 首页不显示无法确认的修改时间、最近训练 / 评估状态；仍通过工作区原入口查看真实运行。资源管理、统一运行中心与训练启动新流程留给后续阶段。
- 保持原视觉 tokens 与功能契约。初次实施按要求只进行 TypeScript / Vite 编译；收到样式问题反馈后补充浏览器检查，确认首页卡片布局与全宽画布实际生效。未运行测试套件或模型 / 训练验证，完整交互验收仍由用户手动完成。

## Acceptance and Delivery Boundary

- 新建并打开一个实验，不配置 API 或 GPU 也可以编辑。
- 修改 Prompt、拖动节点、缩放画布、输入问题；访问首页 / 同实验页面后返回，按已声明的会话边界保留内容。
- 未保存时切换实验，三个离开选项与失败分支均可操作；新实验不显示旧实验结果。
- 深链接只触发读取，不创建实验、保存配置或执行任务。
- 首页列表加载失败不导致全页崩溃；重新连接后可恢复。
- 使用既有 TypeScript / Vite 与 Vitest 配置补充受影响路径的回归，不额外设置纯测试阶段。

交付是“可使用的新首页和工作区导航”，不是实验复制、完整首页聚合接口或持久化跨标签页草稿能力。

## Risks and Edge Cases

- 将 `hidden` 换成条件挂载容易丢失已有草稿，必须先确定状态所有权。
- 原接口字段不足时，应降低首页信息密度，不能通过无限量 bundle 请求补齐。
- 旧入口和新入口同时修改同一实验时必须共享状态或明确冲突，不能各维护一份可覆盖保存的草稿。
