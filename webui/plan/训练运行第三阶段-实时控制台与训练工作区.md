# Plan

本阶段先收口配置入口，再将现有底部控制台重构为**以任务为入口、以当前执行输出为主体的运行面板**。训练启动后主要看日志和必要的运行控制，不将架构模块逐一翻译成侧栏菜单。

采用画布底部可调高、可最大化的同一面板，不再默认建设一个与真实调试平行且重复的训练应用。左侧固定两个任务入口：**训练日志、真实调试**。不提供独立数据集采集或批量试跑功能；训练内部采样仍由训练流程执行。启动检查是训练前的一次确认流程；指标与 Rollout Tree 属于分析；历史和配置快照是当前任务的辅助操作，不是控制台一级导航。

依赖 [第二阶段：运行快照与安全启停](训练运行第二阶段-运行快照与安全启停.md) 的运行身份和生命周期接口；使用前必须核对实际接口能力，不能因文档勾选完成就假定日志、快照查询或重启恢复已经完整。运行详情的长期边界参考 [MAS 前端产品化第五阶段](MAS前端产品化第五阶段-运行记录与详情中心.md)。

实施状态：已在本地接入下述配置收口、底部双入口面板与训练增量日志；沿用 `RunConsole` 外壳和现有启动确认弹层，没有为了目录结构再包装一套工作区。独立采集入口、表单、结果展示及其前端状态已移除；后端 Collector、Collect API/CLI、训练采样和资源管理的数据预览保留。未新增测试代码，UI 交互、服务器训练与停止行为仍由用户手动验收；未提交、推送或部署。

## Position in the Project

`docs/NEW_FRAMEWORK_DESIGN.md` 约束数据来源、执行链路与领域合同，不规定用户界面的菜单结构。用户的工作顺序是：

```text
设计与配置 → 单题调试 → 检查并启动训练 → 看日志与控制运行 → 分析结果
```

据此划分三个区域：

| 区域 | 用户要回答的问题 | 承载内容 |
| --- | --- | --- |
| 画布与实验设置 | 我准备怎样运行？ | Workflow、模型用途、数据、采样、优化与执行资源 |
| 底部运行面板 | 我刚刚执行了什么，现在怎样了？ | 训练 stdout、单题调试输出、所属任务的操作 |
| 分析与记录页面 | 这次效果如何，为什么，与之前有何不同？ | Reward 曲线、轨迹/树分析、诊断、跨运行比较与完整历史 |

Control 仍负责训练，运行面板不实现算法、不模拟终端、不解析文字日志推断 Reward：

```text
训练进程 → stdout.log / status.json → run 日志与状态接口 → 训练日志视图
单题调试 → 现有 Rollout 接口与记录                          → 真实调试视图
领域指标 / RolloutTree / Harness → 各自分析入口（不塞进日志侧栏）
```

统一的是容器、任务选择和操作规律，不强行把训练与单题调试的后端协议改造成一种运行模型。实验级 `/api/events` 保留轻量通知，训练 stdout 单独传输。独立 Collect 不是训练前置步骤，不再作为 WebUI 功能展示。

## Requirements

- 每个配置概念只有一个权威编辑位置；其它位置允许只读摘要和“去修改”，不再放一套可编辑表单。
- 区分真实重复、不同用途以及显式局部覆盖；不能以“去重”为由删除推理/训练模型区分或 Branch Site 覆盖能力。
- 画布、设置抽屉、底部运行面板各司其职：设置不承载日志，控制台不再次配置算法、模型和 GPU。
- 训练成功创建后按返回的 run ID 打开“训练日志”，右侧主体为 stdout/stderr 合并输出。
- 左侧仅切换任务类别，不混入“配置快照”“运行历史”“启动检查”等不同粒度的功能。
- 真实调试保留任务输入、答案与过程、定位画布的能力；移除独立采集的参数、执行和结果展示。
- 面板关闭、收起、最大化、切换任务都不代表停止运行；停止训练必须显式操作并核对 run。
- 运行状态、日志连接状态、当前查看的历史记录分开表达。
- 日志增量读取、断线续传、有界缓存，不让日志更新使画布和配置表单重绘。
- 不预置没有数据来源的指标卡，不把 Collect Reward 或实验级 AGL 数据冒充当前训练指标。
- 本阶段仅调整交互与数据接线；不改变六算法、Sampling 和 Branch Sites 的底层语义。

## Proposed Architecture

### Run Event Stream

训练日志接口按实验与 run 校验身份，沿用 T2 的训练命名空间：

```text
GET /api/rl/runs/<run_id>/events?experiment_id=<id>&offset=<byte-offset>
```

T3 只实现实际需要的 `state`、`stdout`、`heartbeat`，不要求先完成 metric/artifact/domain 通用事件平台：

```json
{
  "run_id": "abc123",
  "experiment_id": "arpo_e2e",
  "type": "stdout",
  "data": {"offset": 1024, "next_offset": 1187, "text": "..."}
}
```

- stdout 的游标是原文件字节位置；UTF-8 跨块字符、非 UTF-8 字节与终端控制字符有明确解码规则。
- state 读取持久化状态，不拿“日志没更新”推断训练失败；心跳不驱动内容重绘。
- 断线从已接收 `next_offset` 续读；去重也按 offset，不按日志文本内容。
- 文件截断/更换时显式返回重置原因；run 结束后排空剩余日志，再关闭实时连接。
- 初次打开大文件读取末尾窗口并标记“前面还有日志”，不从 0 自动灌满浏览器。
- 结构化树事件即使出现在原始 stdout，也不据此在日志侧栏创建树视图；原始下载不删改。

### History Fallback

```text
GET /api/rl/runs/<run_id>/log?experiment_id=<id>&offset=<offset>&limit=<bytes>
GET /api/rl/runs/<run_id>/log/download?experiment_id=<id>
GET /api/rl/runs/<run_id>/snapshot?experiment_id=<id>
```

上述接口是待实现合同，不宣称 T2 已提供。快照只返回登记的有效配置和经过脱敏的启动信息，不接受客户端文件路径。

SSE 中断时提示“重连中”；连续失败后使用同一游标低频增量补读，恢复 SSE 后关闭降级轮询。历史 run 不保持无意义的实时连接。旧 `/api/runs/{id}?tail=160` 继续兼容旧客户端，新的训练面板不再反复下载相同尾部。

最近运行选择器复用 T2 列表，界面只显示当前实验训练；如目录量大，需要服务端分页，不能只截断前端列表却每次扫描读取全部历史。完整跨类型历史中心不在本阶段扩建。

### Training Workspace

保留本节名称，但具体实施改为**工作区内的统一运行面板**，不另起全屏训练产品。

```text
┌────────────────── MAS 画布 / 实验设置 ────────────────────┐
│                                              [开始训练] │
├─ 运行面板 ───────────────────────────── [最大化] [收起] ─┤
│ 训练日志 ● │ ARPO · 运行中 · run abc · GPU 0   [停止训练] │
│ 真实调试   │ [当前/最近运行 ▾]     [本次配置] [更多 ▾]    │
│            │ [搜索当前窗口] [跟随末尾] [复制] [下载日志]  │
│            │                                              │
│            │               stdout / stderr                │
│            │                                              │
└────────────┴──────────────────────────────────────────────┘
```

侧栏的选择依据是“我要执行/观察哪类任务”，不是“后端有什么模块”：

| 左侧入口 | 右侧主体 | 本任务操作 | 不放什么 |
| --- | --- | --- | --- |
| 训练日志 | 指定 run 的原始日志；状态与失败原因固定在顶部 | 查找、跟随、复制、下载、停止当前 run | 算法/模型表单、曲线面板、树浏览 |
| 真实调试 | 现有任务输入与答案/执行过程；结果可定位画布 | 输入问题、执行、查看过程、已有调试历史入口 | 训练模型权重、训练 stop、训练 Reward |

具体取舍：

- **启动检查**：点击“开始训练”后的临时确认视图，不占侧栏；未运行时训练日志显示空态和“配置训练/检查并启动”入口。进行中点击“查看训练”直接定位 run，不重复做 Preflight。
- **指标**：不设侧栏项，不在日志上方放一排 Reward/Loss 空卡片。控制台只显示运行事实：状态、耗时、算法、GPU、run ID；step/总步数仅在存在可证明属于该 run 的结构化数据后再添加。曲线去现有 Monitor/AGL 入口，明确数据范围。
- **Rollout Tree**：不设侧栏项；属于分支路径与 credit 解释，应在轨迹/分析页面查看。有可靠 run/tree 身份且已有页面才提供上下文跳转，否则不放空链接。
- **运行历史**：训练页头“当前/最近运行”选择器；真实调试沿用自己的记录入口。选择历史只切换查看对象，不改变活动训练。
- **配置快照**：页头“本次配置”打开只读弹层，展示来源、有效配置、启动参数与下载；不新建可编辑表单。不把实验当前草稿当成本次快照。
- **Mock**：保留“开发与演示”入口及醒目标识，复用调试布局；不做第三个常驻侧栏，不把模拟结果混进真实调试记录。

面板默认停靠底部，保留调整高度并增加最大化/恢复。最大化使用同一实例，不另开一套轮询与缓存。窄屏把左侧入口折成紧凑选择器，不挤占日志宽度。

深链接用于恢复“我正在看哪一次运行”，而非强制跳出画布：

```text
#/experiments/<id>/workspace?console=training&run=<run_id>
```

扩展现有 route parse/serialize 并保留设置/资源选择参数。刷新从 URL 恢复指定 run；无 run 参数时只在初始选择时选活动或最近一次，之后不可自动替换用户选中的历史记录。不新增原计划中的独立 `/training` 页面；已有外部链接如需兼容，可解析后映射到同一面板。

### Console Interaction

**训练启动是一条流程，不是多套按钮分别保存不同文件。**

1. 点击“开始训练”只打开准备流程，不立刻产生进程。
2. 若 Workflow/Sampling、RL、模型绑定仍有草稿，列出未保存项，提供“保存这些修改并检查”或返回编辑；不静默丢弃，也不默认使用旧值。
3. 复用现有草稿保存注册机制，依次完成明确选择的保存并重新读取 bundle。跨文件保存不是事务：部分成功必须如实报告，任何失败或保存期间新增编辑都不能继续启动。
4. 保存完成后重新获取 Preflight。确认页只展示有效模型、算法及来源、数据、GPU、主要采样值和阻塞原因；错误旁提供到唯一配置位置的跳转。
5. 用户确认后用 T2 的 request ID 与 revision 提交。确认弹层替换现有简易训练确认，不叠加第二套确认流程。
6. 成功时选中准确 run、打开训练日志；网络结果未知时提供复查/重试原请求，不能由于新的 Preflight 看见活动训练就永久挡住原请求恢复。

日志和控制规则：

- 用户向上滚动暂停**跟随**，不是暂停训练；继续接收采用有界缓存，有淘汰时显示缺口提示。
- 搜索明确标为“搜索当前已加载日志”，显示命中与跳转；全文件全文索引不在本阶段。
- 复制选中文字或当前窗口；下载取完整服务端日志。首版不做“清空”，避免误以为删除运行证据。
- 不依据任意字符串 `error` 推断失败，不提供不可靠的错误行分类。真正失败阶段/退出码来自状态，原始日志保留上下文。
- 终态标明成功/失败/已取消；`interrupted` 表示 Control 无法继续确认托管状态，不可写成“进程已停止”。
- 停止按钮只作用于当前查看且可控的活动 run，确认展示实验/run；`stopping` 时禁用重复提交。查看历史不显示针对其它 run 的停止按钮。
- 收起、关闭视图、切换真实调试不停止训练。侧栏圆点及全局入口提示后台仍有活动任务。
- 切换实验清理旧连接与异步响应；切回时按服务端身份恢复，不用上一实验的 ref 或 request ID。

### Navigation Convergence

先调整配置归属，再接运行面板；不能只搬日志而保留所有重复表单：

| 配置概念 | 唯一编辑位置 | 其它位置与兼容规则 |
| --- | --- | --- |
| 默认推理连接（API/本地服务） | 模型绑定 → 默认推理模型 | 调试只显示来源并跳转；不是训练权重 |
| training resource / legacy model_path | 模型绑定 → 训练模型来源 | 训练方案只读摘要；环境页移除绑定编辑器；未绑定时可明确编辑 legacy 路径，损坏绑定不伪装成未绑定 |
| Sampling mode、group_n、全局分支参数 | 数据与采样 → 采样策略 | 训练方案/Preflight 显示最终算法和来源，不放第二个禁用下拉框 |
| Branch Sites、Gate、局部 beam/reward | 数据与采样 → 分支位置 | 全局默认与单点覆盖不是重复；显示“继承全局/自定义”，支持清除覆盖恢复继承 |
| 学习率、训练轮次、步数、PPO/KL 等 | 训练方案 → 基础字段 + 折叠高级字段 | 高级区不再重复基础字段，也不包含 Data/Rollout 资源组 |
| train/val 文件、长度和截断 | 数据与采样 → 训练数据 | 训练高级区移除；资源管理保留数据预览，不提供独立采集输入表单 |
| Training batch、PPO batch/micro-batch | 训练方案 → 批次与优化 | 按优化语义归属，不机械沿用 Hydra 的 Data 分组；分清题目数、每题候选数和优化 batch |
| GPU IDs | 顶部 GPU 控件 | 环境页只读摘要 + 定位；由同一草稿持有，n_gpus 派生不重复编辑 |
| profile、n_runners、Tensor Parallel、显存、Log-prob batch、nnodes | 执行环境 | 训练基础/高级区移除重复编辑；本地无 GPU 时保留服务器目标配置但不可声称可启动 |
| 项目/run 日志标识、评估间隔 | 训练方案 → 训练过程 | 不与实验显示名称或不可变 run ID 混为一谈 |

算法兼容边界：当前后端会将 Sampling mode 映射到 `algorithm.tir_algo`；不能只在 UI 独立选择一个与 Sampling 冲突的算法。存在 Sampling 时唯一入口仍是采样策略。没有 Sampling 的旧实验，在同一位置显示“沿用旧训练算法/候选数”并编辑对应 legacy RL 字段；显式启用 Sampling 后才迁移，不凭组件默认值自动写出 GRPO。IGPO/GIGPO 等已有 legacy 配置必须可见、可保留；APPO 是兼容映射，不标为第七种独立训练算法。六算法能力范围仍由 T4 验收。

参数编辑收口规则：

- 字段描述区分 `group_n`、初始轨迹、分支宽度、题目数、Runner 数与各类 batch；不以相似数字互相代替。
- 数字草稿允许暂时为空；提交时按字段约束校验。可选值区分“未设置/继承”和 0，不统一 `Number('')`。带特殊哨兵值的字段以现有后端合同为准。
- 截断等有限选项用枚举；整数和比例显示单位/范围。不在前端猜测硬件容量或自动改 profile。
- 导入配置中的扩展字段无损保存，未知 mode/gate 不被默认选项覆盖；继承参数显示真实来源，不把占位显示值写回配置。
- “按当前机器推荐”移到执行环境，只推荐资源字段并预览改动，不覆写 Sampling、模型或优化设置。
- 移除基于最近 Collect 的训练建议入口，不再将独立采集产物关联到训练配置；资源推荐仍需显式预览，不得覆写算法。
- 每个设置分组只有一个明确保存入口，文案说明保存 Workflow/Sampling 或训练参数；最终启动再统一协调保存，不需要为了此阶段重写整个配置存储。

入口归并：

- `WorkflowBar` 是主启动入口，运行中显示“查看训练”；设置内部不再调用 `draft.start`。
- 全局运行入口仅显示状态和“查看”，停止收口到当前 run 头部。当前 App 使用 Banner，非画布页另挂 StatusBar；GlobalActionBar 位于旧 WorkspaceHeader，不能将旧组件存在等同于已挂载。移除实际重复操作，旧入口不再恢复另一条启动链路。
- 删除设置里的“打开数据集采集”和旧全局栏的 Collect 操作，不保留替代入口或批量试跑入口。
- Monitor 去掉重复 `TrainingLog`，保留分析及“查看训练日志”跳转；没有 run 归属的指标明确标作实验级。
- 原 RL/LLM/Harness 旧路由继续导向对应设置，不另挂旧表单；隐藏但保留的组件也不能继续轮询同一份日志。

## Frontend State

当前按实际职责拆分；复用已有容器与弹层，不以新建目录数量作为交付：

```text
features/mas/components/RunConsole.tsx           # 同一容器、双入口侧栏、尺寸和最大化
features/training/components/TrainingConsole.tsx # 当前 run、虚拟化日志、历史选择和快照弹层
features/training/model/useRunLog.ts             # SSE、增量补读、游标和有界窗口
shared/ui/alert-dialog.tsx                       # 复用启动检查确认与配置跳转
app/providers/RuntimeProvider.tsx                # 保存协调、幂等请求与活动摘要
```

分离四类状态：配置草稿、全局活动摘要、当前查看的任务/run、日志显示窗口。日志不存入 `RuntimeProvider` 全局 Context；画布无需订阅 stdout。训练与调试共享外壳，不共享请求锁、结果或 run ID。删除采集专属请求、预览、结果和操作日志状态。

性能实施预算：

- 只为当前可见训练日志建立一个流；隐藏/收起时关闭日志连接，保留 offset，重新展开补读。全局状态用已有轻量通知/低频状态查询，不继续拉 160 行尾部。
- 日志按块缓冲，每 100–200ms 批量通知局部视图；心跳、计时器与日志分别更新，不让整个面板树每行 setState。
- 首版建议窗口最多 10,000 行且不超过 2MiB，单次传输不超过 64KiB；超长行单独处理并标注裁剪，完整文件仍可下载。
- 使用有界分块缓存与虚拟化/窗口化渲染，不每块追加都 `split/join` 全部日志；选区、滚动锚点和多行复制必须仍可用。
- 搜索仅针对当前窗口，输入适度延迟；常量字段分组在组件外定义，字段更新保持未变对象引用，不每次键入深拷贝整份配置。
- 草稿与当前输出保留在实验级状态中；隐藏视图不继续挂昂贵图表和副作用。只在需要跨视图保留的层保存状态，不依赖无限 RetainedPanel。

## Lightweight Validation

按用户要求，不默认运行测试套件、浏览器自动巡检、完整生产构建或 GPU 训练。实现期间仅对改动文件做一次必要的 Python 语法检查及一次前端类型检查；文档调整本身不运行这些命令。

```text
python -m py_compile <本次修改的 Python 文件>
cd webui
npm run typecheck
```

用户手动验收集中在四条路径：配置只改一处；单题调试不丢失原能力且不再出现独立采集入口；启动后看日志并停止指定 run；刷新/重连/查看历史不串 run。长日志可用非 GPU 的临时输出源在需要时检查，不作为每次修改必跑环节。

## Acceptance and Delivery Boundary

- 左侧只出现训练日志、真实调试；不出现独立数据集采集、批量试跑或没有真实内容的模块菜单。
- 推理与训练模型明确分工，同一训练绑定不在两个分组出现；算法/group_n 不出现两个竞争编辑器。
- 高级训练设置不再复制数据和执行环境字段；全局默认与局部覆盖均能解释其来源。
- 开始训练不会只保存 RL 而忽略未保存 Sampling；保存/检查失败不能发起训练。
- 训练创建后主要区域显示该 run 日志，停止指向该 run；查看历史时不会误停活动训练。
- 用户能收起/最大化而不终止进程；真实调试与 Mock 可独立恢复输入/结果。
- 日志断线显示连接问题而非训练失败，终态排空日志，超出窗口仍可下载完整日志。
- 训练指标与树留在合适的分析范围，不伪造 run 归属；独立 Collect 的曲线与结果不再展示。
- 本阶段交付交互收口和日志可用性，不宣称六算法正确、GPU 已验收或服务重启后旧进程一定已停止。

## Risks and Edge Cases

- T2 仍是 T3 的硬前提：幂等恢复、进程组清理、快照真正被运行时消费等若有缺口，应明确记录/修复前置问题，不能靠界面状态掩盖。
- 同时编辑 Workflow 与 RL 时，派生值可能使用旧 bundle。保存协调必须重新取服务端结果，确认显示已保存配置而非 UI 猜测值。
- Linux 服务器收到 Windows 数据路径的实际错误已经出现；按当前执行主机显示路径和修复入口，不把不存在的数据拼到仓库根后宣称可用，不在 UI 猜测远程路径。
- 资源登记和绑定有副作用，进入页面/切换任务不能自动绑定；直接登记前必须处理当前未保存选择。
- 后端 Collector、单题调试和训练对 Sampling 的消费路径未必一致；删除独立采集 UI 不等于删除训练采样，也不在 T3 改写底层算法。
- stdout 可含敏感信息、ANSI、超长行和坏字节；安全按文本渲染，不解析为 HTML。快照查询脱敏，不回显凭据/全量环境变量。
- 日志缓存有界意味着暂停查看时可能被淘汰，必须提示可补读或下载，不能承诺无限保留。
- 无可靠 run ID 的 AGL 指标/树不能绑定到当前训练；分析跳转不得静默落入其它实验或“最新记录”。
