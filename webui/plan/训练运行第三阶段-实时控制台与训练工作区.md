# Plan

本阶段交付独立训练工作区和可重连的实时日志控制台。训练不再被塞进画布右侧设置抽屉；用户启动后直接进入本次 run，持续查看 stdout、状态、指标、Rollout Tree、历史和配置快照。

依赖 [第二阶段：运行快照与安全启停](训练运行第二阶段-运行快照与安全启停.md) 提供稳定 run ID、状态机和定向停止。运行历史的通用身份与详情边界继续参考 [MAS 前端产品化第五阶段](MAS前端产品化第五阶段-运行记录与详情中心.md)。

## Position in the Project

训练工作区是 Control 层的运行视图，不是终端模拟器，也不是新的训练执行器。它只消费已持久化的 run、日志、指标和领域事件：

```text
训练进程
  ├─ stdout/stderr → stdout.log → RunEvent(stdout)
  ├─ 生命周期       → status.json → RunEvent(state)
  ├─ 训练指标       → metrics.jsonl / AGL → RunEvent(metric)
  └─ RolloutTree    → tree event → RunEvent(domain)
                                      ↓
                              WebUI TrainingWorkspace
```

原 `/api/events` 继续承担实验级轻量通知；单个训练的大量日志使用 run 级事件流，避免一个实验事件连接被 stdout 淹没。

## Requirements

- 独立路由承载训练，不依赖画布右侧设置抽屉。
- 点击开始并获得 run ID 后自动进入该 run 的训练控制台。
- 日志增量传输，不每 4 秒重复下载最后 160 行。
- 断线重连从上次 offset 继续，避免重复或漏行。
- 日志显示支持自动滚动、暂停跟随、搜索、复制和下载。
- “清空”只清空浏览器显示，不删除服务端日志。
- 运行状态、日志连接状态和训练结果分别表达。
- 切换历史 run 后日志、指标和快照都按所选 run 读取，不跟随“最新训练”漂移。
- 页面刷新、切换页面或 SSE 重连不创建新训练。
- 完成或失败后仍可读取日志与快照。
- 大日志必须有边界、分页或 offset，不能一次读入浏览器内存。
- Metrics、Rollout Tree 和 Harness 使用各自真实身份；不能按时间接近猜测归属。

## Scope

- In：run 级 SSE、日志游标、历史日志降级读取和下载。
- In：独立训练工作区、左侧导航、运行头部和控制台。
- In：本次 run 的状态、日志、指标入口、Rollout Tree 入口、历史和快照。
- In：移除训练设置抽屉内重复的运行与大日志区域。
- Out：修改指标计算、RolloutTree 合同和 Harness 算法。
- Out：Web 终端输入、任意 shell 命令、远程文件编辑和训练进程 stdin。
- Out：多机日志聚合、集中式日志平台和无限期在线保留。

## Current State

- `useTrainingRun()` 每 4 秒读取运行列表，再读取最新活动或最近训练的最后 160 行。
- `/api/events` 只发送 BUS 生命周期事件，并从日志中提取 Rollout Tree 标记，不发送普通 stdout。
- `LogPanel` 是折叠内容，没有持续跟随、搜索和增量读取。
- 训练状态同时出现在 `TrainingBanner`、`StatusBar`、RL 设置和 Monitor，入口重复且语义不一致。
- 当前“开始训练”打开画布右侧训练设置；日志位于窄侧栏底部，不适合长时间观察。
- Monitor 展示实验级训练指标，但不保证所有数据都绑定到当前选中 run。

## Proposed Architecture

### Run Event Stream

新增：

```text
GET /api/runs/<run_id>/events?offset=<byte-offset>
```

事件统一包装：

```json
{
  "event_id": "monotonic-id",
  "run_id": "abc123",
  "experiment_id": "arpo_e2e",
  "type": "stdout",
  "ts": 0,
  "data": {"offset": 1024, "next_offset": 1187, "text": "..."}
}
```

事件类型：

- `state`：状态、时间、return code、失败阶段。
- `stdout`：新增日志块和字节 offset。
- `metric`：能够明确归属该 run 的 reward/loss/step。
- `artifact`：checkpoint、TensorBoard、Rollout Tree 或其他产物引用。
- `domain`：已有 `RolloutTreeEvent` 等结构化领域事件。
- `heartbeat`：保持连接和检测断线。

日志按 UTF-8 安全边界读取，单事件和单次补传大小有上限。客户端保存 `next_offset`；断线后携带 offset 重连。服务端不依赖内存 BUS 保存完整日志，磁盘日志是恢复来源。

### History Fallback

保留：

```text
GET /api/runs/<run_id>/log?offset=<offset>&limit=<bytes>
GET /api/runs/<run_id>/log/download
```

SSE 不可用或 run 已结束时，用有界读取恢复历史。旧 `GET /api/runs/{run_id}?tail=160` 保留兼容，但新工作区不以它作为主要数据源。

### Training Workspace

新增正式路由：

```text
#/experiments/<id>/training
#/experiments/<id>/training/runs/<run_id>
```

布局：

```text
┌──────────────────────────────────────────────────────────┐
│ ARPO · running · 00:13:42 · GPU 0       [停止] [更多]    │
├──────────────┬───────────────────────────────────────────┤
│ 启动检查     │                                           │
│ 训练控制台 ● │      实时 stdout / stderr                 │
│ 指标         │      自动滚动、搜索、暂停、复制、下载       │
│ Rollout Tree │                                           │
│ 运行历史     │                                           │
│ 配置快照     │                                           │
└──────────────┴───────────────────────────────────────────┘
```

左侧是工作区内导航，不是旧式全局技术模块侧栏。右侧占主要空间：

- 未启动时默认“启动检查”。
- 启动成功后自动进入“训练控制台”。
- 失败时保留日志并突出失败阶段。
- 历史 run 默认只读，不显示可误解为继续运行的启动按钮。
- “配置快照”展示本次有效配置，不绑定到仍在编辑的实验草稿。

### Console Interaction

- 默认跟随末尾；用户向上滚动时自动暂停跟随。
- 明确显示“实时 / 重连中 / 历史”。
- 支持关键词搜索和错误/警告快速定位。
- 复制当前选择、下载完整服务端日志。
- 可隐藏时间戳或结构化系统事件，但不修改原始日志。
- 控制台只读，不提供输入框，避免被误认为服务器 shell。

### Navigation Convergence

- 画布“开始训练”进入训练工作区的启动检查。
- 训练中全局横幅只显示状态、“查看训练”和紧急停止。
- 底部 `StatusBar` 不再重复完整日志，只保留一句状态摘要或移除。
- RL 设置页只保存参数；不再承载训练日志。
- Monitor 负责跨步骤曲线和实验级分析；控制台负责单 run 的实时过程。
- 运行历史页可跳转指定训练 run 的同一工作区。

## Frontend State

建议新增 `features/training`：

```text
api.ts
model/useTrainingRun.ts
model/useRunEventStream.ts
model/useRunLog.ts
components/TrainingWorkspace.tsx
components/TrainingSidebar.tsx
components/TrainingHeader.tsx
components/TrainingConsole.tsx
components/TrainingPreflight.tsx
components/TrainingSnapshot.tsx
```

状态按 `experimentId + runId` 建 key。活动训练摘要与当前查看 run 分离，不能让后台发现的新任务覆盖用户正在查看的历史记录。

日志使用分块状态和有界内存；保留最近窗口，完整内容从服务端下载。React 更新按批次合并，避免每一行触发整页重绘。

## Lightweight Validation

默认只验证编译和模拟事件，不启动 GPU 训练：

```bash
python -m compileall science_infra/control
cd webui && npm run build
```

可以用临时日志文件模拟追加、断线和重连，验证 offset 不重复不丢失。页面布局、滚动、搜索、停止确认和历史切换由用户在 WebUI 中手动验收。

## Acceptance and Delivery Boundary

- 启动返回 run ID 后直接打开对应控制台。
- 模拟日志持续追加时页面增量显示，断线重连无明显重复。
- 切换历史 run 不会被最新活动训练替换。
- 训练完成后刷新页面仍可读取完整日志和快照。
- RL 设置中不再塞入狭窄的长日志区域。
- 本阶段不证明算法正确；算法解析和真实 GPU 行为属于第四阶段。

## Risks and Edge Cases

- stdout 可能包含 ANSI、超长单行或非 UTF-8 字节，服务端必须安全解码和限长。
- 浏览器后台标签可能暂停渲染，恢复后应按 offset 补齐而不是积压内存事件。
- AGL 指标没有可靠 run ID 时不能放入某次运行详情，应继续标为实验级数据。
- SSE 与日志下载不得暴露服务端任意文件路径，只允许读取已登记 run 的日志。
