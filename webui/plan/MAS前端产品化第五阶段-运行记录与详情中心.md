# Plan

本阶段交付实验级运行列表和带明确身份的运行详情页，将已经存在的 Rollout、训练进程、Monitor 与诊断结果按真实归属组织。

依赖 [第一阶段](MAS前端产品化第一阶段-实验首页与导航骨架.md) 的导航和 [第三阶段](MAS前端产品化第三阶段-真实调试与结果交互.md) 的结果组件；实施顺序上接在 [第四阶段](MAS前端产品化第四阶段-模型与数据资源入口.md) 后。全局约束见 [实施总览](MAS前端产品化实施总览.md)。

## Position in the Project

**统一页面不是统一后端身份。**单次 Rollout 已有持久化 run ID、快照与轨迹；其他执行能力不能因放进同一个列表就被宣称拥有同等历史完整性。

先完整落地“调试运行列表 → 详情 → 返回画布”，再接入有可靠身份的数据。无法归属的数据仍提供实验级入口，不塞进任意一次运行。

## Requirements

- 列表按实验隔离，区分调试、训练、采集、评估；不把 Mock 当作真实调试。
- 详情顶部显示实验、运行类型、启动时间、状态、运行 ID 和可获得的配置来源。
- 训练曲线、日志、诊断、轨迹与产物必须匹配当前选中身份。
- 运行状态、请求读取状态和记录完整性分别表达。
- 查看历史不覆盖当前画布、不恢复历史密钥、不重新执行。
- 当前运行完成后刷新相应列表和摘要，不能让旧失败记录遮盖本次成功。
- 服务重启或历史缺失时诚实显示可恢复范围，不伪造已丢失的训练历史。

## Scope

- In：运行列表、类型过滤、运行详情外壳、Rollout 详情迁移、受能力限制的训练日志入口。
- In：保留 Monitor、Collect、Harness 现有访问，明确实验级资料与 run 级详情的区别。
- In：共用分页、错误、导出和历史定位组件。
- Out / 前端迁移：新建训练存储、重新归档历史 Collect、重建已丢失进程、替任意运行生成评估。
- Out：把所有类型拼成缺少稳定分页边界的假“全量运行时间线”。

## Current State

- `useRolloutHistory` 已接入实验隔离的列表、context 与 trajectory 读取。
- 单次 Rollout 已有摘要、事件 / 对话分段、快照上下文与导出，不需要再造一套调试记录格式。
- `useTrainingRun` 从进程列表挑选正在运行或最近训练，读取其日志；它不是“读取任意选中 run ID”的 hook。
- `MonitorPanel` 接收实验级 monitor 与最新训练信息，当前接法不能直接放入历史训练详情。
- `HarnessPanel` 诊断的是最近 Collect，显示本页返回的 hypotheses；并非任意 Rollout 的 run 级诊断。
- 当前独立 Collect 与训练 / 诊断产物的持久化和身份能力不与单次 Rollout 完全一致，必须逐项确认。

## Proposed Architecture

```text
ExperimentRunsPage
  ├─ 调试记录适配器 → 已有 rollout-runs
  ├─ 训练进程适配器 → 已有 runs / run detail
  └─ 实验级资料入口 → Monitor / 最近 Collect / 最近诊断

RunDetailsPage（experimentId + kind + source ID）
  ├─ 概览
  ├─ Rollout（有可靠关联时）
  ├─ 训练曲线（有可靠关联时）
  ├─ 评估与诊断（有可靠关联时）
  └─ 日志与产物（有可靠关联时）
```

- 建议展示标识由 `kind + source ID` 组成，不能假设不同后端 ID 命名空间全局唯一。
- 保留原始 ID，前端展示 key 不是新的服务端 run ID。
- 第一版按类型分页最稳妥：调试保留原 cursor，训练按现有能力展示。真正混合排序需要服务端统一游标 / 聚合边界后再开放。
- 地址显式包含类型，如 `#/experiments/demo/runs/debug/<runId>`；直接访问必须校验实验归属。
- 当前任务状态与历史浏览分别订阅；选中历史不能令 `useTrainingRun` 的“最新任务”覆盖其标题和日志。
- 调试面板和详情页共用轨迹适配模块，展开状态可以独立，但记录解释必须一致。
- 详情内“定位画布”携带可靠实体身份返回同一编辑会话，不加载历史 Workflow 替换当前设计。

## Evidence and Capability Matrix

| 数据 | 进入某次运行详情的条件 | 不满足时 |
| --- | --- | --- |
| 单次调试快照 / 轨迹 | experiment ID、run ID 与 trajectory ID 一致 | 记录缺失 / 损坏提示，不补造 |
| 训练日志 | 当前进程记录明确属于所选实验及 run ID | 不显示另一进程或最新训练日志 |
| 训练 reward / loss | 指标携带可核实的训练 run / trace 关联 | 留在实验监控，标记无法归属本次运行 |
| Collect 结果 | 有不可变采集身份及其 Workflow / 产物引用 | 以“实验最近采集产物”访问，不给历史列表伪造记录 |
| Harness 诊断 | 结果绑定实际输入产物 / 运行身份 | 保留“诊断最近 Collect”，不称为所选调试诊断 |
| 独立评估 | 真实执行接口、输入、结果与运行记录已接通 | 不提供空壳评估执行按钮 |

run 级指标、诊断和持久化训练历史属于总览中的后端能力门禁。前端不能用时间接近、相同模型名或实验相同来猜测关联。

## UI Layout

```text
← 工作区      实验名称 · 运行记录
[调试] [训练] [采集 / 评估能力说明]        [刷新]
时间        类型        结果        模型 / 策略        查看

运行详情
实验 / 类型 / Run ID / 时间 / 状态 / 配置来源
[概览] [轨迹] [训练曲线] [诊断] [日志与产物]
仅显示有意义的内容；不适用页签隐藏，缺失证据明确说明。
```

- 调试详情无训练曲线，无奖励时显示未评估，不显示 0。
- 训练详情不把 Collect 均值标为训练 reward。
- 过渡阶段提供“实验级监控 / 最近采集与诊断”入口，明确不是本次运行的数据。
- 下载动作使用现有脱敏接口；大记录按需读取，复用第三阶段性能策略。

## State and Loading

- 所有缓存 / 请求 key 至少含实验、类型、运行 ID；事件详情再加 event ID。
- 切换运行立即清除不匹配的详情引用或明确旧数据占位，旧请求返回不能污染新选择。
- 运行摘要加载与大型轨迹加载分开，先看到身份和状态再展开过程。
- 日志轮询仅针对当前有权限 / 归属正确的运行；完成或不可见时按策略停止。
- 实验级运行活动可使用轻量订阅保留，不能通过销毁全部 Provider 令用户看不到仍在训练。
- 404、存储损坏、服务不可达和历史不支持分别呈现；失败的详情请求不得覆盖已知执行结果。

## Acceptance and Delivery Boundary

- 先看旧失败再新发起成功运行，两个状态始终可区分；能直接打开正确的新记录。
- 对两次不同训练 / 调试交替查看，日志、模型、快照和错误不串用。
- 已记录的运行不因当前模型配置改变而更新历史标题或模型身份。
- 详情返回画布，选中历史实体不会覆盖草稿；不存在实体只提示，不自动创建。
- 原 Monitor、采集、诊断能力仍可访问，即使暂时不具备 run 级归属。
- 大轨迹首屏不加载所有事件和消息；错误详情展开不阻塞导航。

交付统一的浏览外壳及真实可关联内容。没有后端持久化 / 归属契约的部分保留明确限制，不能声称“四类运行全部完成统一归档”。

## Risks and Edge Cases

- 混合类型列表最容易误用同一分页游标，第一版避免无契约聚合。
- 正在运行的训练与最后一条训练不是同一个选择概念。
- 历史快照只用于查看；“使用此问题”不等于严格按旧环境重放。
